# Chaya 列表与返回定位规范

- 状态：现行规范；约束后续开发与存量页面迁移，不代表所有页面已完成实现。
- 生效日期：2026-10-18。
- 适用范围：Web 控制台、桌面 App 与 GameEdit 内的全部业务页面、数据列表及详情、编辑、调试等子页面。
- 关联：[UI 风格指南](chaya-ui-style-guide.md)。后续列表、子页面和返回交互需求应直接引用本文，避免各功能重复定义规则。

## 1. 统一原则

所有子页面返回时，必须恢复用户离开上一页时的浏览现场。恢复范围包括查询条件、排序、分页、每页条数、滚动位置；列表进入详情后返回，还必须定位原条目并闪两下。

闪烁本身就是定位反馈。不得为返回定位新增 Toast、提示文字、气泡、状态标签、弹窗或额外播报。普通子页面返回若没有对应列表条目，只恢复页面状态和位置，不制造条目闪烁。

业务数据列表统一采用列表结构与列表行交互，不使用 HTML table 或表格角色模拟列表。新开发必须遵循本文；修改存量列表及其详情返回功能时，应同步迁移该功能涉及的结构与导航行为。

## 2. 列表结构

### 2.1 语义与布局

1. 优先使用 `ul / ol + li`；自定义或虚拟化容器使用 `role="list" + role="listitem"`。列表必须有可访问名称。
2. 禁止使用 `table / thead / tbody / tr / th / td` 承载业务列表；禁止仅换成 div 后继续保留 `role="table" / "row" / "cell" / "columnheader"` 模拟表格。
3. 多字段行可以使用 CSS Grid 或 Flex 对齐。多列布局不等于 table，不能因为数据有多列就改变列表语义。
4. 禁止为获得类似表格的样式而套用 `role="grid"`。需要单元格编辑与网格键盘操作的专用工具，应另有明确交互规范，不得用作普通列表的替代方案。
5. 列表行采用项目统一的密度、间距、分隔线和操作按钮。不得在同一种列表里混用表格行、独立大卡片与自定义行壳；不为每个条目增加重复的卡片外框。
6. 行身份必须使用稳定的业务 ID，React key、返回定位与虚拟化定位保持一致。不得使用当前数组下标、显示序号或可编辑标题作为条目身份。

列表通常由以下区域组成：

```text
固定内容头部：标题 / 描述 | filter bar | 操作按钮
内容区：列表列头（需要时） + 列表行，或加载 / 空 / 错误状态
固定底部：分页及每页条数（需要时）
```

列头仅负责字段说明与排序。排序必须使用可聚焦的按钮，并通过可访问名称说明字段和排序方向；不得为复用 `aria-sort` 而伪造表格角色。行中的链接、按钮、复选框保留各自语义，点击行内操作不得意外触发行导航。

### 2.2 筛选与滚动

- Filter bar 不显示独立可见 label，保留准确的 `aria-label`、当前选项或搜索占位提示；易混淆的控件使用共享 Tooltip。
- 筛选在前，操作在后。窄屏使用横向筛选滚动区，关键操作保持可达，不通过增高头部或裁切按钮解决溢出。
- 列表使用共享 `ScrollArea`，固定头部与分页不随列表正文滚动。多列列表需要双轴滚动时，列头与条目必须位于同一个滚动根，保证水平对齐。
- 加载、空数据、无匹配与错误必须区分。空态与错误放在列表滚动轨道之外，保留筛选和适用的操作入口。
- 统一结构与交互同时适用于分页、无限加载和虚拟列表。虚拟列表可使用可访问的位置及总数信息，不得把所有数据一次性挂入 DOM 来实现返回定位。

## 3. 返回时必须恢复的上下文

离开来源页面之前，必须记录足以恢复以下状态的上下文：

- 来源页面及来源历史条目标识；所属游戏、资源库或其它业务作用域。
- 搜索词、全部筛选、排序字段与方向、页码、每页条数；无限列表还包括已加载范围或可恢复游标。
- 实际滚动容器的横向与纵向位置。页面内有独立 `ScrollArea` 时，不得只记录 `window.scrollY`。
- 进入详情的条目 ID、条目相对可见区域顶部的位置，以及必要的相邻条目身份。
- 触发导航的可聚焦元素身份，供返回后恢复焦点；焦点恢复不得再次改变已恢复的滚动位置。

例如：列表每页 100 条，用户滚到页底后打开第 97 条详情。返回时仍使用原筛选、原排序、原页码和每页 100 条，恢复离开前的位置，让第 97 条位于原来附近的可见位置，并让它闪两下。

普通子页面同样必须恢复来源现场，不要求入口位于某个列表条目内。例如：从缓存第 2 页的页底，通过内容头部的调试按钮进入 `/translate/test?returnTo=%2Ftranslate%2Fcache%3Fpage%3D2`，返回时仍停留在原筛选、原排序、第 2 页、原每页条数和原滚动位置；搜索框中尚未提交的输入也应保留。此类入口没有条目锚点，只恢复页面状态，不闪烁无关条目。

上下文按页面实例与业务作用域隔离。同一列表的不同筛选、多次进入详情、不同浏览器标签页，以及不同游戏的相同条目 ID，不得互相覆盖。

可分享的查询状态使用既有 URL 参数约定；历史条目标识、滚动和锚点等临时状态由统一返回恢复机制维护，不把滚动坐标、闪烁标记或整条业务内容塞入分享链接。上下文应能跨来源组件卸载保留，并在同一标签页刷新子页面后仍可用于返回；不得仅依赖来源组件的局部 state。

## 4. 返回行为

### 4.1 入口一致

页面内返回按钮、浏览器后退及等价返回手势，必须使用同一份来源上下文与恢复规则。GameEdit 面板内子视图切换也必须遵守，不以没有浏览器路由为理由丢失位置。

有有效应用内来源时，返回到该来源对应的页面实例。不得统一写死跳转列表根地址，也不得重新进入第一页来代替返回。详情内的保存完成、取消编辑等需要返回的操作，使用相同规则。多级子页面必须逐层恢复各自来源，不得越过中间页直接跳回列表。

直接打开或分享进入子页面、没有有效来源上下文时，页面内返回按钮回到该功能的默认父页面；不推测旧条目、不闪烁无关项目。不得盲目调用可能离开应用的浏览器后退；显式返回地址必须限制在有效的应用内父页面范围。无应用内来源时，浏览器自身的后退遵循真实历史，不应被应用拦截或伪造。

### 4.2 恢复顺序

1. 校验来源页面、业务作用域及上下文是否仍有效。
2. 恢复筛选、排序、分页与每页条数，加载对应数据；无限或虚拟列表恢复足够覆盖原位置的数据范围。
3. 等待列表内容及目标行可定位后恢复滚动。不得在 skeleton 上写入坐标后就视为完成。
4. 目标条目存在时，优先恢复该条目在原可见区域中的相对位置；布局与数据未变化时，滚动位置应与离开前一致。不要默认把原条目拉到屏幕正中央。
5. 完成定位后恢复适当焦点，并执行一次两轮闪烁；没有条目锚点时，只恢复滚动位置。

浏览器原生滚动恢复与应用恢复必须协调，同一个滚动容器不能由两套机制反复纠正。异步加载、重新渲染或布局测量不得导致页面先跳顶、再反复跳到不同位置。

恢复期间若用户主动滚动、触摸拖动或使用键盘继续浏览，必须终止尚未完成的自动校正，尊重用户当前位置。恢复必须有明确完成或降级条件，不得无限重试。

### 4.3 数据或布局变化

- 条目仍在当前结果中：按稳定 ID 定位，不能按旧数组下标闪错条目。编辑后行高变化时，仍以该条目及其视口偏移为锚点。
- 条目移动到其它分页：仅在同一筛选与排序下能够可靠定位时恢复到其实际页；不得清除筛选或无边界扫描全部分页来找条目。
- 条目已删除、被筛选排除或无法可靠定位：优先恢复仍存在的相邻条目或原滚动邻近位置，不闪烁替代条目。
- 原页码因删除数据而失效：回到合法的最近页，滚动位置限制在该页有效范围内，不强制回第一页。
- 数据为空或加载失败：展示对应状态，停止定位与闪烁，不新增“定位失败”提示。
- 窗口大小、列数或行高改变：优先保持锚点条目可见；无法恢复原相对位置时，使用最接近的有效位置。

## 5. 原条目闪两下

正常动效模式下，目标条目定位完成且进入可见区域后，执行两次轻量高亮周期：`原样 → 高亮 → 原样 → 高亮 → 原样`。每轮约 600ms，总时长约 1.2 秒，结束后清除临时高亮状态。

高亮使用项目语义色的低强度背景或内描边，不改变行高、边距、排序、文字颜色对比度或原有选中状态。不得让整行文字消失，不使用刺眼的明暗闪屏，不叠加提示文字、Toast 或气泡。

每次真实的返回事件只执行一次两轮闪烁。请求结束、React 重渲染、窗口聚焦或普通列表刷新不得重复触发；重新进入详情再返回，才构成新的返回事件。待定位条目未渲染时不得提前播放动画。

若用户启用 `prefers-reduced-motion: reduce`，用约 1.2 秒的静态轻量高亮替代闪烁，仍不显示额外提示。离开页面、切换查询、目标条目消失时应取消未完成的定位与高亮，并清理定时器、观察器或动画回调。

## 6. 开发与迁移要求

返回上下文、滚动恢复和闪烁必须由共享机制提供；业务页面只提供作用域、稳定条目 ID、滚动根及导航关系。不得为每个列表各写一份定时滚动、闪烁 CSS 或 sessionStorage 协议。

共享实现应覆盖 Web 路由与 GameEdit 内部子视图，并区分“首次进入”“普通刷新”“返回恢复”。列表布局、排序按钮及分页沿用共享 UI 能力；旧组件名称或历史类名不能作为继续使用 table 结构的理由。

迁移存量列表时，必须同时核对结构、可访问语义、排序筛选、行内操作、滚动和返回行为。只把 `<table>` 换成 `<div>`，或只恢复 URL 参数但不恢复位置，均不算完成。

### 6.1 共享 API

- `components/sk/DataList.tsx`：列配置、排序按钮、统一 Grid 行布局；业务行使用 `role="listitem"`、`data-list-row` 和 `data-list-cell`。旧 `DataTable` 仅保留兼容导出，实际输出仍是列表。
- `components/sk/ScrollArea.tsx`：默认登记实际滚动根。不同本地筛选或子视图使用明确的 `restorationKey`；业务行提供稳定的 `data-navigation-id`，打开子页面的按钮增加 `data-navigation-trigger`（链接自动识别），禁止使用会随排序变化的数组下标。
- `components/sk/VirtualList.tsx`：使用相同滚动根，传入 `restorationKey`、`getRowId(index)`；按已保存位置恢复虚拟范围，等对应行挂载后再高亮。分批列表继续通过原来的 `onEndReached` 加载已浏览范围，恢复超时会停止，不扩大到全量数据。
- `components/navigation/NavigationScope.tsx`：通过 Context 隔离业务作用域。GameEdit 工作台以 `catalog.contentRoot` 隔离不同游戏，子列表不自行维护另一套游戏 ID 协议。
- `components/navigation/useNavigationViewState.ts`：本地搜索、枚举筛选及经过校验的 JSON / 布尔视图状态按历史条目、业务作用域、视图名称保存。已有 URL 状态继续使用 URL；相关 Hook 用于角色、事件、地图与存档等内部子视图的本地控件。`replace` 修改 URL 筛选时保留当前历史条目标识，避免其它本地筛选随之重置；进入同类子视图可继承现有筛选，返回仍读取来源条目的值。
- `lib/ui/navigation-restoration.ts`：`returnToNavigationSource(router, fallback)` 用于 Web 子页面返回；有应用内来源则后退，无来源则使用本地兜底地址。来源信息与 Next 历史状态共存，禁止业务组件直接覆盖 `history.state`。

```tsx
<ScrollArea restorationKey={`items:${query}:${sort}:${page}:${pageSize}`}>
  <ul>
    {items.map((item) => (
      <li key={item.id} data-navigation-id={`item:${item.id}`}>
        <button data-navigation-trigger="" onClick={() => openDetail(item.id)}>
          {item.name}
        </button>
      </li>
    ))}
  </ul>
</ScrollArea>
```

共享层在导航前记录坐标、稳定 ID、相邻项、视口偏移和焦点；在路由提交或内部视图重新显示后恢复。临时上下文保存在同标签页 `sessionStorage` 中，最多保留 80 份快照；存储不可用时退化为内存。不要在快照中放业务记录正文、凭据或译文。

### 6.2 本轮存量接入

缓存列表及详情、缓存调试页、日志、GameEdit 目录与角色、公共事件、地图事件、敌群与战斗列表、存档虚拟列表、代理配置和 MCP 参数列表均采用列表结构；共享 `ScrollArea` 覆盖其余标准滚动面。缓存、GameEdit 事件、存档逐级返回与代理配置返回使用来源历史；GameEdit 内部视图的卸载、重新显示也走共享恢复。

后续新增独立滚动根必须使用共享控件。新增详情入口需要稳定条目 ID，并按第 7 节做实际返回验收；不能仅依赖自动登记就跳过业务作用域和查询状态检查。

## 7. 验收与 CR

相关需求与 PR 应引用本文，并按改动面验证以下行为：

- 所有业务列表使用列表语义和统一行布局，无 HTML table 或表格角色伪装。
- 每页 100 条，分别从页首、页中、页底进入详情再返回，查询、分页、每页条数和位置均正确。
- 页面返回按钮与浏览器后退结果一致；普通子页面返回也恢复位置。
- 从内容头部、工具栏或其它非条目入口进入测试、调试等子页面后返回，仍恢复完整来源现场；不得仅恢复 `returnTo` 地址便视为完成。
- 原条目准确定位并只闪两下，用户界面没有新增提示文字、Toast 或气泡。
- 原条目删除、跨页移动、被筛选排除、原页码失效时，按规则降级且不闪错条目。
- 慢加载、行高变化、双轴滚动、虚拟列表及窄屏下仍能恢复，不先跳顶再反复跳动。
- 刷新子页面后返回、同页多次进入详情、多个来源历史条目和多个标签页之间互不串位置。
- 主动滚动可中止自动恢复；减少动态效果偏好生效；键盘焦点恢复不引发额外滚动。

数据列表的结构与共享恢复逻辑使用自动化验证；实际滚动位置、焦点及两轮闪烁必须在真实渲染中验收，不能只凭源码或 URL 相等判定通过。
