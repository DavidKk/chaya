# 远程串流：静态封面、低频预览与 MV/VX 性能优化需求

- **日期**：2026-11-01
- **状态**：已完成代码对照评审；实施与实机验收分开记录，未通过实测的指标不得标为完成。
- **对应技术方案**：[技术方案](technical/remote-play-acceleration-and-cover.md)
- **关联文档**：[静默与多实例](remote-play-silent-multi-instance.md)
- **有效范围**：本地服务的 MV/MZ 与 XP/VX/VX Ace 封面、管理列表预览、实时串流和性能验证。原生采集第一阶段限 macOS；Windows/Linux 不能继承其能力声明。
- **优先级**：本文件修正旧静默方案中的性能承诺：4–8ms RTT 不代表端到端延迟；隐藏或锁屏时不能保证 60 FPS；同一游戏允许观看，控制权仍独占。静默、多实例与主动取消后不重连的需求继续保留。

## 1. 问题与边界

用户反馈前台游玩顺畅，改为后台运行后 MV/VX 卡顿。当前代码可确认以下风险，不能直接把它们写成已经测定的唯一根因：

1. RGSS 的 `current_frame.jpg` 同时承担预览和实时视频源。把 Ruby 截图改为每 180 秒一次后，网关即使每 3 秒重读，看到的也只是同一旧帧。降低预览频率不能牺牲正在游玩的画面更新。
2. MV 的 RAF 和定时器可能同时推进主循环；仅把补帧阈值调到 14ms，会在两个时钟错开时额外更新。全局禁用引擎跳帧也不能证明性能提高。
3. 标题封面存在时，客户端仍可能在播放或退出时截取视频，覆盖静态封面。封面解析还会重复读文件、解密、缩放。
4. 隐藏、遮挡、最小化、系统锁屏和整机睡眠是不同状态。系统调度、引擎渲染、编码、网络和解码均需分别测量，不能用启动参数代替验证。

## 2. 目标与非目标

| 编号 | 要求                                                     | 验收口径                                                                                         |
| ---- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| R1   | 有可读取标题图时优先静态封面，不启动游戏、不请求运行截图 | 冷启动、重进页面、切换游戏均成立；加密 MV/MZ、普通 MV/MZ、RGSS 松散图片分别覆盖                  |
| R2   | 管理列表预览默认 180 秒更新一次                          | 服务端按房间限频并合并并发；多标签页不能倍增采集；页面隐藏时停止预览更新                         |
| R3   | 实时视频独立于列表预览                                   | MV 使用 Canvas MediaStream；RGSS 接入独立原生内存采集，不能用三分钟旧图冒充视频                  |
| R4   | MV 保留引擎节奏并减少多余工作                            | 前台不叠加第二套更新；RAF 暂停时补帧；恢复后不积累回调；不永久覆盖跳帧配置                       |
| R5   | 按需分配采集资源                                         | 第一个实时消费者建立后启用，最后一个离开后停止；控制与观看共用采集，不重复截图；关闭实例释放资源 |
| R6   | 性能效果可追踪                                           | 分开记录引擎/采集/发送/解码 FPS、RTT、丢包、抖动缓冲、CPU、内存与预览次数；不把 RTT 标为操作延迟 |
| R7   | 保持静默能力与可见窗口对照模式                           | 可见窗口用于兼容与性能对照，不能作为后台性能问题已解决的证明；不擅自改用户已保存设置             |

本阶段不承诺所有游戏有标题图、不承诺零读取/零拷贝、不承诺任意机器或锁屏状态下 60 FPS。60 FPS 是可支持游戏和设备的优化目标，不能超过游戏原生逻辑帧率。原生 RGSS 音频采集与完整原生 WebRTC 编码发送属于后续阶段，不能把 MV 的 WebAudio 能力写为 VX 已支持。

## 3. 封面与预览

### 3.1 封面来源

1. MV/MZ：按 `System.json` 的 `title1Name`、`title2Name` 读取标题素材，支持标准 `.png`、`.rpgmvp`、`.png_`。首选有效背景层；第二层仅作为回退，本轮不声称完整重建启动菜单。
2. XP/VX/VX Ace：在 `Graphics/Titles1`、`Titles2`、`Titles` 探测松散图片。没有解析 Ruby Marshal 的标题配置时，目录探测仅是近似选择。
3. 回退：约定封面文件、同游戏已有存档缩略图、应用图标，最后显示默认背景。
4. RGSS 加密归档、RTP、脚本定制标题、视频标题和缺失密钥不能保证解析，不为获取封面自动开游戏或高频截图。
5. 静态封面优先于历史游玩截图。仅无静态封面时允许保存客户端已收到的视频帧，最多每 180 秒一次；不触发主机截图。

### 3.2 缓存与安全

服务端有界缓存命中、未命中和并发中的解析；按游戏与内容根目录隔离。素材解析需要磁盘读取，但不写解密文件。对尺寸、文件大小、密钥格式与路径进行校验，拒绝目录外符号链接。

二进制封面使用私有 HTTP 缓存，避免包含存档画面的响应进入共享缓存。允许 24 小时新鲜期，明确素材更新可能需要清缓存；不是所有浏览器都必定命中缓存。JSON 保持项目 API 信封。

### 3.3 管理页

卡片有封面时不主动截图。无封面才读取低频预览；服务器按房间保存最近结果，跨标签页合并。预览失败不连环重试、不把占位图作为成功实测。打开监看弹框才创建实时 WebRTC，关闭即释放对应消费者；不能占有玩家控制权。

## 4. 实时串流与运行状态

### 4.0 主机窗口与声音设置

- 在「云游戏 → 配置」选择「显示窗口」或「后台运行」，默认保持显示窗口，方便与当前流畅效果对照。
- 配置保存到服务端，手机与电脑共用；只影响从串流页发起的下一次启动。已启动游戏直接复用，不隐藏、不重启，需先主动退出游戏再切换测试。主应用普通本地启动不读取该设置。
- 「主机游戏静音」独立于窗口模式，默认开启；只控制游戏声音，不影响其他应用。MV/MZ 已接入的 WebAudio 继续传到客户端；VX/VX Ace 暂无客户端音频，不能宣称静音后仍有客户端声音。
- 后台模式仍需持续渲染游戏画面并编码传输，不能等同于关闭渲染。减少桌面展示可能省下部分开销，具体节省与帧率需实测，不能预先承诺更省资源或同等流畅。
- 保存失败保留原配置并提示错误；读取失败禁用对应控件并允许重试。不因设置变化自动启动任何实例。

### 4.1 MV/MZ

- Canvas 直接捕获，H.264 作为兼容偏好，浏览器自行协商编码器。码率是上限而非固定带宽，保留拥塞控制。
- 正常 RAF 更新优先；后台补帧同时检查最近任意更新和原生 RAF 是否已经停顿，避免 14ms 阈值叠加更新。
- 仅对支持的接收器设置低延迟提示；不能承诺清空抖动缓冲。
- 主机静音仅指已接入的游戏 WebAudio 路径，不是断开物理声卡，也不是让整台电脑静音。HTML 音频或插件自建 AudioContext 需单独验证。

### 4.2 RGSS

第一阶段在 macOS 增加按需原生窗口采集，帧在内存中送到现有 WebKit Canvas，再由 WebRTC 输出；Ruby 主线程不做实时截图、编码或逐帧写盘。桥接采用单帧背压，慢消费者丢弃旧帧，不累积队列。

需要处理屏幕录制授权、窗口消失、采集错误、首帧超时、重连与停止。macOS 14.4+ 使用本进程窗口枚举；更早的受支持系统可能需要屏幕录制权限。没有授权、系统不支持或采集不可用时，记录英文错误并保留诊断入口，不能将静态封面当作可玩画面。

本轮原生测试发现，窗口透明度为 0 时采集只收到初始帧。静默窗口改为保持不透明、移到屏幕外、不接受鼠标操作；不必显示到桌面前台。离屏合成测试已通过，但真实游戏、最小化与锁屏仍需单独验收。

第二阶段评估将原生帧直接送入硬件编码/WebRTC，消除第一阶段 JPEG 和 JS 桥接开销。必须补齐编码后帧如何进入 RTP、协商、关键帧、拥塞控制和音频时钟设计后再实施，不能只接 VideoToolbox 就宣称完成。

## 6. 实施顺序

1. 修正文档、接口示例和旧承诺；删除无证据的“已实测”结果。
2. 完成封面优先级、解密校验、有界缓存与低频预览服务约束。
3. 修复 MV 的双时钟补帧风险，去除未经证明的全局资源强制参数。
4. 接入 RGSS 原生内存采集并验证生命周期，明确平台与授权限制。
5. 运行针对性测试、类型检查及原生构建；实测后再记录性能结论。未通过的环境单独列为待验收，不能勾选完成。

## 7. 当前交付边界

封面解析与缓存、低频预览、MV 补帧与媒体资源回收、RGSS 内存采集及多观看者共享已进入实现。原生采集测试只使用一个临时窗口，可见/离屏两种状态均收到 30 个不同画面，输出比例正确；不代表游戏已达到 30 FPS。

因用户反馈机器卡顿，本轮清理重复构建监听器，确认游戏实例列表为空，不再启动真实游戏压测。两分钟性能对照、iPhone Safari 真机、RGSS 声音与 Windows/Linux 实时采集尚未验收；不能把这些项标为完成。详细命令和结果记录在技术文档。
