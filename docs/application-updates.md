## 1. 目标与边界

新增翻译词条、发布游戏插件或更新业务界面时，尽可能只分发受影响的包。涉及宿主运行环境、启动器或基础接口的不兼容变更，再进行完整应用升级。

本项目建设统一的版本发现、可信分发、下载管理和安装记录，各更新类型通过独立适配器决定安装与启用方式。不承诺任意代码实时热替换，不建立第三方插件市场。

首个交付对象是翻译资源包及表现性文本匹配能力包，先数据、再算法。游戏插件、业务包和整应用更新分别进入后续阶段。更新基础能力不得依赖这些后续阶段完成。

默认翻译资源和匹配算法必须随安装包一起交付，安装后即可使用这些基础能力，首次启动不要求联网、手动导入或再次下载。GitHub 仅用于后续检查和取得更新；未配置更新源信任根、断网或检查失败均不影响内置能力。开发环境同样直接使用随源码构建的默认资源，只有修改或增加资源时才需要导入。

已有用户首次获得更新能力，仍需安装一次包含更新器的新应用版本；此后兼容的资源包更新才可脱离整应用发布。

本地开发提供 CLI 和管理 API 两种资源入口，使用同一资源库。管理 API 支持查看版本、预览、导入、按预览结果应用、启用、停用、回滚、导出及试匹配；预览不修改数据，过期预览拒绝应用，已有版本不可覆盖。接口只接受资源数据和本地版本身份，不接受下载 URL 或服务器文件路径。访问沿用本机管理权限及磁盘能力限制，完整管理页面后续建设。

## 2. 更新对象

| 类型       | 内容                                                     | 安装范围                           | 生效方式                                   |
| ---------- | -------------------------------------------------------- | ---------------------------------- | ------------------------------------------ |
| 翻译资源包 | 预存译文、表现性文本译例、受限模板、语言对数据           | 本机公共资源库                     | 下一批翻译固定新快照                       |
| 匹配能力包 | 表现性文本归一化、重复与拖音处理、完整译例及模板匹配算法 | 本机版本化能力目录                 | 下一批任务固定新算法版本，已有任务保持旧版 |
| 游戏插件包 | MV/MZ、RGSS 对应的翻译、日志、编辑等产物                 | 先安装到本机包库，再应用到指定游戏 | 按插件契约重新加载或重启游戏               |
| 业务包     | App 内 Next UI、对应服务与必要依赖组成的一致构建产物     | App 可写业务版本目录               | 安全停止任务后重启本地服务并刷新界面       |
| 整应用     | Electron、preload、启动器、基础更新器及内置运行环境      | 操作系统应用安装范围               | 专用更新器完成安装，重启 App               |
| 原生组件   | 特定平台、架构和运行环境的辅助程序或库                   | 类型专属目录                       | 兼容时单独更新，否则要求升级宿主           |

游戏内容原生 locales、应用 UI 文案、翻译资源是不同概念。本项目优先处理翻译资源及匹配算法分发，不将整个翻译模块改成下载。翻译调度、引擎调用、缓存与存储、格式校验、异常采集和游戏提取回写仍随应用发布。

算法和数据分别版本化；更新词条只下载数据，更新算法只下载能力包，存在兼容依赖时由更新管理器先检查并形成更新计划。匹配算法不负责下载、直接读写数据库或自行升级。

### 2.1 固定 GitHub 分发源

- 官方元数据与安装包统一通过 GitHub 发布；客户端直接从 GitHub 下载，不经过 Vercel 或业务 API 转发。
- 官方入口由应用内置固定仓库和渠道，用户不需要配置域名。首期不建设自定义源 UI、部署域名推断或多镜像选择。
- 元数据使用固定入口，版本包使用 GitHub Releases 的明确 tag/asset 地址；详细路径及发布顺序见技术方案 §3.2。
- 翻译资源、算法和 App 使用独立版本身份；不能用仓库全局 `latest` 同时代表所有包的最新版。
- 已有相同内容不重复下载；首次安装使用随应用附带的基础算法和资源，不要求联网重新取得。
- 官方渠道必须允许客户端不携带 GitHub 凭据下载；不在 App 中嵌入发布用令牌。实际公开访问能力在 U0 验证。

## 3. 共同行为

1. 可查看本地版本、兼容的可用版本、更新说明、下载大小与生效要求。
2. 手动检查和主动更新为首版交互；允许后台检查，首版不默认自动下载或自动启用。
3. 已安装内容支持离线使用。检查或下载失败不阻塞翻译与游戏，不移除现有可用版本。
4. 下载进度复用只读下载中心；检查、更新、重新发起和回滚入口放在对应资源管理页面。不会在下载中心新增取消、重试按钮。
5. 区分已下载、已安装、已启用和已应用到游戏；不能用一个“更新成功”混淆这些状态。
6. 同一包版本不可被发布端静默替换；资源格式、宿主接口、平台和依赖不兼容时拒绝启用。
7. 保留上一可用版本。失败恢复和人工回滚有明确记录，不覆盖用户词条、游戏存档、配置或人工修改。
8. 用户主动回滚已验证的本地版本与远端诱导降级分开处理。过期的远端元数据不能用于接受新包，已有本地版本仍可离线使用。

## 4. 首期范围与验收

首期实现统一基础层、翻译资源适配器及最小匹配能力加载器，分 U2a/U2b 验收：

- 通过发布流水线独立发布两个连续版本，不发布 App 即可发现并安装新版。
- 首次离线可使用随应用附带的基础包，其他语言对按需安装。
- 语言覆盖按日语、英语、俄语、韩语、其他语言推进；数据不足时不承诺已支持，包结构不限制语言对扩展。
- 下载中断可重新发起；损坏包、无效签名、不兼容版本和非法资源内容被拒绝，旧版仍可用。
- 退出后再启动能恢复到一致状态；正在运行的翻译批次不切换资源版本，下一批使用新快照。
- 更新官方资源不覆盖用户自定义内容，翻译结果与缓存能追溯资源版本。
- 支持从本地文件导入同一格式的官方签名包；用户自定义词条沿用单独导入入口，不因此获得执行代码的能力。
- 官方资源与算法包都从 GitHub 实际完成两版本验证；下载过程无 Vercel 代理流量，检查失败继续使用本地版本。
- 匹配能力通过稳定接口调用，算法更新无需整应用升级；超时、异常或不兼容时回退到已验证的内置匹配器或未命中路径。
- 一次匹配使用兼容的算法/数据组合；记录算法版本、资源版本与来源，不能只更新数据版本而复用旧算法结果。

现有翻译 M1 的匹配能力和质量验收继续按原需求执行；本项目增加独立分发能力，不宣称原 M1 已通过完整质量验收。

## 5. 后续交付约束

- 游戏插件：本机包库更新和游戏安装升级分开；按游戏记录版本，尊重备份与人工修改，失败不能留下半套插件。
- 业务包：先作为完整一致构建单元更新，不单独替换 Next 编译后的 JS/CSS。未完成宿主接口与启动恢复设计前，继续随整应用发布。
- 整应用：按平台确定安装格式、签名和恢复策略；无条件自动回滚不作为承诺，涉及不可逆数据迁移时必须给出专门恢复方案。
- 浏览器/cloud 形态继续使用现有部署与浏览器文件访问边界，不获得更新本机 Electron 或静默写入任意游戏目录的能力。
