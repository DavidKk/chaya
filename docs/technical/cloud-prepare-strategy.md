# 云端 / 跨平台：游戏准备与壳安装策略

> 目标：初始化更快、少报错、少步骤；大体积场景可预期、可中断续跑。
>
> 范围：vercel（Chrome FSA）为主；local / app（DiskOps）对照。
>
> 结论先行：**默认绝不整包复制游戏**；只在用户明确要求「迁到工作区」时才谈拷贝 / 剪切 / 克隆。

---

## 0. 现状澄清

当前云端准备（`cloudPrepareGame`）已经是：

| 动作                            | 是否触碰 8GB 游戏体 |
| ------------------------------- | ------------------- |
| 在内容根写插件 / `ChayaEnv`     | 否（小文件）        |
| 旁挂统一壳 `Chaya.app`/`Chaya/` | 否（仅 ~200MB NW）  |
| 写 `Chaya启动.*`                | 否                  |
| 把 `www` 拷进壳 / 新目录        | **不做**            |

因此「复制 8GB 会崩溃」**不应出现在默认路径**。若产品以后要「整理到 Chaya 工作区」，才启用下文「迁移动作」。

---

## 1. 原则（所有平台共用）

1. **原位优先（In-place）**
   用户选哪就改哪：插件写入内容根，壳旁挂，启动脚本传内容根。游戏资产不动。

2. **壳下载与游戏资产解耦**
   NW zip（约 200MB）可缓存、可续写；与游戏体积无关。

3. **禁止静默大拷贝**
   任何预估 ≥ **阈值**（建议 **1 GB**，可配置）的「目录级复制」必须：
   - 展示预估体积与耗时量级
   - 用户显式选：**原位 / 剪切迁移 / 复制 / 取消**
   - 默认可选「原位（推荐）」

4. **中断可续**
   - 壳：OPFS 缓存 zip + 按文件大小跳过已写条目（已有雏形，见 §3）
   - 迁游戏：清单 + 已完成文件集合；禁止「失败后从头再拷 8GB」

5. **能链就不拷**
   仅 DiskOps（local/app）能硬链 / 克隆；**浏览器 FSA 不能建硬链 / 软链**。

## 2. 能力矩阵（决定方案边界）

### 2.1 Chrome / Edge（vercel 云端）

| 能力                           | 支持情况                           | 备注                                              |
| ------------------------------ | ---------------------------------- | ------------------------------------------------- |
| `showDirectoryPicker`          | ✅ 安全上下文（https / 127.0.0.1） | 局域网 `http://192.168.x` ❌                      |
| 读写已授权目录                 | ✅                                 | 逐文件 `createWritable`                           |
| OPFS 缓存大 zip                | ✅                                 | 已用于 NW 包                                      |
| 目录内 `FileSystemHandle.move` | ✅（Chromium）                     | **更像剪切/改名**，非字节复制；同授权树内重组可用 |
| 创建符号链接 / 硬链接          | ❌                                 | 无 API                                            |
| `chmod +x`                     | ❌                                 | Mac 启动脚本可能需用户首次 `bash` / 终端授权      |
| 读取绝对路径字符串             | ❌（标准）                         | 无法直接调 `ln` / `cp -c`                         |
| 后台长任务保活                 | 弱                                 | 标签休眠会中断；需进度落盘 + 续跑                 |

**结论（浏览器）：**

最优路径 = **原位注入 + 旁挂壳 + 启动脚本**。

不要在浏览器里做 8GB 复制；若用户坚持「复制到别处」，应用 **move（剪切式重组）** 或提示改用 **本机 Toolkit / 自己在访达里拖**。

### 2.2 macOS + DiskOps（local / app）

| 能力             | API / 手段                                       | 适用                                         |
| ---------------- | ------------------------------------------------ | -------------------------------------------- |
| 原位写插件       | `fs`                                             | 默认                                         |
| 旁挂壳 / 共用壳  | `data/shell/Chaya.app` + 传参或 `app.nw` 软链    | 默认                                         |
| APFS 克隆（CoW） | `copyfile`/`fs.copyFile` + `COPYFILE_FICLONE` 等 | **同卷「复制」首选：几乎不占双倍空间、极快** |
| 硬链接文件       | `fs.linkSync`                                    | 仅单文件、同卷；目录需自行遍历               |
| 软链接目录       | `fs.symlinkSync`                                 | 共用壳 `app.nw` → 内容根（已有）             |
| 剪切             | `fs.rename`（同卷）/ 跨卷则拷+删                 | 「迁移工作区」                               |

**结论（mac）：**

- 浏览器：原位。
- DiskOps：若必须「多一份」→ **优先 APFS clone（FICLONE）**；展示「将使用系统克隆，几乎不额外占空间」。
- 跨卷（外置盘 → 内置）无法 clone → 走复制或提示剪切，并强制确认。

### 2.3 Windows + Chrome / DiskOps

| 能力          | 浏览器 FSA      | DiskOps                                       |
| ------------- | --------------- | --------------------------------------------- |
| 原位 / 旁挂壳 | ✅              | ✅                                            |
| 硬链接        | ❌              | `fs.link`（同卷）；目录需工具化               |
| 克隆 / CoW    | ❌              | 视文件系统：ReFS 等；NTFS 上 FICLONE 常不可用 |
| 剪切          | `move`（同树）  | `fs.rename` 同卷；跨卷拷+删                   |
| 启动          | `Chaya启动.bat` | `nw.exe <contentRoot>`                        |

**结论（Win）：**

浏览器仍原位。DiskOps「复制」前必须估体积；同卷可尝试硬链清单（适合大量小文件的 RPG Maker 资源），失败再回退字节拷贝。

**不要假设** Windows 总有 APFS 式秒拷。

### 2.4 Linux + Chromium / DiskOps

| 能力    | 浏览器                                   | DiskOps                                      |
| ------- | ---------------------------------------- | -------------------------------------------- |
| 原位    | ✅（若有 FSA，需 Chromium + 安全上下文） | ✅                                           |
| reflink | ❌                                       | `cp --reflink=auto` / `FICLONE`（btrfs/xfs） |
| 硬链    | ❌                                       | `link(2)` 同卷                               |
| 软链    | ❌                                       | `symlink`                                    |

**结论（Linux）：** 与 Win 类似；探测文件系统后选择 reflink → hardlink 树 → copy，并确认大体积。

## 3. NW 壳下载 / 写入（已部分落地，建议补齐）

对象：官方 zip ≈ 200MB，**与游戏体积无关**。

| 阶段     | 策略                                                                                                                                  |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 下载     | 官方 `dl.nwjs.io` 直链（本站不代理）；写入 **OPFS**（`chaya-nw-shell/{ver}-{file}.zip`）。浏览器无 CORS 时：打开 CDN 下载后选本地 zip |
| 中断下载 | 下次优先读 OPFS；可选后续做 HTTP Range 续传（进阶）                                                                                   |
| 解压写入 | 逐文件写入统一名；**同名且 size 一致则跳过**（已有）                                                                                  |
| 完整性   | 仅当关键二进制存在才算「已装壳」；残缺目录续写而非跳过                                                                                |
| 进度 UI  | 下载 % + 写入 `done/total（已跳过 n）`                                                                                                |

进阶（可选）：

- Service Worker / Cache API 与 OPFS 双写，多标签共享
- zip 内大文件流式解压，降低峰值内存（fflate 流式）

## 4. 「迁游戏」若产品需要：统一交互（非默认）

仅当用户勾选类似 **「复制/移动到 Chaya 工作区」** 时进入：

```text
① 扫描预估体积 + 文件数 + 是否同卷（DiskOps 可知；浏览器常不可知）
② 体积 < 阈值 → 可静默用「最佳策略」
③ 体积 ≥ 阈值 → Modal 三选一（默认「取消，改用原位」）：
     A. 原位准备（推荐）— 不迁文件
     B. 剪切到目标 — 同卷 rename / FSA move；跨卷警告
     C. 复制到目标 — DiskOps: clone/hardlink/copy；浏览器: 强烈不推荐并二次确认
④ 执行时写 manifest（目标路径、策略、已完成相对路径集合）
⑤ 中断后再次进入：读 manifest 续跑；完成后删 manifest
```

### 4.1 浏览器侧（vercel）推荐文案逻辑

- **默认不提供「复制 8GB」按钮**，避免误点。
- 若强需求：只提供
  - 「在当前目录准备（推荐）」
  - 「我已自行把游戏放到目标位置，重新选择该文件夹」
- 高级：「尝试用浏览器移动文件夹（剪切，非复制）」→ 调 `handle.move`，失败则引导访达 / 资源管理器。

### 4.2 DiskOps 策略优先级

```text
同卷且支持 FICLONE/reflink → 克隆（首选「复制」语义）
同卷且用户选「链接工作区」→ 目录软链或文件硬链树
同卷 rename → 剪切
否则 → 字节复制（必须确认）+ 续跑清单
```

## 5. 分平台推荐产品方案（汇总）

### A. macOS + Chrome（vercel）

| 步骤     | 做法                                                    |
| -------- | ------------------------------------------------------- |
| 选目录   | 仅 https / 127.0.0.1；局域网 HTTP 直接「无法选择」      |
| 准备     | 原位写插件 + 旁挂 `Chaya.app` + `Chaya启动.command`     |
| 壳       | OPFS 缓存 + 断点续写                                    |
| 启动     | 脚本传内容根；可选首次 `ln -s` app.nw（脚本内，非 FSA） |
| 大游戏   | **不拷**；提示「游戏无需复制」                          |
| 升级路径 | 需要一键启 / 迁工作区 → 引导安装 **local/app**          |

### B. Windows + Chrome / Edge（vercel）

| 步骤    | 做法                                                    |
| ------- | ------------------------------------------------------- |
| 准备    | 原位 + `Chaya/` + `Chaya启动.bat`（双击友好）           |
| 壳      | 同 OPFS 续传                                            |
| 大游戏  | 不拷；bat 传 `%CONTENT%`                                |
| DiskOps | 大复制前确认；同卷尝试硬链树，否则 copy + manifest 续跑 |

### C. Linux + Chromium（vercel）

| 步骤    | 做法                                                |
| ------- | --------------------------------------------------- |
| 准备    | 原位 + `Chaya/` + `Chaya启动.sh`（提示 `chmod +x`） |
| 壳      | zip 可浏览器解压；tar.gz 仍建议本机或后续加解压库   |
| DiskOps | reflink → hardlink → copy + 确认                    |

### D. local / app（所有 OS）

| 能力         | 做法                                           |
| ------------ | ---------------------------------------------- |
| 默认         | 绑定路径原位；共用 `data/shell/Chaya…`         |
| 启动         | Host 层 `launchShell(shell, contentRoot)` 传参 |
| 可选迁工作区 | §4 + OS 最佳链/克隆                            |
| 体验         | 进度、可取消、可续跑；完成后Reveal 目标        |

## 6. 错误与友好性清单

| 问题             | 处理                                                |
| ---------------- | --------------------------------------------------- |
| 局域网无法 FSA   | 明确「无法选择文件夹」，不跳转 127.0.0.1            |
| 壳写到一半       | 不标记已装；再跑续写 + 跳过已完整文件               |
| 标签关掉         | OPFS 仍在；下次跳过下载                             |
| 用户以为要拷游戏 | UI 写清：「只写入少量插件与运行壳，不复制游戏资源」 |
| 非要双份 8GB     | 二次确认 + 预估时间；优先引导剪切或本机克隆         |
| Mac 无执行位     | 启动脚本说明；或引导「终端运行一次」                |

---

## 7. 建议落地顺序

1. **P0（产品文案 / 门闸）**
   云端门闸与完成 toast 明确「不复制游戏」；大操作不出现在默认按钮。

2. **P0（壳续跑）**
   巩固 OPFS + size 跳过 + 完整壳探测（已有，补测试与失败提示）。

3. **P1（DiskOps 迁工作区，可选）**
   体积扫描 + 确认 Modal + manifest 续跑 + macOS FICLONE / Win hardlink 探测。

4. **P2（浏览器 move）**
   仅作为「剪切到子目录」高级能力，不做 8GB copy。

5. **P2（NW Range 续传）**
   弱网优化，非阻塞。

---

## 8. 一句话决策

- **vercel + Chrome：** 原位准备 + 缓存壳 + 启动脚本；**永不默认复制游戏**。
- **要快、要省盘、要灵活：** local/app 用系统克隆 / 硬链 / 剪切；大复制必须确认且可续跑。
- **8GB 复制本身没有「优雅的浏览器解法」**——优雅的是 **根本不复制**。
