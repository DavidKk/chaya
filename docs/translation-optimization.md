## 1. 背景与核心问题

Chaya 当前具备多引擎并发翻译与非阻塞缓存调度能力，但在实际游戏汉化与游玩过程中，机翻（尤其是纯词汇直译、离线小模型机翻）存在明显的生硬与语义错位问题：

1. **游戏常用单词与专用术语机械直译**：例如经典游戏菜单与系统词汇，机翻往往直译为生活化通用词汇（如 `Save` 被机械译为“节省/拯救”，而游戏中应为“保存/存档”；`Load` 被译为“负荷/装载”，而游戏中应为“读取/读档/载入”；`Equip` 译为“装备”但有时被误译为“装设”；`Party` 译为“聚会/政党”而游戏中为“队伍/同伴”；`Item` 译为“项目/条款”而游戏中为“道具/物品”）。
2. **机翻初版与精翻/优化的定位分离**：机翻的核心价值是**以最低时延让玩家快速获得能看懂的初版译文**（先保证游戏可玩、不卡关），但这绝非终点。玩家在游玩或汉化完成后，需要一种自动或半自动的“二次优化（Polish / Refinement）”机制。
3. **资源利用率错位（游戏闲时算力浪费）**：实时游玩期间，用户通常在跑图、战斗或阅读长文本，此时外部大模型 Agent（Ollama、本地 LLM）或空闲算力处于待机状态；若能利用游戏闲时（Idle）或后台无感知进行长文润色、术语替换与二次批量优化，既不抢占实时对白带宽，又能持续提高本地汉化质量。

## 2. 核心目标与产品原则

### 2.1 游戏术语（Game Terms）分级增强与零成本修正

- **内置常见游戏术语库扩展**：丰富并细化单词与短语级术语表（如 Save -> 保存/存档，Load -> 读取/载入，New Game -> 新游戏，Continue -> 继续游戏，Options -> 设置/选项，Item -> 道具，Skill -> 技能，Status -> 状态，Quit -> 退出等），在快速匹配阶段即具备最高置信度命中能力。
- **批量一键术语纠偏**：针对已经机翻完成的缓存或译文库，支持一键批量扫描并优化已知的常见劣质机翻词汇（如纠正历史错误译文“节省” -> “保存”），无需消耗模型 Token，毫秒级快速完成。

### 2.2 批量二次优化（Batch Optimization / Polish）

- **按需触发的批量优化作业**：用户可在翻译控制台对已完成的翻译内容发起“二次优化”任务，支持针对单条目、按批次或针对整库低秩译文（如 `live:*` 来源、未经过精翻的机翻条目）进行批量重译或术语替换。
- **守秩保护与人工不可逆覆盖**：严格遵守 Chaya 缓存写入秩（Rank 机制）：人工修改（`manual`）与已确认映射拥有最高保护权；自动优化与二次润色结果只提升机翻低秩记录（`live:*`、`manual:optimize`），绝不静默覆盖人工定稿。

### 2.3 闲时智能优化（Idle / Background Optimization）

- **基于游戏运行状态与系统负载的闲时感知**：结合游戏连接心跳（`getGamePresence`），当检测到游戏未运行（离线闲时）或游戏运行中但近期无高频实时请求（请求空闲）时，调度器自动降低并发与资源配额，在后台平滑推进低优先级精翻与优化。
- **实时对白绝对优先（Preemption & Zero Jam）**：一旦用户在游戏中触发新的实时对话（对白拦截/请求涌入），闲时优化任务立即主动让出计算资源与引擎并发配额，保证游玩实时画面零卡顿。

## 3. 用户体验与典型场景

| 场景                 | 用户行为                                   | 系统响应与交互                                                                                                                                             |
| :------------------- | :----------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **术语即时修正**     | 游戏界面遇到单次菜单文字（如 Save/Load）   | 命中内置游戏术语表，秒级直接呈现“保存/读取”，避免机翻产生“节省”等荒谬译文。                                                                                |
| **已译条目批量优化** | 用户在翻译管理页点击“优化已译内容”         | 系统筛选出全部机翻来源条目，先快速执行术语表纠偏，再依序按优先级派发精翻引擎优化，进度条清晰展示优化率与优化前后对比。                                     |
| **后台闲时静默优化** | 用户在玩游戏或挂机，控制台开启后台优化     | 调度器在无实时翻译请求的空闲窗口，以低并发缓慢润色已存储的低质量初版机翻，并写入候选或提升低秩缓存；玩家下次读到该对白或重启游戏时，译文自然变得更加通顺。 |
| **游玩打断闲时任务** | 闲时任务运行中，玩家突发进入新剧情大量对白 | 系统检测到实时对白请求，闲时任务瞬时挂起让位，所有并发槽位优先保障实时翻译；对白结束后平滑恢复闲时优化。                                                   |

## 4. 边界与非目标

- **非目标**：本期不改变现有 SQLite 存储底层核心表结构；不引入破坏性数据库迁移。
- **保护底线**：任何自动优化绝不能以破坏 RM 控制码（如 `\C[2]`、`\FS[24]`）或覆盖人工精校为代价。
- **成本可控**：闲时优化优先使用本地离线/免费通道或用户明确授权的 Agent，默认限制速率，防止后台静默消耗大量商业 API 额度。
