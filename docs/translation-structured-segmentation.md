# 翻译缓存结构化分段优化方案

- 状态：首期实现；支持模式确认，任意边界拖拽与嵌套编辑留待后续。
- 日期：2026-10-17。
- 技术设计：[结构化分段与缓存测试](technical/translation-structured-segmentation.md)。
- 既有方案：[语义分段与优化需求](translation-cache-optimization.md)。

## 1. 目标

游戏文本不仅包含对白，也包含条件、材料、奖励、属性和操作说明。这些文本常由一个说明类别的标签和多个完整项目构成。标签与各项目可以分别翻译和复用，不必每次都把整段重新翻译。

本轮增加结构化分段：识别标签、阿拉伯数字编号、罗马数字编号、圈号和项目符号，提出完整项目的拆分结果；同时提供缓存测试页，展示每段能否复用、命中了什么以及如何拼回。

“完整”指项目本身能独立表达含义，不要求以句号结束。`铁矿石` 可以是完整材料名，`等级60以上` 可以是完整条件；不能把条件拆成 `等级`、`60`、`以上` 三段。

## 2. 核心案例

```text
解锁条件：①等级60以上 ②再次进行VIP特典工作
```

识别为一个标签和两个项目：

| 角色   | 可匹配文本          | 保留的结构         |
| ------ | ------------------- | ------------------ |
| 标签   | 解锁条件            | 后接冒号 `：`      |
| 项目一 | 等级60以上          | 前置编号 `①`       |
| 项目二 | 再次进行VIP特典工作 | 前置空格及编号 `②` |

编号、冒号、空格和换行保留在原文位置；匹配内容时不把它们强制并入词条。三段均有可用译文时，按原来的结构拼回。任何一段未命中，都明确标出缺口。

这是一条例子，不依赖预先枚举“解锁条件”“奖励”等中文词。日文、英文等语言出现相同结构时，使用同一套结构规则。

## 3. 支持的结构

| 结构                    | 示例                                                          | 候选片段                                           |
| ----------------------- | ------------------------------------------------------------- | -------------------------------------------------- |
| 冒号标签与圈号          | `所需材料：①铁矿石 ②木材`                                     | 所需材料／铁矿石／木材                             |
| 阿拉伯数字加点          | `奖励：1. 金币 2. 装备`                                       | 奖励／金币／装备                                   |
| 阿拉伯数字加顿号        | `条件：1、等级60以上 2、完成委托`                             | 条件／等级60以上／完成委托                         |
| 括号编号                | `材料：(1)铁矿石 (2)木材`                                     | 材料／铁矿石／木材                                 |
| 小写罗马数字            | `奖励：i. 金币 ii. 装备`                                      | 奖励／金币／装备                                   |
| 大写及 Unicode 罗马数字 | `条件：I. 完成委托 II. 返回城镇`、`条件：Ⅰ完成委托 Ⅱ返回城镇` | 标签／各完整条件                                   |
| 无点罗马数字列表        | `奖励：i 金币 ii 装备`                                        | 奖励／金币／装备；须识别出连续编号组               |
| 项目符号                | `属性：力量·敏捷·智力`、`材料：• 铁矿石 • 木材`               | 标签／各完整项目                                   |
| 换行列表                | `奖励：` 后分行列出 `1. 金币`、`2. 装备`                      | 标签／各完整项目；原换行保留                       |
| 无分隔点的数字列表      | `说明：1是什么 2是什么`                                       | 说明／是什么／是什么；证据较弱，先人工确认编号边界 |

圈号首期覆盖常见 `①` 至 `⑳`。编号从 1 以外的位置开始也可识别，但要求顺序关系明确。原有单独名词、标签或完整句缓存仍可独立命中。

## 4. 识别与确认

### 4.1 先识别列表组，再确定每项边界

`1.`、`i`、`II`、`·` 都可以是结构标记，但单个符号不足以证明可拆分。连续编号、相同编号格式、行首位置、冒号引出的列表和多个并列项目共同提供依据。

连续同族强编号自动接受；行内中点、无点编号及不连续编号先展示建议，允许人工接受或禁用拆分。现有原译分组仍支持编辑与合并。系统不根据字数平均分段，也不在任意名词、助词或数字处拆分。

### 4.2 标签与项目都要保持完整

`所需材料` 说明后面的类别，可以独立成段；编号后的材料名或条件保留完整。标题、标签不必拥有完整句子的语法形式。

如果冒号前是依赖后文才能表达完整意思的正文，或编号两侧明显属于一个数量、名称、表达式，则保留较大的完整区域。用户可以手动确认特殊格式，不强行套用自动规则。

### 4.3 典型误拆保护

| 文本                                | 处理                                       |
| ----------------------------------- | ------------------------------------------ |
| `伤害提高1.5倍`                     | 小数不作为编号                             |
| `版本1.2.3`、日期、IP、URL          | 数值或受保护文本内部不拆分                 |
| `等级60以上`、`金币100`、`第1章`    | 数字属于项目正文                           |
| `VIP II`、`最终幻想 VII`            | 罗马数字可能是名称或等级，单独出现不拆分   |
| `约翰·史密斯`                       | 中点可能属于人名；没有列表证据时不自动拆分 |
| `\V[1]`、`\C[2]`、Ruby、替换占位符  | 控制码和参数内部不拆分；保留显示作用域     |
| `1. 等级60以上且` 换行接 `完成委托` | 同一项目内的排版折行不生成新的独立项目     |
| 引号里的 `“1.5倍”`                  | 引语内的标点不能直接作为外层列表标记       |

`属性：力量·敏捷·智力` 可提出明确的列表候选；`作者：约翰·史密斯` 保留作者名；带多个中点的名字也只生成待确认建议。冒号本身不能保证每个中点都是项目分隔符。

## 5. 原译对齐与缓存复用

结构化分段分别回答两个问题：原文可以在哪拆，以及每一段对应哪段译文。

原文结构明确，可以自动拆段并查询已有独立缓存；但要从一条已有整段译文中提取子译文，必须有与当前定稿版本绑定的已确认映射。原译编号相同、段数相同或标点相似，都不能自动证明语义一一对应。

优化页提供以下操作：

1. 展示原始定稿和标签、项目正文的拆分预览，编号及分隔符按布局保留。
2. 原译两侧分别选择自动、接受建议或禁用模式；继续使用原译分组编辑与合并。任意区间拖拽不在首期范围。
3. 用户确认对应关系；一对多、多对一作为完整映射块保存。
4. 预校验通过后保存结构注解和映射，均绑定当前定稿版本。
5. 更改边界模式会提示替换旧映射；禁用一侧拆分只保存模式并清空旧映射。
6. 不自动生成大量去编号、去标点的新缓存记录，不更改原文主键。

已有人工译文保护、语言对、来源优先级和冲突策略继续生效。结构清晰不能覆盖人工决策，也不能解除译文歧义。

查询先尝试可用整段与连续完整块；整段不能复用时，再按标签和项目查询。列表项之间保留独立边界，不能为了提高覆盖率把不同项目拼成一个短句。原项目内的标点、数量、否定和修饰关系保持完整。

## 6. 缓存测试页

入口为翻译库内容头部最右侧的「缓存翻译调试」，路径 `/translate/test`，首期用于本机服务或 App。共享库索引未就绪时提示先打开普通缓存页完成初始化；测试请求不执行迁移。

### 6.1 输入

- 原文输入没有 `q` 参数时初始为空，不预填示例；有 `q` 时还原原文。点击「测试缓存」通过 replace 将完整原文同步到当前 URL 的 `q` 参数，保留 `returnTo` 等已有参数、不新增历史记录、不改变滚动位置；仅编辑草稿时不更新 URL。用户粘贴的真实换行、空格和控制码须完整保留。
- 选择源语言和目标语言。共享库支持四种已有语言代码；本作缓存没有独立语言对元数据，首期仅按原文语言检测后用于译入中文的查询，其它目标语言禁用本作及合并范围。
- 选择共享翻译库、当前游戏翻译库或合并查询；未绑定游戏时禁用需要当前游戏的范围。
- 对低确定性的分段，可以在本次测试中确认边界；默认不保存。

### 6.2 结果

结果同时展示原文、分段结构、各段命中及拼接预览。明细包含命中记录身份、来源、匹配方式、原文片段与复用译文，并汇总结构歧义、缺少映射或达到上限等原因。首期不逐条列出所有拒绝候选。自动建议与人工确认须有区别。

| 结果       | 含义                                               |
| ---------- | -------------------------------------------------- |
| 完整命中   | 所有需要翻译的完整单元均可复用                     |
| 部分命中   | 只有部分单元可复用，缺口保留原文并高亮             |
| 未命中     | 没有可用单元                                       |
| 冲突或歧义 | 有候选但无法唯一选择，不冒充成功命中               |
| 查询受限   | 达到长度、候选或项目数上限；说明哪些内容未完成检查 |

测试只查询和预览，不调用翻译引擎、不自动补译、不写回缓存、不增加使用命中次数，也不触发本作共享译文回填。进入优化页确认保存是独立操作。

界面中的拼接预览用于解释查询结果。游戏内既有渐进替换行为保持原有契约，不因测试页新增而改变。

## 7. 实施顺序与验收

先实现共享结构识别与原文位置保留，再接入优化确认和匹配索引，最后上线缓存测试页并做真实语料回放。数字占位符泛化、任意语义分句和嵌套列表编辑器留到后续。

验收至少覆盖：

- 核心案例得到一个标签和两个完整项目，重新拼接与原文完全一致。
- 阿拉伯数字、罗马数字、圈号和项目符号的常见格式均有正反例。
- 小数、版本、数量、名称中的罗马数字、人名中点和控制码不被误拆。
- 两段命中、一段未命中时展示部分命中，测试期间没有补译或写回。
- 原译段数相同但内容错位时，不自动赋予可信映射。
- 修改父记录后，旧结构注解和映射失效，测试能说明版本变化。
- 服务端、优化预览和插件使用同版本规则，结果差异可定位。

收益按真实语料统计完整命中、部分命中、歧义、误拆及人工确认比例，不预设未经测量的命中率提升。

## 8. 缓存翻译调试入口

2026-10-18：将现有缓存测试页作为「缓存翻译调试」页，入口放在 Web 缓存列表的内容头部最右侧，排在所有筛选项之后。使用 32px 图标按钮与调试图标，提供「缓存翻译调试」可访问名称和「仅使用缓存翻译，查看命中、缺口与拼接结果」Tooltip；键盘及触控均可直接进入。

页面沿用 `/translate/test`，取消独立测试侧栏入口，进入时侧栏仍选中翻译库。新增返回翻译库按钮，恢复进入前的查询、语言筛选、排序及分页。无来源链接直接访问时返回默认缓存列表。缓存列表空、加载中或错误时，调试入口仍可用。

基于缓存翻译指只使用现有缓存和匹配规划器：显示完整／部分／未命中、结构拆分、命中记录及拼接预览。缺口保留原文并高亮，不调用模型补齐。点击调试才查询；修改输入或语言后清空旧结果。重复调试开始时也清空上次结果，避免旧快照被误读为本次结果。

测试操作始终只有一个「测试缓存」按钮。请求期间沿用共享 Button 的 loading 状态，在原尺寸内只显示 spinner、隐藏文字并禁止重复点击；完成或失败后还原文字。不新增取消按钮。编号结构明确对应的缓存整句可提供完整短项；中间一项未命中时，前后命中仍分别回填，不能整句回退。

提供本次查询的候选记录数和规则版本，便于复现。首期不新增缓存写入、命中计数、引擎调用或任意脚本执行能力。Cloud 沿用磁盘能力提示，GameEdit 浮层不提供跳出游戏的 Web 入口。

窄屏时只横向滚动筛选栏，调试按钮始终固定在头部最右侧。返回按钮显示在调试页标题左侧；调试页原有范围、语言、边界模式与错误提示继续生效。

验收：入口最后排列且 Tooltip 可达；点击进入并返回可恢复列表状态；直接访问有安全默认返回；旧测试地址有效；侧栏无重复入口；缺口不冒充完整译文；桌面与窄屏按钮可用。

## 2026-10-18：完整句自动对齐回退

完整句的运行时提取新增受限例外，见[整句对齐回退](translation-sentence-fallback.md)。原译句数、语气与控制签名满足规则时可临时推断句末对应关系；不新增索引、不保存映射，不将推断视为 verified。列表及逗号子句仍沿用原有确认要求。
