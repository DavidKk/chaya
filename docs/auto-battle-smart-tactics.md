## 1. 背景与核心痛点

Chaya 控制台及游戏浮层中提供了“自动战斗（`autoBattle`）”运行开关，其初衷是为玩家提供流畅的战斗托管能力（“自动选攻击/技能；敌群事件后再行动”）。

然而在当前版本中，该功能直接挂钩 RPG Maker 引擎原生 `isAutoBattle`（或 `auto_battle?`），导致实际游玩体验极其呆滞，表现为“只会平 A”、“行为不自然”，主要暴露以下核心痛点：

### 痛点 1：机制呆滞，强力技能沦为摆设（只会平 A）

- **非伤害/非治疗技能 100% 暴毙**：原生评估算法仅给直接伤害/治疗技能打分，所有增益（加攻/防/速/盾）、减益（破甲/降防）、状态异常（眩晕/催眠/麻痹）、驱散与嘲讽技能评分恒为 0，因无法超越初始阈值而永远不会被释放。
- **随机数淹没伤害差异**：原生引擎在技能伤害评分后叠加 `Math.random()`（0~1 浮动），高血量战斗中伤害分值仅 0.05~0.2，平 A 凭借随机数有极高概率反超高伤害技能，导致角色频繁放弃大招使用普攻。
- **预估阶段插件报错归零**：许多第三方插件（如 Yanfly 系列）的伤害公式引用了执行期上下文，在输入阶段预计算时抛错并被原生静默吞掉，技能直接归零淘汰，仅留下无插件依赖的普通攻击。

### 痛点 2：特殊状态下死磕平 A 导致卡顿或抽搐（典型如“缴械”）

- 当角色受到“缴械 / 攻击被封印”状态影响时，普通攻击 `canUse()` 为 `false`；
- 原生打擂流程中未将“防御（Guard）”纳入候选池，且如果技能池恰好因蓝量、沉默或上述评分缺陷无法选出有效技能，角色将产生空动作；
- 引擎在输入阶段不断重试或停滞，表现为角色在每帧不断尝试平 A、原地抽搐发呆或卡死输入回合。

### 痛点 3：多菜单分类与技能类型无法有效调度

- 许多游戏将技能细分为多个菜单（如普通攻击、白魔法、黑魔法、战技、必杀奥义、职业专属技等）；
- 虽数据层包含在 `usableSkills` 中，但高级战技多消耗 TP（开战初始为 0 导致前期用不出）、辅助菜单全为 0 分、奥义受公式报错影响，导致“菜单虽多，但只有平 A 能点”。

### 痛点 4：缺乏战局与生命态势感知

- **无视队友危机**：队友濒血甚至倒地时，有治疗或复活技能的角色依然只顾平 A 攻击；满血时却可能因除以 0 的计算缺陷丢大治疗。
- **无视敌群规模与残血**：面对多只群怪时不用全体 AOE；面对只剩一丝血皮的残血小怪时，无法感知斩杀，可能浪费高蓝大招或错失补刀时机。

## 2. 核心目标与衡量标准

| 编号   | 目标项                       | 详细定义与衡量标准                                                                                                                 |
| ------ | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **G1** | **情境感知优先决策**         | 动作选择不再是简单的“无脑平 A 打擂”，而是根据自身状态（是否缴械/沉默）、队友生命（是否危急/倒地）、敌群态势（群怪/残血）动态分流。 |
| **G2** | **全菜单技能穿透**           | 不依赖 UI 菜单层级，直接在底层打平角色所有的可用技能（魔法、战技、特技、奥义），无论归属哪个子菜单均可根据战况被正常调用。         |
| **G3** | **受限自愈与优雅防御**       | 当受到**缴械（无法平 A）**时，立即转向使用可用特技/魔法；若无技能可用，**自动执行防御（Guard）**，彻底杜绝死磕平 A 与回合卡死。    |
| **G4** | **战术合理性（救急与收割）** | 队友 HP 低于阈值（如 < 35%~40%）时优先单体/群体回复；存活敌人 ≥2 且有 AOE 时优先群伤；残血目标优先低消耗补刀斩杀。                 |
| **G5** | **去随机数稳定释放**         | 剔除原生破坏性的 0~1 随机数扰动，资源允许且效果有效时默认优先技能；普攻已能击杀时节省技能消耗。                                    |
| **G6** | **跨引擎一致性**             | 目标为双运行时情境决策一致；本次 MV 修复不代表 MZ / RGSS 已完成验收。                                                              |
| **G7** | **技能优先与道具智能协同**   | 默认优先使用可再生技能；在无技能/空蓝/无回复技或需补给时调取道具；根据受创缺口（如缺 200 血尽量用 200 回血药）智能匹配。           |
| **G8** | **过期低效道具自动淘汰**     | 识别角色血量体量，后期面对数千血池时，自动过滤淘汰回 50HP 这类杯水车薪的早期道具，避免浪费珍贵回合。                               |
| **G9** | **MP 监听与投掷道具利用**    | 实时监听角色 MP 状态，低蓝时可用道具补蓝；被缴械或空蓝时，可使用投掷类伤害道具对敌打击。                                           |

## 3. 情境决策行为规范（行为树）

自动战斗每轮为角色生成行动时，按以下优先级流水线依次决策：

```text
[进入角色行动决策]
       │
       ▼
 [阶段 1: 自身能力与状态约束检查]
  ├─ 是否被沉默？ → 排除魔法类技能
  ├─ 是否被缴械 / 封印攻击？ → 标记普攻不可用
  └─ 提取当前角色真正可用动作集合 (满足 MP/TP 消耗、武器与条件限制)
       │
       ▼
 [阶段 2: 团队生命危急评估 (救急优先: 技能 > 道具)]
  ├─ 存在阵亡队友？ → 优先复活技能；无技能则使用复活道具 (如不死鸟之尾)
  ├─ 存在队友 HP < 35%~40%？
  │    ├─ 优先使用可用治疗技能
  │    └─ 无技能/空蓝？ → 检索回血道具：
  │         ├─ 过滤淘汰低效前期道具 (如数千血池时丢弃 50HP 药水)
  │         └─ 智能匹配受损缺口 (如受伤 200 优先匹配 200 回血道具，避免过量浪费)
  └─ 全队健康 → 进入阶段 2.5

 [阶段 2.5: 资源续航与 MP 监听]
  ├─ 角色为技能/法系核心 & MP 比例 < 35%？
  │    └─ 背包持有回蓝道具 (如魔法水/以太) → 使用道具回蓝维持战力
  └─ MP 充足 → 进入阶段 3
       │
       ▼
 [阶段 3: 敌群战局态势决策 (输出/压制: 技能 > 普攻 > 投掷道具)]
  ├─ 存活敌人数 ≥ 2 & 拥有可用全体技能？ → 优先释放全体 AOE 压制
  ├─ 存在残血可击杀敌人？ → 优先以低消耗/普攻完成收割斩杀
  ├─ 面对普通/精英敌人 → 优先释放期望伤害高且资源充足的优势技能
  └─ 被缴械或无蓝可用？ → 若持有投掷伤害道具 (如手榴弹/飞刀/属性石) 优先投掷输出
       │
       ▼
 [阶段 4: 兜底降级决策 (防卡死保障)]
  ├─ 普攻可用？ → 执行普通攻击
  └─ 普攻不可用 (如被缴械) 或无可用技能？ → 执行防御 (Guard)，绝不发呆死磕
```

## 4. 详细场景用例

### 用例 1：角色被缴械（无法平 A）

- **前置条件**：角色附加了“禁止攻击”或装备/状态导致普攻被封印。
- **分支 1（有可用技能）**：角色若有满足 MP/TP 的战技或魔法，正常选择并释放技能打向敌人。
- **分支 2（无可用技能/空蓝）**：角色立即将动作设置为“防御（Guard）”，回合顺利推进，控制台不报死锁，角色不抽搐。

### 用例 2：角色被沉默（无法施法）

- **前置条件**：角色附加了“封印魔法”状态。
- **行为表现**：自动排除所有魔法类型技能，转向使用不需要魔法的物理特技或普通攻击。

### 用例 3：队友濒危急救

- **前置条件**：队伍中有角色 HP 低于最大 HP 的 35%，且当前角色持有回复技能并有足够蓝量。
- **行为表现**：角色放弃普攻或输出，将目标锁定为当前生命比例最低的存活队友并施放治疗。

### 用例 4：面对群怪

- **前置条件**：存活敌人数量 ≥ 2，角色拥有全体攻击技能。
- **行为表现**：优先释放全体技能，避免在群怪场景下一次次单体平 A 拖慢战斗节奏。

---

### 用例 5：智能回血匹配与低效道具淘汰

- **场景 A（缺口精确匹配）**：角色受到 220 点伤害（缺口 220），背包中同时持有“草药（回 50）”、“回复剂（回 200）”、“特级回复剂（回 2000）”。系统智能选用“回复剂”，尽量贴近缺口，避免浪费特级道具。
- **场景 B（后期低效道具过滤）**：后期角色 Max HP 达到 4500，当前受到 2800 伤害，背包仍残留游戏前期未用完的“小草药（回 50）”。若无强力回血道具或技能，系统直接标记淘汰该草药，绝不浪费整整一轮行动去回复无济于事的 50 点生命。

### 用例 6：MP 枯竭预警与道具回蓝

- **前置条件**：角色具备高价值魔法/特技，但当前 MP 低于 35%（或无法支撑下一次关键技能消耗），全队无生命危险。
- **行为表现**：角色自动使用背包中的以太/魔法药剂为自身恢复 MP，保障后续轮次的技能压制力。

### 用例 7：缴械与受限时的投掷道具利用

- **前置条件**：角色处于缴械状态无法平 A，且无可用蓝量释放技能，但背包中持有可对敌投掷的炸弹或伤害卷轴。
- **行为表现**：优先选用投掷道具给予敌方致命打击，而非直接转入被动防御。

## 5. 非功能需求与边界

1. **零配置开箱即用**：沿用现有的 `autoBattle` 开关与全局快捷键，不需要在设置界面添加繁琐的技能权重配置，默认行为即符合玩家直觉。
2. **容错与插件保护**：所有第三方插件自定义公式的 eval 必须使用严格的 try-catch 包裹，发生异常时静默降级到基础物理攻击或防御，绝不打断游戏进程。
3. **事件与剧情兼容**：遇到敌群事件运行中（`troop.isEventRunning()`）或战斗消息框忙碌（`message.isBusy()`）时，严禁抢先提交动作，严格保持现有安全栅栏。
4. **与一键胜利互斥**：当 `autoWin` 开启时，`autoWin` 拥有最高优先级，自动战斗不进行干涉。

## 6. 取消与手动接管验收

1. 输入期取消后恢复“攻击、技能、物品、防御”命令与 MOG 命令精灵。
2. 已提交动作执行期间取消，等待当前动作结束；不抢先弹出命令，下次输入正常选择。
3. 接管时关闭仍可见的技能/物品列表、目标列表与帮助窗口，避免遮住战斗。
4. 开关重复关闭或在消息期间尚未接管就取消，保留当前手动子菜单。
5. 已满层增益、已有状态或免疫目标不反复施放；无法攻击时不随机释放无目标的治疗/复活技能。

本次实现会在决策中跳过低效道具，不删除库存、不新增持久标记或 UI 标签。全队未来行动收益预测、跨角色物品预留、未知脚本效果推断不在当前已验证范围内。
