# 翻译缓存整句对齐回退需求

- 日期：2026-10-18
- 状态：已实现并通过算法、服务与真实缓存回放验证。
- 技术设计：[整句对齐回退](technical/translation-sentence-fallback.md)。

## 目标

查询 `a.b.` 时先尝试整体复用；整体不可用时，复用独立句缓存。独立句未命中时，通过现有句子索引找到包含该句的整段缓存 `a.c.`，在原译两侧可按句末标点等长对齐的情况下，临时取出对应的 `a1.`。未命中的 `b.` 保留为待翻译，结果为部分命中。

本轮优化算法，不新增数据库表、索引、派生缓存记录或持久化映射，不触发索引重建。共享库、本作与插件使用同一纯规则。

## 匹配顺序

1. 沿用现有整段、独立句、完整块及人工确认映射匹配；可完整覆盖时直接返回。
2. 仍有缺口时，对现有候选记录推断句末标点对应关系，仅补充缺口。
3. 保留已有命中与本作人工保护；推断不能替换已有译文，不能覆盖用户已保存的映射。
4. 多个推断候选对同一范围给出不同译文时保留缺口并标记歧义，不按时间选择。

## 自动对齐范围

- 原文和译文都至少包含两句，每句以句号、问号或感叹号结束；两侧句数相同、逐句语气标点兼容。
- 逗号、顿号、分号、换行不作为自动对齐依据；同一句内的这些分隔仍属于整句。
- 查询必须命中完整句子，不截取半句、任意词、数字或单个字符。
- 保留受保护引语和括号，不在其内部新增拆分。列表结构及禁用拆分的记录不参与推断。
- 控制码、占位符逐句一致；跨句有状态格式、HTML/Ruby 等复杂文本不参与推断。
- 自动结果属于结构推断，不等于语义验证。合句、拆句、重排仍可能造成误配，规则检查只能降低风险。已确认映射优先。

## 结果与只读约束

继续使用完整／部分／未命中、歧义和受限状态。推断命中保留父记录 id、revision、原文区间与译文，并在匹配数据中标记推断依据，不冒充人工确认。缺口不调用模型补译。

诊断操作不写数据库、不增加命中计数、不回填本作。仍保留候选数及计算量上限。

## 验收

- `a.b.` 整体命中时不做自动对齐，即使别的记录可推断出不同的 `a1.`。
- 只有 `a.c. → a1.c1.` 时，`a.b.` 得到 `a1.b.` 的部分预览；支持从段首、段中及段尾取句。
- 真实案例：`勇者パーティの天才美少女魔法使い。勇者レオンとは幼馴 3染で許嫁。` 的第一句可复用，第二句保持待翻译；另用移除独立短句的固定语料验证确实走整段提取。
- 原译句数不同、只按逗号分段、只命中半句、语气变化、控制码错位、推断译文冲突时不自动填入。
- 有独立句或已确认映射时优先使用；缓存修改后下次查询使用当前译文。
- SQLite 与插件内存规划结果一致；数据库内容、revision、索引及统计不因诊断改变。

## 完整行独立缓存回退

2026-10-18：多行对白中的软换行通常先按连续正文匹配；如果整段、句段与整句推断之后仍有缺口，允许按完整行查找已有独立缓存。举例：`改动前缀、` 换行接 `名字は`、`后续正文`，后两行分别存在独立译文时可以复用，改动前缀保留原文。

这一步只复用完整行对应的独立词条，不根据原译行数提取父记录，不做任意子串搜索。整段与已有命中优先，显式换行注解、受保护引语及禁用拆分规则继续生效。换行、缩进和未命中的内容按原文保留；原先“软换行两侧不能匹配”的限制仅保留于语义分句和父记录提取，独立完整行缓存作为此处明确的回退例外。

## 系统性验收

新增固定语料组合矩阵：句号、顿号、分号、换行分别与无外壳、`「」`、`『』`、`（）` 组合，再分别改动开头、中间和末尾，未改动且有独立缓存的片段必须继续命中。另用只保留父段落缓存的组合验证整句提取。候选检索和规划器必须使用相同的查询视图；不能依赖修改已有缓存或升级索引来使这些用例通过。成对外层对白壳可保留后进入正文匹配，正文内部的嵌套引语仍受保护。
