# 游戏多语言包自动探测、语料反哺与双向对照翻译需求文档

- **状态**：设计完成 / 待开工
- **版本**：v1.0
- **日期**：2026-10-18
- **关联技术方案**：[docs/technical/game-multilingual-locales.md](technical/game-multilingual-locales.md)

---

## 1. 背景与核心痛点

在当前的 RPG Maker 游戏抽取流程中，遇到使用多语言本地化插件（如 `DKTools_Localization`、`PKD_EasyLocalization`）的游戏时：

1. **原文全部显示为占位符 Key（如 `Map007-42`、`Map066-18`）**：
   - 地图事件与数据库中并不存放自然语言对话，而是存放占位符 Key；
   - 现行抽取逻辑仅剥离大括号，导致列表与抽取结果前上百页充斥着无意义的键名，用户无法阅读与翻译。
2. **游戏自带高质量多语言文本被闲置**：
   - 游戏根目录下的 `locales/` 中通常已包含官方制作的英语、俄语、日语、韩语、繁体中文等多语言对应文本（例如当前游戏包含 40,076 条高质量多语言台词）；
   - 系统未将这些宝贵的平行语料吸收沉淀为翻译缓存记忆库。
3. **缺少语种对照与新增语种翻译能力**：
   - 汉化者往往更习惯参照英文或日文进行翻译，但系统无法自由切换参考语言；
   - 当用户想将游戏翻译为游戏原生未收录的语种时，缺乏直观新建与回写机制。

---

## 2. 目标与需求范围

### 2.1 自动多语言包探测（Locales Discovery）

- 自动检测游戏根目录与常见变体路径（`locales/`、`www/locales/`、`languages/`、`data/locales/` 以及 `js/plugins.js` 声明配置）。
- **排除无用底层二进制包**：自动规避 Chromium / NW.js 框架自带的 `locales/*.pak`（仅为浏览器运行时右键菜单等无用系统文件），精准锁定存放真实游戏剧本的语言包目录。
- 探测并提取游戏原生支持的所有语种（如 `ru`、`en`、`ch`、`cht`、`ja`、`ko` 等）。

### 2.2 真实自然语言台词还原与 Key 标签呈现

- **原文展现**：若命中多语言包，将 `Mapxxx-xxx` 占位符自动解析还原为真实自然语言原文（默认以开发源语言或英语为基准），彻底告别 Key 刷屏。
- **Key 专属标识标签**：
  - 条目顶部保留精简的 Key 标签（如 `Map007-42`），具备最大宽度与截断保护（`truncate`）；
  - Hover 弹出 Tooltip 展示完整 Key 与所属文件，并允许一键复制。
- **无多语言时的优雅降级**：若未探测到多语言文件，则保持当前的单语言/默认展示模式，无缝兼容传统游戏。

### 2.3 “源语言 ⇆ 目标语言”同框复合选择器

- 仅在探测到多语言文件时，在列表顶部筛选栏中展示该控件。
- 遵循公共组件与暗黑设计规范：
  - **同一个外框**，固定高 32px（`h-8`），中间带有双向切换图标（`LiaExchangeAltSolid`），左侧为源语言下拉，右侧为目标语言下拉。
- **切换联动**：
  - 切换源语言（左侧）：列表原文实时替换为该语言的真实台词。
  - 切换目标语言（右侧）：
    - 若该目标语言在游戏中已存在译文，则右侧译文编辑器直接展示已有译文供校对与二次编辑；
    - 若选择游戏未收录的语言（支持添加新目标语言），译文编辑器留空，允许用户自由输入或点击“智能翻译”生成。

### 2.4 多语言平行语料库全排列入库（缓存预热）

- 系统从游戏多语言包中提取所有有效台词，生成纯文字对文字的双向平行语料（$N 	imes (N-1)$ 全向互译组合）：
  - 严禁将 Key（如 `Map066-18`）写入翻译缓存；
  - 仅保存文字到文字（如 `"Supreme Magic..."` ↔ `"诸神贪得无厌..."`）；
  - 来源引擎标记为 `game:locales`，自动沉淀至系统的本地翻译数据库（`translate-cache.db`），极大增强系统在跨游戏、同类型游戏及局内实时翻译中的命中率。

### 2.5 语言包回写与自动备份机制（`*.bak.json`）

- 当用户在列表中修改并点击“保存”某条翻译时：
  1. 依据该条目的 Key 找到对应的多语言文件（例如目标语言为 `ch` 时写入 `locales/ch/Act1.json`）；
  2. **安全备份**：首次修改该文件时，自动在同目录下创建 `*.bak.json` 备份文件；
  3. 更新对应 JSON 文件的 Key 映射值；
  4. 同步更新本地翻译缓存数据库。
