# Agent 活动记录需求

> 状态：已实现
> 日期：2026-10-09
> 技术方案：[`technical/agent-activity-log.md`](./technical/agent-activity-log.md)
> 关联：[`game-agent.md`](./game-agent.md)、[`game-assistance.md`](./game-assistance.md)

## 1. 背景与目标

当前侧栏和陪玩面板只能显示少量阶段文案或持续 loading。玩家无法确认 Agent 正在观察什么、调用了哪些工具、为何继续或停止；日志页也无法回溯一次任务的提示词、操作和结果。

本需求建立一份跨入口共享的 Agent 活动记录。侧栏、陪玩面板和日志页读取同一任务记录，不各自维护互相冲突的历史。

目标：

- 运行中持续展示可理解的活动，不让玩家面对无信息的 loading。
- 记录用户提示词、实际系统提示词、公开判断摘要、模型回复、工具调用和 token 用量。
- 陪玩迷你面板提供“聊天 / 思考过程”两个 Tab。
- 日志页提供“运行日志 / Agent 活动”两个二级页面。
- 同一任务的成功、失败、停止或上限提示只产生一份最终结果。
- 挂机任务遇到单周期工具调用上限或当前目标完成时保存进度并进入下一周期；正常情况下只有玩家主动点击停止才结束，不可恢复错误可以被迫终止。

## 2. 记录边界

“思考过程”是面向玩家和开发调试的结构化活动摘要，不是模型隐藏思维链。系统不得请求、保存或展示原始 chain-of-thought。可记录的公开阶段包括：

- `observation`：本轮读取到的关键事实。
- `decision`：选择当前动作的简短理由。
- `plan`：下一步计划。
- `action`：正在或已经调用的工具。
- `result`：工具或模型返回的可验证结果。
- `next`：继续、等待玩家或结束的原因。

记录内容：

| 类别     | 必须记录                                                                                      |
| -------- | --------------------------------------------------------------------------------------------- |
| 任务     | task id、game id、会话、入口、能力、Agent 配置、模型、状态、开始和结束时间                    |
| 提示词   | 用户原始提示词、实际生效的系统提示词、玩家后续回复                                            |
| 模型     | 请求开始、公开活动摘要、最终回复、失败信息、耗时                                              |
| 工具     | 名称、脱敏后的参数、开始时间、脱敏后的结果或错误、耗时、状态                                  |
| 用量     | provider 提供的 input、output、reasoning、cached input、total token；未提供时显示未知，不估算 |
| 生命周期 | 阶段变化、进度、等待玩家、停止、完成、失败、重载中断和历史缺口                                |

凭证、Authorization、cookie、token、secret、password、API key、用户主目录及绝对本地路径必须在写入前脱敏。UI 再做防御性脱敏，但不能把只在展示层遮盖当作安全保证。

## 3. 统一任务与互斥

- 同一游戏同一时间只允许一个 Agent 任务运行。侧栏、陪玩聊天、自动陪玩和其它入口共享这把锁。
- 任一入口启动任务后，其它入口显示同一个进行中任务和停止按钮，不能再次启动冲突任务。
- 关闭面板、切换 Tab、SSE 断开或完成一个阶段目标都不会停止挂机任务。正常情况下只有玩家点击停止才结束；游戏断连或不可恢复错误可以被迫终止。
- 刷新或重新打开面板后，从持久化事件序号恢复活动记录；历史被裁剪时明确显示缺口。

## 4. 各界面行为

### 4.1 Agent 侧栏

- 运行中的 Agent 回复区域展示当前公开活动摘要和工具调用。
- 新活动实时追加；工具行显示运行中、成功或失败以及耗时，可展开查看脱敏参数和结果。
- 最终回复到达后替换“正在思考”主显示；此前活动默认折叠在该回复下，可展开回看。
- 等待玩家时保留活动历史，并在输入区显示具体问题。

### 4.2 陪玩迷你面板

- 内容区顶部提供“聊天”和“思考过程”两个 Tab，默认进入聊天。
- 聊天继续展示玩家与陪玩回复；思考过程展示当前共享任务的活动时间线、工具调用与状态。
- 切换 Tab 不影响任务运行。任务从侧栏发起时，陪玩思考 Tab 仍显示同一记录。
- 自动陪玩提示也走统一 Agent Turn，不再调用独立、已不存在的接口。

### 4.3 日志页

- 日志页提供“运行日志”和“Agent 活动”两个二级页面，URL 可直接表达当前页面。
- 两个二级页面使用与辅助、设置、翻译和集成页面一致的侧栏导航；窄屏完全隐藏页面内二级导航，并将一级、二级入口统一收进右上角导航菜单。
- Agent 活动页按任务倒序展示，可选择任务并查看详情。
- 详情按时间展示完整记录，包含提示词、公开活动、工具参数与结果、最终回复、用量和耗时。
- 空态、连接失败、历史缺口和仍在运行使用独立明确状态；错误不挤进滚动内容底部。

## 5. 连续挂机与终态

- 单周期仍保留模型循环和工具调用硬上限，防止一次请求失控。
- 挂机任务达到单周期上限时写入进度事件和 `next` 摘要，等待短间隔后启动下一周期；不写 `failed`，不向聊天追加“操作未完成”。
- 每个新周期携带原始目标、最新公开进度和必要历史，重新观察后再行动。
- 当前目标已经完成时先输出阶段结果，再进入监看周期；没有新动作可做时保持低频观察，不以成功终态退出挂机。
- 玩家点击停止后不再开始下一周期，当前短动作结束或取消后写入一个 `stopped` 终态。
- 完成、失败和停止由任务控制器各写一次。聊天 UI 只从任务终态生成最终消息，不再额外追加同文错误，因此不得出现 `Yui:` 与 `!:` 两条相同上限提示。
- 连续任务仍受任务级安全边界约束：游戏断连、重复不可恢复错误、权限拒绝或数据损坏会终止并说明原因。

## 6. 保留与降级

- 延续现有任务存储：最多 20 个任务、单任务最多 200 个事件、任务最长保留 7 天；达到边界时裁剪最旧记录。
- Node 游戏写入游戏目录中的任务文件；浏览器形态使用现有本地存储。
- 持久化失败时任务可以继续运行，但必须产生可见的“记录未持久化”警告；不得因写日志失败卡死游戏操作。
- 不支持记录的 provider 字段保持为空，不影响任务继续。

## 7. 验收标准

1. 从侧栏发起任务，侧栏和陪玩思考 Tab 同时看到相同阶段与工具调用，且另一个入口不能再启动任务。
2. 最终回复出现后，活动记录自动收起，可展开查看工具参数、结果、耗时和 token 用量。
3. 陪玩面板具有“聊天 / 思考过程”两个可键盘访问的 Tab，切换不会中止任务。
4. 日志页可在“运行日志 / Agent 活动”间切换；刷新后仍能打开最近任务及其提示词、活动、工具和回复。
5. 系统提示词会记录，但凭证、敏感字段和绝对本地路径不会以明文落盘或显示。
6. provider 返回 token 统计时正确汇总；未返回时显示未知且任务正常完成。
7. 达到单周期工具调用上限或完成当前阶段目标的挂机任务记录进度后继续监看，正常情况下直到玩家点击停止才结束。
8. 同一终态只显示一次，不再出现角色回复和错误行内容相同的重复输出。
9. SSE 断线、面板关闭和页面刷新不停止任务；重连按事件序号恢复且不重复渲染。
10. 记录写入失败、单个事件损坏或历史被裁剪时均有降级提示，界面和任务不会卡死。
