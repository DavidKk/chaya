## 2. 身份、当前事实与能力契约（T0）

所有接口使用同一组身份，不让 `gameId` 同时代指库游戏、运行实例和连接。

```ts
type RuntimeScope = {
  libraryGameId: string
  dataRevision: string
  playthroughId: string
  runtimeInstanceId: string
  segmentId: string
}

type ContextStamp = {
  scope: RuntimeScope
  contextEpoch: number
  factsRevision: number
}

type FactValue<T> = { value: T | null; known: boolean; sourceRefs: string[] }

type FactView = {
  stamp: ContextStamp
  capabilities: Record<string, 'supported' | 'partial' | 'unsupported'>
  current: CurrentGameFacts
  mechanics: KnownMechanics
}
```

`CurrentGameFacts`、`KnownMechanics` 在 T0 定义为具名类型和可区分联合，不保留任意 JSON 作为稳定实现契约。至少涵盖场景 / 地图、队伍与敌人实体、遭遇、HP / 资源、关键状态、当前合法行动和可读技能 / 状态机制。机制保留标准字段、适用条件、来源及未知项；不执行任意脚本去猜隐藏效果。展示还需遵守玩家剧透偏好。

`factsRevision` 表示有关事实的版本，不是帧号。模型结果不因普通数值更新一律作废，而按它依赖的事实校验；`contextEpoch` 在加载开始、人工重置和失去可信现场时递增，旧 epoch 的异步结果不能再用于当前现场。成功读档再建立新 `segmentId`；失败回滚保留分段但重建 epoch / 基线。

游戏事实接口提供 `current()`、`subscribe(afterSourceCursor, listener)`、`readMechanics(entityRefs)`。读取失败返回不可用或未知，不能将空数组解释成没有敌人 / 没有技能。旧事件信封沿用 `producer.id / epoch / sourceSeq` 和 `eventId`，兼容字段只映射一次，不创造第二套游戏事实来源。

## 3. 模块与传输接口（T0）

下面列出必需语义，具体 TS 联合类型与现有桥接消息在 T0 固定；接口是进程内 port，跨已有桥接的情况由适配器实现，不表示新增网络服务。

| 接口                                     | 输入 → 输出                                                              | 所有权                             |
| ---------------------------------------- | ------------------------------------------------------------------------ | ---------------------------------- |
| `memory.ingest`                          | 来源事件、记录设置版本 → 内存投影 / 待提交经历                           | 记忆内部写入；工具和模型不直接调用 |
| `memory.query`                           | scope、实体 / 遭遇 / 当前分段过滤、limit → 有限证据、完整度、memoryEpoch | 陪玩和托管只读                     |
| `memory.preferences` / `applyPreference` | 用户作用域、受校验的显式变更 → 有版本偏好                                | 入口验证用户来源后交记忆保存       |
| `memory.clear` / `setRecording`          | 用户动作、范围、requestId → 新 memoryEpoch / 提交状态                    | 管理入口；禁止模型自行清理         |
| `companion.react`                        | 反应状态、事实事件、时间、偏好、有限记忆 → 新状态、cue                   | 纯策略；I/O、随机数由调用方注入    |
| `companion.chat`                         | requestId、用户原文、conversationId、stamp、取消信号 → 消息事件流        | 只读生成，无工具执行器引用         |
| `companion.prepare`                      | 重要新证据、角色 / 语言、stamp、预算 → 有条件候选                        | 后台低优先级，不产生聊天消息       |
| `control.start/reply/stop/status`        | 受校验操作目标或定向任务命令 → 既有任务事件                              | 托管；复用控制器与输入仲裁         |
| `entry.route`                            | 用户原文或显式卡片、requestId、上下文 → chat / control / clarification   | 唯一路由，不从游戏文本接收新目标   |

陪聊消息事件至少有 `accepted / queued / delta / completed / cancelled / failed`，携带 requestId、messageId、会话 / 角色 / 语言、ContextStamp、递增 seq。非流式适配可直接 completed，不能伪造已流式生成。订阅重连按 seq 补有限窗口，缺口显示中断；不能通过重订阅重发生成或游戏操作。

`requestId` 对路由、聊天、卡片点击和管理动作幂等。同 ID 不同 payload 返回冲突；幂等窗口受数量 / 时间限制，过期请求不得自动重放写操作。控制继续沿用其现有 requestId、taskId 与事件归档契约。

错误契约统一包含 `code / retryable / requestId / currentStamp`；至少区分 NOT_READY、STALE_CONTEXT、STALE_CARD、CONTROL_BUSY、MODEL_BUSY、MODEL_UNAVAILABLE、MODEL_TIMEOUT、CAPABILITY_UNSUPPORTED、PERSISTENCE_DEGRADED、MEMORY_EPOCH_CHANGED、CANCELLED 和 REQUEST_CONFLICT。UI 按错误语义展示，不能一律静默返回或换成普通聊天。

### 3.1 宿主、桥接与访问边界

启动时通过宿主能力版本确认唯一事实 / 业务实例，再建立消息订阅；旧宿主不支持新接口时返回能力不足，不调用旧自动工具循环兜底。Cloud 和本机入口都指向对应 runtimeInstanceId 的权威游戏宿主，不能各起一套托管执行器。

跨现有桥接的消息按精确类型白名单扩展：陪聊 start / cancel / status / events，记忆 query / status / settings / clear，以及受校验偏好变更。T0 将这些 port 映射为版本化消息联合；不通过允许整个 `agent.*` / 任意方法名扩大远程调用。memory.ingest 仅接受经过身份绑定的游戏生产者，不暴露给聊天模型或普通远程管理请求。

所有查询与管理动作检查当前用户存储空间、库游戏和实例访问权，不能仅凭客户端 gameId / 文件路径查询其它数据。远程操作仍经过既有首次 play 授权和超时流程，操作卡片不绕过它；模型密钥、服务目录和原始供应商会话不下发给无权客户端。

## 4. 入口路由、确认与操作授权（F06、F08、F10）

```text
用户提交
  ├─ 停止 / 定向确认 / 已授权卡片：直接校验对应 ID，不调用意图模型
  └─ 普通文本：一次快速语义分类（无游戏工具）
       ├─ 聊天 / 建议 / 回忆 → companion.chat（一次生成）
       ├─ 明确游戏操作 → 校验当前操作槽 → control.start
       └─ 歧义 / 无效分类 / 修改数据 → 澄清或提示能力边界
```

自由文本先分类后聊天最多两次模型调用，不承诺一次完成所有工作；托管目标解析沿用现有流程，不能为省一次调用跳过守卫。分类只消费用户原文和精简当前事实；失败不默认为操作。游戏台词和历史记忆只作资料，不具有授权地位。

操作卡片包含 cardId、允许效果 / 目标、生成时 stamp、适用情境和过期时间。卡片文字由陪玩提出，入口保存结构化意图；点击后重新检查作用域、相关事实和既有工具权限，不能把模型生成的任意 toolName / args 直接执行。卡片过期返回重新确认，不悄悄替换目标。

等待确认的任务保留操作任务槽；只有显式 replyToTaskId / cardId 或经用户明确指向的确认才能恢复。无引用的普通聊天不会被送给 `task.reply`。新的操作请求在已有任务活动时显示冲突；明确替换则先完成旧任务停止流程，确认不再派发输入后才建立新任务。

同一实例的所有入口共享上述校验。对同一游戏的不同运行实例必须分别绑定；同一实例来自侧栏与旅伴的重复请求不能形成两个控制器。

### 4.1 执行形态与生命周期分别绑定

| 字段       | 值与规则                                                                                                                |
| ---------- | ----------------------------------------------------------------------------------------------------------------------- |
| shape      | single / batch / open，继续复用分层执行；batch 仍受起始可见区和地图等硬边界限制                                         |
| lifetime   | goal / until_stopped；未明确持续授权的自然语言目标默认 goal，只有明确持续要求或既有持续托管启动动作才可用 until_stopped |
| completion | goal 在验证目标完成后结束，例如完成当前战斗；until_stopped 在每轮边界内继续观察 / 执行，Stop、接管、失联和失败仍可终止  |

shape=open 不自动等于无限任务，surface=companion 也不自动强制单轮结束。T6 需要用明确 lifetime 替换现有 Host 按入口决定是否继续的分支，但复用动作、边界、单轮预算和完成证据验证；不能为了维持任务而重复一个已完成的有限目标。边界不足先澄清，持续任务不能自行扩大玩家授权范围。

## 5. 三种互斥，不能继续用同一把任务锁（F09）

| 层           | 基线规则                                                                                                 |
| ------------ | -------------------------------------------------------------------------------------------------------- |
| 游戏操作任务 | 每 runtimeInstanceId 最多一个活动托管任务，含 waiting_user / waiting_service；不因切换面板释放任务边界   |
| 陪聊请求     | 每实例最多一个前台陪聊生成；新提交先显示忙碌及取消 / 重试，不静默丢输入；不会启动 Agent 工具循环         |
| 推理资源     | 每 resourceKey 默认一个上游请求；已验证可并发的配置才能增加容量，所有路由 / 聊天 / 托管 / 候选都经此调度 |

`resourceKey` 不等同于 profileId：指向同一推理资源的不同配置必须归入同一限流域；本地同一计算资源按保守共享处理，显式独立资源才分开。CLI 会话、模型上下文和取消信号仍按请求用途 / 会话隔离。

App / local 的资源调度所有者是现有本机服务，所有游戏宿主经它提交模型请求，不能每个插件各自建一把看似全局的锁。Cloud 由浏览器宿主统一调度当前页面的游戏请求；同源多页面以 IndexedDB 事务登记资源租约、请求截止时间和所有者代次，页面结束时尽力释放，接替需等旧请求截止与回收窗口。不能协调的跨浏览器 / 跨设备共享供应商资源仅受各宿主本地限流与上游配额约束，不声称全局独占；此边界不影响游戏输入仍由实例宿主独占。

前台路由和聊天具有交互优先级，托管决策获得公平调度，后台候选可被取消 / 丢弃。默认前台与待执行控制轮流取得资源，二者均不被持续到来的另一方无限饿死；后台仅在没有前台 / 控制请求时开始。紧迫控制使用既有可验证本地处理，不能承诺模型抢占已经发出的请求。

每资源待排队上限 16 项，其中后台最多 1 项；前台入队失败明确返回忙碌。等待计入总超时，不持有按键；拿到模型槽后、执行写动作前重新验证当前事实。用户直接停止不经模型队列。适配器取消后只有确认上游请求已结束 / 连接已回收才释放资源槽；取消失败继续计入占用并显示降级，不能逻辑释放后无界重发。

陪聊取消不能调用 `interruptAll`，停止托管不能清空聊天、记录或候选缓存。控制器仍仅管理操作任务；历史 companion 任务只读展示，升级不恢复旧工具循环。

## 6. 事实、机制和记忆怎样形成建议（F03、F05）

1. 事实适配器生产标准技能结算、击倒和结算事件；记忆模块立即冻结相关证据，异步提交。
2. 再次遇敌按游戏 / 数据版本 / 周目 / 敌人 ID 查询，返回最多 3 条相关经历，包含后续胜利和证据缺口。
3. 构建 `AdviceContext`：当前资源与合法技能、可读机制、历史观察、已尝试结果、情境差异；每项带来源和 known 状态。
4. 确定性危险提醒本地渲染。模型可以给出策略假设，但引用不存在证据、不可用技能或确定化未知机制的候选不得进入自动发言缓存。
5. 玩家明确要求执行后，托管重新观察、检查可用性与目标，不直接执行旧建议。实际结果回到同一事实源，形成新经历。

防御尝试用 actionId / resultId、遭遇和效果条件关联，不仅按时间接近猜因果。没有可靠机制时可说「可以试试防御」，不能说「缴械必然能封住这招」。一次胜利 / 减伤不形成跨难度、阶段和装备的必胜规则。

## 7. 快速反应、候选与发言调度（F02、F07）

```text
事实事件 → react → cue
                  ├─ 危急：有效缓存或本地变体 → 检查后立即展示
                  └─ 普通：有效候选或本地变体 → 合并 / 限频 → 展示

重要新证据 / 结算 / 情境变化 → 闲时 prepare → 校验 → 有界候选缓存
```

`Cue` 必须携带 cueId、eventId、scope / epoch、事实依赖、priority、expiresAt 和 evidenceRefs。发送前再次校验；记忆检索和落盘都不能阻塞危急反应。相关记忆尚未加载时先不声称记得，不能为同一事件迟到补发。

候选键使用角色、语言、游戏版本、相关实体、记忆版本与情境标签；场景 / 阶段不同或用户偏好变化后重新校验。模型只输出受约束的文案槽位 / 证据引用，不允许任意增加数值和机制。数值、名称及机制断言由已验证槽位渲染；自由措辞不作为事实提取器。候选是可丢失缓存，不是长期事实。

候选优先填充普通开场、成功 / 失败回应、再次遭遇等适用语境，不枚举所有未来事件。一次准备最多生成 4 条；同一证据水位和情境不重复请求。已经显示本地反应后不再替换、补发同事件的模型改写。主动聊天独立于此自动发言去重。

展示调度按「玩家确认 / 任务结果 → 危急反应 → 主动聊天 → 普通自动反应」。这是消息排序而非延迟渲染：聊天 delta 和固定任务卡片各自更新，不能把整段聊天锁成阻塞提示的长队列。队列满时合并同类危险、丢旧普通 cue，并保留最严重当前事实；不无限刷屏。

## 8. 聊天、偏好和模型适配（F06、F12、F13）

聊天输入包含用户原文、有限近期对话、当前事实、相关记忆、偏好和各自版本。陪玩编排层负责一次生成，模型不拿游戏写工具。记忆不足时回答未知或澄清，不启动无限查询循环。具体经历问题可做一次实体 / 遭遇消歧，仍不明确就交还用户。

涉及经历引用、技能建议或操作卡片的输出用带 evidenceRefs / entityRefs / known 条件的结构块，收齐并验证后才渲染；纯聊天文本可以增量显示。不能把原始模型输出的数字、技能或动作参数直接展示为已验证事实。结构块无效时显示信息不足或退回确定性证据摘要，不自动二次补判；非结构化供应商按整段解析降级。自由措辞不能承诺零幻觉，验收同时检查结构验证与真实对话中的无依据断言。

供应商适配暴露 streaming、thinkingControl、structuredOutput、cancellation 和 resourceKey 等能力。复用现有凭据 / 代理；Ollama、HTTP API 与 CLI 按实际能力实现。托管可保留原整段补全接口，陪玩新增增量接口；不能让 `completeAgentModel` 丢弃 delta 后仍声称界面已流式。thinking 只在供应商支持时关闭，非支持配置需要换快速模型或按原样降级。

陪玩与托管分别选择 profile / model，但可指向同一配置，不要求小模型。CLI 整段返回时显示等待与整段完成；完整流式验收至少覆盖一种现有可实现的供应商路径。模型常驻 / 预热仅按适配能力与设置，不因每次游戏事件启动新 CLI 会话。

近期对话属于陪玩会话，有界维护，不自动全部持久化为长期记忆。显式偏好由入口验证用户来源后写记忆；优先级为当前明确设置 > 当前游戏偏好 > 用户默认。模型只能提出经过字段白名单验证的变更，不把游戏台词、模型总结或推测情绪写为用户偏好。

角色 / 语言 / 新对话使用新的 conversation / generation 身份；供应商会话键包含用途、角色、语言和对话身份。已有托管任务的目标与权限不因角色变化改变，任务结果只展示一次。

## 9. 生命周期与取消矩阵（F04、F10–F14）

| 事件                      | 当前事实 / 记忆                                            | 陪玩与候选                                                                             | 托管                                                                         |
| ------------------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 面板关闭                  | 采集继续                                                   | 取消该入口前台生成，保留已展示部分并标中断；无可见消费者时取消后台候选，不排队过期 cue | 继续，等待确认状态仍可重新展示                                               |
| 停止回复                  | 不变                                                       | 取消指定 requestId                                                                     | 不变                                                                         |
| 停止托管 / 游戏内手动接管 | 新事实仍记录                                               | 不受连带取消，旧任务自动评论作废                                                       | 停后续写入，已派发动作独立短回读，未知则如实标记                             |
| 读档 begin                | contextEpoch 递增，冻结 from，暂停派发依赖旧现场的观察结论 | 取消旧现场生成、卡片与 cue                                                             | 外部加载中断；任务自发加载在受控动作内等待结果                               |
| 读档 commit               | 新 segment、清临时战斗上下文、从 to 建立基线               | 新上下文重新候选，不重放旧提示                                                         | 仅自发加载按原边界验证 / 完成；不把旧按键计划带入新分段                      |
| 读档 rollback             | 原 segment、新 epoch、重新观察或标未知                     | 不恢复旧异步结果                                                                       | 外部加载任务仍中断；自发加载按失败策略停止或重新观察                         |
| 切场景 / 遭遇结束         | 更新 factsRevision，不删除经历                             | 校验事实依赖，取消已不适用 cue / 建议；普通闲聊可继续                                  | 沿用任务边界检查 / 重规划                                                    |
| 暂停 / 恢复               | 暂停不推断状态推进；恢复观察                               | 取消时效性 cue；玩家聊天可用，事实标暂停                                               | 不派发新动作，恢复后重新验证；总预算按既有托管规则                           |
| 切角色 / 语言 / 模型      | 游戏经历不变，偏好按作用域                                 | 取消旧请求、缓存与供应商会话；已展示内容保留原身份                                     | 不改变原目标；模型配置变化只影响之后启动的托管                               |
| 清理记忆 / 关闭记录       | memoryEpoch 递增，作废旧写队列；按清理范围操作             | 丢旧检索 / 缓存；涉及已删除证据的生成取消                                              | 仍需真实观察；后续决策不再引用被删证据，不取消已派发动作                     |
| 游戏断连 / 退出           | 尽力刷新，保留已提交记录                                   | 中断生成 / 订阅，不复活旧结果                                                          | 中断，不自动恢复执行                                                         |
| 仅本机服务短暂退出        | 采集保留有界内存，恢复后按 epoch 提交                      | 当前请求失败，候选回退，用户可重试                                                     | 仅依赖该服务的请求进入既有 waiting_service，最多 60s；恢复先观察，不重放写入 |

## 10. 默认预算与降级

以下为实施默认值，可根据验收调整；它们不是实测性能，也不能通过去掉上限来掩盖问题。记忆自身预算统一见记忆技术文档，避免维护两套数字。

| 项目               | 初始预算 / 行为                                                                                                               |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| 本地关键提示       | 可见面板 p95 ≤200ms；分别计采集、策略、调度、展示                                                                             |
| 普通短聊天体验基准 | 至少一组指定热模型 / 设备 / 网络下，从发送起首段 p95 ≤2s、完整回复 p95 ≤8s，含路由 / 排队；冷启动、非流式与证据块整体验证另报 |
| cue 队列           | 每实例最多 16 项 / 16 KiB；危险默认有效 3s，普通结算 10s，再遇提醒 15s 且必须仍在同一遭遇                                     |
| 冷却               | 普通同类 12s、普通总间隔 4s；危险绕过普通限制，同目标 2s 内合并，状态恶化可更新当前一条提示                                   |
| 候选缓存           | 每实例 32 条 / 64 KiB，10min 到期；实体 / 情境 / 证据条件同时有效才可用                                                       |
| 后台生成           | 每实例同时 1 项、每次最多 4 条、每遭遇最多 2 次、每小时最多 32 次；无新证据不启动，队列满直接跳过                             |
| 输入上下文         | 总计最多 12000 字符：近期对话 6000、当前事实 / 机制 4000、相关记忆 2000；超限优先保留当前问题与直接证据                       |
| 生成输出           | 分类 128 tokens、聊天 256 tokens、候选 384 tokens；不扩为多轮工具循环                                                         |
| 请求时限           | 分类总计 5s；聊天首段等待 5s、总计 15s；候选总计 10s，含排队；托管沿用既有预算                                                |
| 陪聊历史           | 每会话最多 20 条且最多 32 KiB；生成时仍按上下文总预算裁剪                                                                     |
| 可恢复消息窗口     | 每实例最多 128 条事件 / 256 KiB；超出显示缺口，不影响已提交记忆                                                               |

首段超时后结束该生成并显示可重试状态，不能让不可见任务持续占用资源；非流式模型只测完整回复 / 总超时，不伪造首字指标。后台失败不自动无限重试；主动聊天的重试由用户触发新请求，已完成请求不重复计费式重放。

存储失败保留有界内存、显示一次降级；模型失败不关闭本地反应；能力不足不产出无依据建议。任务宿主退出后未完成操作与生成均中断，重启只恢复查询和明确完成的记录；仅本机服务短暂退出按上表处理，不能误杀仍在游戏宿主中的任务。

## 12. 迁移、兼容与变更规则

升级后旧角色 / 语言 / 面板设置保留，已配置模型可继承为陪玩默认模型；自然增强可在设置关闭，后台用量按预算展示。旧自动 companion 任务不恢复执行，旧任务日志只读保留；旧文本历史没有行动字段时不能回填为确定死亡证据。

新入口只接收新协议后才关闭旧自动循环，同一运行实例以宿主能力版本协商选择一条路径，不能同时启动两套反应 / 记忆。旧插件仅保留原能力并显示升级缺口；不能静默把新功能调用降级到可操作工具循环。新的稳定身份、偏好、存档关联和记忆 schema 有显式版本 / 迁移；具体恢复详见记忆设计。

本设计不重写托管算法，不改变其它编辑入口的既有权限，也不把历史文档的缺口表重新当成待办。托管专项「单活动任务」在此解释为单操作任务；仅本次独立陪聊通道不受它阻塞，其它旧 Agent 任务是否并发不在本次扩权范围。

实施中发现适配不足时先缩小能力表并补 T1，不通过 prompt 造事实。只有调整顶层模块、身份 / 事件所有权、权限、并发或最终验收范围才需要先修订本基线及受影响任务；预算和语料可按测量优化，但记录原因，不能以分任务为由删除最终能力。

## 13. 验证计划

纯领域测试覆盖事件去重、顺序 / 缺口、冷却与槽位、候选过期、偏好优先级和所有权；存储测试覆盖事务失败、多窗口、裁剪、删除与迁移。供应商契约测试覆盖真实 delta、整段降级、取消未结束、配额 / 排队与模型能力差异。

集成测试按 F01–F14 验证，至少包括：聊天过程中读档 / 切角色、删除时还有写队列和模型返回、托管等待确认时闲聊、两个入口同时操作、同资源持续请求下的公平性、关闭面板但托管 / 采集继续、外部加载与任务自发加载，以及加载失败回滚。

真实运行在指定 App / local 与 Cloud 环境分别验证 MV / MZ 标准路径；报告支持版本和插件组合，不能从 MV 结果推断所有 MZ / 自定义系统正确。性能报告记录设备、冷 / 热模型、事件负载、路由 / 排队 / 首字 / 完整回复和故障降级；无需依赖模型判断固定事实采集是否成功。
