# translate

Bing / Google / Ollama 合并翻译（`services/translate`）。

## 结构

```
cli.ts           # pnpm translate
import-cache.ts  # 作内 ndjson → 共享 sqlite
paths.ts
shared-cache.ts  # SQLite
cache-api.ts     # 给 Next API 的查询/统计
index.ts         # 对外导出
lib/             # 管线实现
```

## 运行

```bash
pnpm translate -- --root /path/to/www
pnpm translate:import-cache -- --root /path/to/www
```

内容根文件见 `lib/game/content-files.ts`。翻译库分为本游戏的 `chaya/translate/seed.json` 与 `chaya/translate/cache.ndjson`，以及跨游戏复用的 `data/translate-cache/shared.sqlite`（Drizzle ORM + `node:sqlite`）。`cache` 是兼容既有磁盘格式的路径名，不代表译文可随时丢弃。游戏中会合并 seed 里已有的译文与 NDJSON，后写的 NDJSON 译文覆盖同名 seed 译文；服务端先查本作，再查共享库。

## 游玩翻译模式

在控制台「翻译 → 执行」的「游玩翻译模式」中选择并保存，每个游戏独立保存到 `chaya/config/translation-play.json`：

- **预翻译后游玩**（默认）：游戏内只读取已有译文，缺失内容显示原文，不等待翻译服务。可先抽取、批量翻译再进入游戏。
- **实时翻译**：标准 RPG Maker MV/MZ 对话与选项照常显示原文，已有译文立即显示为额外字幕；未命中时按左侧启用的平台及顺序请求翻译，返回后只在当前对话显示中文字幕。对话和选项不等待模型。无须 mtools；实时与 Seed 补译共用平台开关及顺序。菜单、自定义插件窗口和直接通过 Canvas 绘制的文字会使用已有译文，未命中的非对话文字仍显示原文。

需安装并启用 ChayaTrans 插件。实时翻译不需要启动 Chaya 服务；启用 Ollama 时需保持 Ollama 运行，启用 Google/Bing 时需要网络连接。局内面板直接调用插件；Edge 与 App 控制台通过同一条游戏连接调用插件。翻译设置、抽取、后台补译、导入和本作翻译库管理均在游戏进程执行。更改模式后，运行中的插件会在约一秒内读取设置，下一段对话生效；升级插件后建议重新启动游戏。

模型栏填写 Ollama 已安装的模型名；插件留空使用 `gemma4:e2b-it-q4_K_M`，直连 `http://127.0.0.1:11434`。实时翻译、短句测速和批量补译都按游戏保存的 Ollama / Bing / Google 开关及顺序运行。CLI / 服务端独立调用仍支持 `OLLAMA_MODEL`、`OLLAMA_HOST`。

「短句测速」使用固定的 50 字左右日文，不写入翻译库；结果包含模型加载、排队、生成时间。首次冷启动通常更慢，可连续测两次比较。2000 字用时 20 秒不能保证 100 字只需 1 秒，实际速度还受硬件、模型与选项数量影响。

模型超时默认 8 秒，可设置 2–30 秒。原文从一开始就能阅读和跳过；关闭或更换对话立即取消旧请求并隐藏旧字幕，迟到译文不会覆盖下一句。成功译文立即写入本游戏翻译库，下次命中立即显示字幕。未命中时可向配置的 Chaya 地址查询共享翻译库，查询限时 500 ms；服务离线或无共享库存储时回退本地，并冷却一分钟。远程命中也写入本作库。当前不自动上传译文至远程共享库；已有译文不会自动重译，质量不满意时可在本作翻译库页重译。

当前对话取消插件内正在进行的后台请求，并优先进入推理队列；被跳过的后台条目保留为待译，稍后继续可重试。关闭控制台不会中断游戏内补译，退出游戏或插件热更新会停止任务，重新打开后可从已写入的译文继续。对白逐行查库，只把未命中的行发给模型；对白先翻译并显示、入库，然后再处理选项。每次只保留当前对话的请求，切段会取消上一段。没有 debounce：快速跳过仍可能产生已发送的请求；HTTP 取消不保证 Ollama 已开始的计算立刻停下。为限制大段成本，合计超过 360 字或超过 7 个选项时不发起实时推理，已有译文字幕仍可显示。

这里的“命中”指当前原文能否直接复用已有译文，与模型输出质量是两项指标。先复用整句、规范化键、按行和控制码/数字模板；不按任意子串或编辑距离猜测，以免错误台词进入游戏和选项脚本。Google/Bing 等低成本译文可作为后续补全来源，但自动校订需要另行记录译文来源与人工修改状态，避免后台结果覆盖人工译文；当前没有自动质量修正任务。
