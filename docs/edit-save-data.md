## 1. 背景

「修改」新增二级分类 **数据**：把当前游戏进度（存档里保存的那份运行时对象）按层级展示成**字段列表**，可浏览、搜索、逐字段修改、增删子项、锁定。用于现有预设能力覆盖不到的字段，例如计时器、画面色调、某个角色的内部属性、插件存在存档里的自定义数据。

参考 MTool 的「数据修改」，但不照搬它的做法：

| MTool 的做法                                                   | 问题                                                                                       | 本方案                                                       |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------ |
| 「更新数据」把整个存档对象 `JsonEx.stringify` 成一份 JSON 下发 | 大型游戏数 MB（`$gameMap` 带全部事件和解释器），每次刷新游戏卡顿一下，网页端解析和渲染也卡 | 只取当前所在的那一层，按页取；不做整体序列化                 |
| 以 JSON 文本 / 树展示和编辑                                    | 嵌套深、看不清；在原地改值，值一刷新输入就被打断                                           | 层级列表逐层进入；「当前值」只读实时刷新，「修改为」单独输入 |
| 数据是快照，要手动「更新数据」才看到最新值                     | 改完不知道生效没有；想看实时值只能反复全量刷新                                             | 只订阅屏幕上可见的字段，每秒比较，变了才推送差异             |
| 「应用至游戏」整体 `JsonEx.parse` + `extractSaveContents` 写回 | 写回期间游戏改过的值全部被旧快照覆盖；改错一个字段可能整局坏掉                             | 只写用户填了新值的字段，写后读回确认，可撤销                 |
| 原始键名（`_data`、`_paramPlus`），开关 / 变量只有下标         | 看不懂改的是什么                                                                           | 已知结构标注名称（开关名、变量名、角色名、物品名等）         |

## 2. 性能方案

| 方案                               | 游戏侧每次开销                          | 传输量                     | 网页端开销               | 实时性         | 结论                     |
| ---------------------------------- | --------------------------------------- | -------------------------- | ------------------------ | -------------- | ------------------------ |
| A. 全量 JSON，手动刷新（MTool）    | 序列化整个存档对象，O(全部数据)         | 数 MB / 次                 | 解析 + 构建整份数据      | 无             | 否                       |
| B. 全量 JSON，定时刷新 + 网页 diff | 同 A，且每秒一次                        | 数 MB / 秒，需分片         | 每秒解析与比较整份数据   | 有，但代价最高 | 否                       |
| C. 全量序列化，游戏侧 diff 后推送  | 每秒遍历整个对象图                      | 只有差异                   | 小                       | 有             | 否：遍历成本仍随总量增长 |
| **D. 按层懒加载 + 可见字段订阅**   | 只读当前层、只比较可见字段，O(可见行数) | 每次一层（≤ 200 项）+ 差异 | 只渲染可见行（虚拟滚动） | 有，1 秒内     | **采用**                 |

方案 D 的成本只跟「屏幕上显示了多少行」有关，跟存档总大小无关。不管游戏数据是 100 KB 还是 20 MB，单次读取和每秒比较的开销都基本固定。

### 2.1 读取：一次一层

- 每个字段用**路径**表示：从根开始的键数组，如 `['party', '_items', '12']`。用数组而不是点号字符串，因为键名里可能有点号或空格。
- 进入一层时请求这一层的字段：键、名称标注、类型、类名、子项数、当前值（基本类型）或摘要（对象 / 数组）。不取更深一层。
- 字段多时分页：每页 200 项，滚动到底再取下一页。开关 / 变量这类上千项的数组也不会一次传完。
- 当前值截断：字符串显示前 120 字；对象显示类名和子项数（如 `Game_Actor · 48 项`），数组显示长度。完整长字符串在点开修改时单独取，上限 64 KiB。
- 每层响应经现有 `link.chunk` 分片发送（CJK 文本 200 项可能超过 DataChannel 单条上限；小响应只有一片，无额外开销）。
- 游戏侧直接按路径在运行时对象上取值，不复制、不序列化。

### 2.2 实时：只订阅可见字段

- 网页端只渲染可见行（虚拟滚动），把**当前可见的字段路径**、**当前所在层**、**常用栏里的字段**报给游戏，合计上限 300 条；滚动、进入别的层、增删常用后更新订阅（防抖 200 ms）。
- 游戏侧每秒对订阅列表做一次比较：基本类型比较值，对象 / 数组比较子项数、键签名和对象身份（见 §2.3）。
- 只推送变化的字段，没有变化就不发消息。推送只更新「当前值」列，**不碰「修改为」输入框**（见 §4.3）。
- 页面不可见（切走分类、浏览器标签隐藏、局内浮层关闭）时取消订阅，游戏侧零开销。
- 比较在游戏的定时器里做，单次耗时预算 2 ms；超出时下一轮从中断处继续，保证不掉帧。

### 2.3 不在屏幕上的数据如何保持最新

游戏只主动推送订阅中的字段；其余数据不推送，但保证「一出现在屏幕上就是最新的」：

- **新进入可见区的行**：订阅生效时游戏立即回一次这些字段的当前值，不等下一秒。滚回之前看过的位置，显示的也是当前值。
- **离开的层**：离开即丢弃该层缓存，再进入重新取。
- **内容变化但子项数不变**（如数组元素被替换成另一个对象）：除子项数外，还比较「键签名」（键名列表的哈希，子项超过 1000 个时只比数量）和子对象身份（游戏侧给每个对象分配编号，同一路径指向了另一个对象即视为已替换）。替换时网页端重取该层。
- **整体替换**：读档、开始新游戏会整体换掉 `$gameParty`、`$gameMap` 等对象；场所移动会换掉地图上的全部事件对象。游戏侧检测到根对象身份变化时递增「代数」并推送，网页端清空全部缓存并重取当前层；当前路径已不存在时退回到最近的存在的上层。
- **手动刷新**：页头刷新按钮重取当前层，作为兜底。

## 3. 数据范围

根层与存档内容一致（`DataManager.makeSaveContents()` 返回的就是这些运行时对象的引用，取根不产生复制），另加设置：

| 根字段         | 运行时对象          | 名称标注                                 |
| -------------- | ------------------- | ---------------------------------------- |
| `system`       | `$gameSystem`       | —                                        |
| `screen`       | `$gameScreen`       | 图片编号                                 |
| `timer`        | `$gameTimer`        | —                                        |
| `switches`     | `$gameSwitches`     | 开关名                                   |
| `variables`    | `$gameVariables`    | 变量名                                   |
| `selfSwitches` | `$gameSelfSwitches` | 地图名 · 事件名 · 字母                   |
| `actors`       | `$gameActors`       | 角色名                                   |
| `party`        | `$gameParty`        | 物品 / 武器 / 防具名，队伍成员名         |
| `map`          | `$gameMap`          | 事件名（含事件，数据量最大）             |
| `player`       | `$gamePlayer`       | —                                        |
| `config`       | `ConfigManager`     | 设置项名称（音量、一直奔跑、记住指令等） |

- 名称经翻译库查表显示译名，原始键名以淡色并列。
- 插件追加到这些对象上的字段一并显示（这是这一页的主要价值之一）。
- 函数、getter 不显示（`config` 例外，见下）；类名来自构造函数名（MV/MZ 的 `Game_*` 类）。
- 开关 / 变量的 `_data` 只存设过值的下标，长度常小于数据库里的数量。这两个根字段按 `System.json` 的开关 / 变量总数列出（未设过的显示为空，可直接填值）。
- `config` 的音量等字段在引擎里是带设值方法的属性，按 `ConfigManager.makeData()` 的键列出，写入经引擎的设值方法并保存设置文件。
- 循环引用：遇到与上层相同的对象时显示「↻ 引用上层」，不可进入。
- `Map`、`Set`、类型化数组等非普通对象只显示类名，不可进入、不可修改（正常存档里不会出现）。
- 不包含静态数据库（`$dataActors` 等）：它们不在存档里，改了也不会保存，且「物品」「角色」等页已覆盖。

## 4. 页面

### 4.1 布局

- 顶部第一行：路径面包屑（点击跳回任一上层）、复制路径（格式为可在游戏控制台直接使用的表达式，如 `$gameParty._items[12]`）、搜索框（含范围「全部 / 名称 / 值」）、刷新。
- 当前层允许增删时，列表上方显示「添加一项」（数组，加到末尾）或「添加字段」（对象）。
- 顶部第二行（有内容时显示）：「待应用 N 项 · 全部应用 · 清空」、「撤销：<上一步摘要>」、锁定数量（点击列出全部锁定）。
- 常用栏：常用与钉住的字段（§4.6）。
- 主体：当前层的字段列表，一行一个字段：

  | 名称                                         | 当前值                          | 修改为                                        | 操作                         |
  | -------------------------------------------- | ------------------------------- | --------------------------------------------- | ---------------------------- |
  | 已知结构显示名称，原始键名淡色；类型用小图标 | 只读，实时刷新；变化时短暂高亮  | 输入框 / 开关，默认空；待应用、已失效时加标记 | 填入当前值、应用、锁定、更多 |
  | 对象 / 数组行：类名或长度                    | 摘要（如 `Game_Actor · 48 项`） | —                                             | 进入 ›、更多                 |

- 「更多」菜单：复制路径、钉到常用；当前层允许增删时另有「在此前插入」「复制此项」（数组）、「删除此项 / 此字段」（§4.4）。
- 本次会话写入过的字段在行首加标记；锁定中的字段显示锁图标。
- 固定行高 + 虚拟滚动，几千行也不卡。
- 路径进入 URL（`/cheat/data/party/_items/12`），刷新页面、前进后退、分享链接都回到同一层。
- 局内浮层（816 宽）：同一套列表，「名称」在上、「当前值 → 修改为」在下的两行布局，操作收为图标。

### 4.2 空态与可用条件

| 情况                         | 显示                                                   |
| ---------------------------- | ------------------------------------------------------ |
| 游戏未连接                   | 「连接游戏后可用」                                     |
| 标题画面 / 未读档 / 回到标题 | 「进入游戏后可用」（回到标题时清空撤销与锁定，同读档） |
| 当前层为空                   | 「没有字段」                                           |
| 当前路径已不存在（读档后等） | 自动退回最近的存在的上层，并提示一次                   |
| 读取失败                     | 错误原因 + 重试                                        |

### 4.3 修改：当前值与新值分开

- 每行两列：**当前值**（只读，实时刷新）和 **修改为**（输入框，默认空）。
- 输入框只由用户改动。当前值每秒怎么变都不影响输入框里的内容、光标和焦点；空输入框也不会被自动填入当前值。
- 想基于当前值改时，点「填入当前值」再改。
- 填了新值的行标记为「待应用」；回车或点该行「应用」只写这一行。
- 页头「全部应用」一次写入所有待应用行（跨层也算）：先整体校验（类型、只读、失效），有不通过的行时整批不发并标出问题行；校验通过后逐行写入，个别行失败不回滚其他行，结果按行显示。需确认的字段（§4.8）在同一个确认框里列出。
- 「清空」放弃全部草稿；输入框里按 Esc 放弃这一行。
- 草稿按路径保存在当前页面会话里：离开这一层再回来，草稿还在。草稿同时记住所属对象的身份；同一路径换成了另一个对象（场所移动、读档、数组元素位移），该草稿标为「已失效」，不能应用，只能删除或重新填写。
- 写入以用户填的值为准，不校验「填写时的当前值」：当前值持续变化的字段（计时器、步数、战斗中的 HP）要求一致就永远改不进去；用户提交时能看到实时当前值，自行判断。
- 类型：
  - 数字只接受有限数字（拒绝 `NaN` / `Infinity`），布尔用开关，字符串用文本框（长文本展开为多行）。
  - 有值的字段保持原类型；不能把对象换成基本类型，也不能反过来。
  - 空值（`null` / `undefined` / 未设过的开关变量）：已知结构按结构定（开关 → 布尔，变量 → 数字或文本、默认数字，物品数量 → 数字）；未知字段由用户在输入框旁选择类型（数字 / 文本 / 布尔 / 空）。
  - 「设为空」（`null`）：类型固定的已知结构（开关、变量、独立开关、物品数量、设置）不提供；其他字段都可以，需确认。
- 写入后游戏立即读回该字段，网页端用读回值更新当前值列：
  - 读回值等于新值：成功，输入框清空。
  - 读回值不等于新值（被游戏或插件立刻改掉，例如被上限截断）：提示「已写入，但游戏改成了 X」，输入框清空。
  - 写入失败：保留输入并在行内显示原因。
- 有引擎设值方法的已知结构经设值方法写入，保持游戏内部一致，读回值可能与填写值不同（按上面的读回规则提示）：
  - 开关、变量、独立开关：经引擎的设值方法（变量的数字会被取整；独立开关设为关闭时引擎会删除该项），并刷新地图事件出现条件。
  - 物品 / 武器 / 防具数量：按「当前数量到目标数量的差值」增减（受持有上限截断；数量为 0 时该项从列表消失），并刷新地图事件出现条件。
  - 设置：经引擎设值方法并保存设置文件。
- 其他字段直接写入，写后按所属对象补调刷新：角色字段重算能力值、截断 HP / MP；队伍成员变化刷新玩家行走图；其余对象写入即生效。

### 4.4 结构修改：增删子项

- **数组**：
  - 「添加一项」（列表上方，加到末尾）、「在此前插入」（行菜单）：新项为基本类型，同 §4.3 选类型填值。
  - 「复制此项」（行菜单）：深拷贝该元素（保留其类，适合事件、图片这类对象数组），插入到它后面。
  - 「删除此项」（行菜单）：删除后后续元素前移。
  - 插入、复制、删除都会让后续元素的路径变化：这些路径下的草稿标为已失效。游戏自己移动基本类型数组的元素（不经本页）无法察觉，这类数组的草稿以写入时的路径为准。
- **对象**：
  - 「添加字段」（列表上方）：键名 + 基本类型值；键名不能与已有字段重复，不能是保留名（§5）。
  - 「删除此字段」（行菜单，仅基本类型字段；对象 / 数组字段不可删，避免游戏读不到内部结构而报错）。
  - 独立开关（`selfSwitches._data`）的「添加」改为填写地图编号、事件编号、字母（A–D）与开关值，键名由此生成。
- 所有删除、复制对象都要确认，确认框写明影响（如「删除后第 4 项之后的 12 项前移」）。
- 只读字段所在的对象（§4.8）不能增删子项。
- 开关 / 变量根层不提供增删（按数据库总数固定列出）；物品类（`party._items` 等）的「添加」改为选择物品并填数量，「删除」等于数量清零。

### 4.5 锁定

- 任意基本类型字段可锁定：游戏每 0.2 秒把它写回锁定值，用于 HP、计时器这类会被游戏持续改动的字段。与「运行」「物品」页现有锁定的频率一致。
- 有草稿时点「锁定」：先按草稿写入（与普通应用相同，进撤销栈），再锁定为该值；无草稿时锁定为当前值。
- 锁定中的字段再应用新值：写入并把锁定值更新为新值。
- 不能锁定为「空」；对象 / 数组不能锁定。
- 锁定与所属对象绑定：对象被替换（读档、场所移动）时该锁定自动解除并提示。
- 锁定只在本次游戏进程内有效，不写进存档；页头显示锁定数量，点开可逐个解除或全部解除。
- 已在「运行」「物品」「角色」页锁定的同一字段（如金钱）在这里显示为锁定中并提示去原页面管理，不重复锁定。

### 4.6 常用与钉住

- 常用栏预置：金钱、步数、计时器、玩家坐标、遇敌步数、存档次数。（游戏时间由引擎帧计数器维护，不在存档对象里实时更新，不列入。）
- 任意字段可从「更多」钉到常用栏，可拖动排序、移除，上限 30 项。钉住项保存在游戏一侧（按游戏区分），网页与局内浮层看到的是同一份。
- 常用栏里的字段同样有当前值和修改为两列，参与实时订阅，可以不进入层级直接改、锁定。
- 钉住的路径在当前进度里不存在时显示为「不可用」，不报错。

### 4.7 搜索

- 按名称（含名称标注与原始键名）或值搜索，在游戏侧进行，范围为当前层及其下层（在根层即整个进度）。
- 范围选择「全部 / 名称 / 值」，默认全部。名称与文本值按包含匹配、不区分大小写；关键词是数字时，数字值按相等匹配（搜 12 不会命中 112）；关键词为 `true` / `false` 时匹配布尔值。
- 遍历有预算：单次最多 5 万个字段，分片执行不卡帧，超出时提示「结果不完整，请缩小范围」；最多 200 条结果；输入新关键词或离开页面时取消上一次搜索。
- 结果是一个扁平列表：完整路径（含名称标注）、当前值、修改为，可直接在结果里改、锁定；点路径跳到所在层并高亮该行。
- 结果列表同样参与实时订阅（只订阅可见结果）。

### 4.8 只读与确认

| 规则     | 字段                                                                                      | 原因                                       |
| -------- | ----------------------------------------------------------------------------------------- | ------------------------------------------ |
| 只读     | 任意层级下名为 `_interpreter` 的对象及其下全部字段                                        | 事件解释器内部状态，改了极易卡死           |
| 只读     | 地图事件的 `_eventId`、`_mapId`                                                           | 事件身份，改了会错位                       |
| 修改确认 | `map._mapId`、`player._x` / `_y` / `_realX` / `_realY`、`player._newMapId` 等场所移动字段 | 建议用地图页传送；直接改可能落在墙里或错图 |
| 修改确认 | `system._saveCount`、`system._versionId`、`system._framesOnSave`                          | 影响存档与读档校验                         |
| 修改确认 | 设为「空」、删除、复制对象                                                                | 不可直观还原                               |

- 页面顶部常驻一行提示：「直接修改内部数据，改错可能导致存档异常。建议先存档。」

### 4.9 撤销

- 游戏侧在写入瞬间记录「路径 + 写入前的值 + 新值」（结构修改记录被删除 / 插入的项），保留最近 50 步；页头显示「撤销：<上一步摘要>」。「全部应用」算一步，撤销时整批还原。
- 撤销前检查当前值仍等于当时写入的新值，以及所属对象未被替换：
  - 都满足：直接还原。
  - 值已被游戏改动：列出冲突字段与当前值，确认「仍要还原？」后强制还原。
  - 对象已被替换（读档、场所移动）：该步不可撤销，从栈中移除并提示。
  - 结构修改的步骤（插入、复制、删除、增删字段）要求数组 / 对象在那之后没有被别的操作改动过位置（被插入的那一项仍在原位），否则不可撤销，不提供强制还原。
- 网页与局内浮层同时打开时共用同一个撤销栈；摘要里写明上一步改了什么（首个字段的名称与新旧值，以及共几项），按当前界面语言显示，避免撤销了另一端的修改。
- 撤销栈只在游戏进程内存里，读档、回标题后清空。锁定的写回不进撤销栈。

## 5. 安全

这是一条新的任意字段写入通道，而 Edge 的 DataChannel 信令无鉴权（见 [capabilities.md](./capabilities.md)）。以下限制在游戏侧强制执行，网页端的校验只作体验：

- 路径只能从 §3 的根字段出发；任一段为 `__proto__`、`constructor`、`prototype` 时拒绝，新增字段的键名同样禁止这些保留名。
- 只读写对象自身的普通数据属性：不写 getter / setter（`config` 白名单除外）、不写原型链上的属性。
- 新值只能是基本类型或「复制同级元素」，不接收任意对象、不执行任何代码。
- 只读字段（§4.8）在游戏侧同样拒绝；需确认的字段要求指令带确认标记，没有标记时游戏侧拒绝。
- 路径深度上限 32 段，单段长度上限 256 字符；一次「全部应用」最多 200 项。

## 6. 可用条件与 Agent

- 需要游戏在线：local / edge 网页经 link 访问，局内浮层直接访问；不提供离线读存档文件。
- 必须在读档或开始新游戏之后（`$gameParty` 存在）。
- **Agent 不开放**。按 [capabilities.md](./capabilities.md) 第 4 条，Agent 只能调「修改」页的预设能力，不能任意改内部对象；这一页本质是任意字段读写，不进 MCP 工具，也不进 WebMCP 页面工具。

## 7. 不做

- JSON 文本 / 树形展示与编辑。
- 整体导出 / 导入整个存档（MTool 的「更新数据」「应用至游戏」）：即方案 A，性能和覆盖问题见 §2。
- 离线编辑存档文件（`.rpgsave` / `.rmmzsave`）：需求不同（不依赖游戏运行），以后单独评估。
- 修改静态数据库（`$dataXXX`）。

## 8. 验收（修改闭环）

1. 进入「数据」→ 根层 11 个字段 → 逐层进入 `party` → `_gold`，当前值随游戏变化实时刷新。
2. 在「修改为」填 99999 并回车，期间当前值每秒变化不影响输入；回执后当前值显示 99999（或「已写入，但游戏改成了 X」）。
3. 跨层填 3 个草稿（其中 1 个在 `map._events` 下）→ 场所移动 →「全部应用」→ 失效的那个被拦下、整批不发；删除它后另外 2 个写入成功；「撤销」整批还原。
4. 填草稿后场所移动 → `map._events` 下的草稿变为「已失效」；读档 → 当前路径不存在时退回上层并提示，撤销栈清空、锁定解除。
5. 锁定角色 HP → 战斗中 HP 保持不变；解除后恢复正常。
6. 数组复制一项、删除一项、对象添加 / 删除字段均需确认，且可撤销。
7. 搜索变量名 → 结果中直接修改 → 当前值更新。
8. 开关 #500（从未设过）可直接设为开启，地图事件出现条件立即生效。
9. 构造含 `__proto__` 的路径、未带确认标记改 `map._mapId`、写只读字段，游戏侧均拒绝。
10. 打开大型游戏（数百张地图、数千开关）停留在 `map._events` 层，游戏帧率无可感知下降；切走页面后游戏侧不再有比较开销。
