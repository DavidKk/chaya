# Windows 本地离线翻译引擎接入需求

- 日期：2026-10-19
- 状态：需求草案待评审
- 适用范围：Windows 版 Chaya（Windows 10 / Windows 11 / Copilot+ PC）
- 技术设计：[Windows 本地离线翻译接入技术设计](technical/windows-native-translation.md)

## 1. 背景与目标

继 macOS 原生 Apple Translation 离线翻译落地后，Windows 平台同样需要具备**零网络依赖、零 API 成本、极速响应（毫秒级）**的端侧机翻能力。

由于 Windows 硬件生态碎片化（不同显卡、NPU 及系统版本），本方案旨在实现**双轨制智能自适应探测**：

1. **轨 A（系统原生 WinRT 神经翻译）**：在具备 NPU / Copilot+ 的 Windows 11（24H2+）设备上，自动优先调用微软官方原生端侧神经翻译 API。
2. **轨 B（通用 DirectML / CTranslate2 轻量离线兜底）**：在普通 Windows 10/11 PC（无专用 NPU）上，调用基于微软 DirectML / GPU / CPU 硬件加速的轻量本地翻译守护进程，确保 100% 普及覆盖。

系统启动时**自动探测硬件与系统环境**，智能决定支持路径，用户无需手动甄别。

## 2. 支持语言范围

与 Chaya 目前定义的 10 种核心语言完全保持一致，支持全向双向互译：

1. 英语 (`en`)
2. 简体中文 (`zh`)
3. 繁体中文 (`cht`)
4. 日语 (`ja`)
5. 韩语 (`ko`)
6. 法语 (`fr`)
7. 德语 (`de`)
8. 西班牙语 (`es`)
9. 俄语 (`ru`)
10. 巴西葡萄牙语 (`pt-BR`)

## 3. 业务功能与场景需求

### 3.1 运行时环境自动检测与状态上报

系统需在上电和检查离线翻译能力时自动探测并返回状态：

- **`winrt-npu`**：系统为 Windows 11 24H2+ 且检测到可用 NPU / 离线系统语言包，直接启用 Windows 原生硬件翻译通道。
- **`directml-gpu`**：检测到支持 DirectX 12 / DirectML 的独立显卡（NVIDIA / AMD / Intel Arc）或核心显卡，启用 GPU 加速通用离线引擎。
- **`cpu-simd`**：老旧设备或纯 CPU 环境，自动降级为 AVX2 / AVX-512 CPU 模式运行。
- **`unsupported`**：非 Windows 系统或核心组件缺失。

### 3.2 离线语言包/模型包下载引导

- **对于 WinRT 原生路径**：若检测到系统支持但尚未在 Windows「设置 $
ightarrow$ 时间和语言 $
ightarrow$ 语言和区域」下载离线功能包，弹出清晰模态框指引用户下载对应语言。
- **对于通用 DirectML 路径**：提示一键下载或预置轻量多语言模型文件（约 500MB~600MB，支持 10 种语言互译）。

### 3.3 交互与错误处理规范

- **不执行静默兜底**：当用户在单项或批量中选择「Windows 原生/本地翻译」时，若未就绪直接提示明确原因与操作指引，不静默串到外部云端服务。
- **模态框引导**：弹框详细列出当前翻译对**需要具备的两种语言**（如：`日本語 (ja) 和 简体中文 (zh)`）。
- **全多语言文案**：所有 UI 界面、错误 Toast、指引模态框支持 10 种语言。
- **API 与日志全英文规范**：后台进程状态、错误码、stdio 通信消息一律使用英文。

## 4. 验收标准

1. **环境自适应**：在 Windows 启动时能准确识别系统版本（Win10 / Win11）及 NPU / GPU 可用性，输出自适应策略。
2. **零配置开箱即用**：满足运行条件时单句响应时间 ≤ 40ms。
3. **跨语向准确性**：10 种语言两两互译均能正确输出译文，无乱码、不崩溃。
4. **异常提示健全**：环境不满足或缺包时，提供直观易懂的前端安装指引弹窗。
