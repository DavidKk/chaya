# 翻译缓存整句对齐回退技术设计

- 日期：2026-10-18
- 状态：已实现并通过算法、服务与真实缓存回放验证。
- 需求：[整句对齐回退](../translation-sentence-fallback.md)。

## 现状与边界

`sentence_positions` 已按句段正文、语气和语言对检索包含查询句的父记录；插件的 `createSentenceResolver` 使用现有内存倒排。问题位于 `sentence-plan.ts` 的译文提取：无 verified 映射时拒绝截取父记录。无需新增索引，也不改变已有分句键和索引规则版本。

本设计补充既有结构化分段文档中“只能凭 verified 映射提取”的约束：仅本设计限定的完整句允许运行时结构推断。列表和逗号子句仍需已有独立译文或人工映射。

## 纯规则模块

新增 `lib/translate/sentence-auto-alignment.ts`，复用 `sentenceUnits` 的原始 UTF-16 偏移和受保护文本规则，将逗号等弱边界单元聚合，遇到真正的句末 stop 才形成一整句。至少两句，且所有正文必须落在已结束的完整句中；省略号、未结束尾句、结构模式 disabled 和列表项不提供推断。

原译逐句比较数量、语气及控制签名。原文可以包含逗号而译文没有，聚合后仍按整句对齐；不可从聚合句内部提取子句。变量和占位符逐句对应，带有跨句格式状态、HTML 或 Ruby 的记录拒绝自动对齐。

仅返回临时原译区间，不写 `alignment_groups`，不改变父记录。不得把 inferred 写为 verified。已有映射的记录不推断，避免绕过人工合并块或明确分组。

## 两阶段规划

1. 运行现有候选生成、来源优先级、人工区间保护、歧义检测与覆盖规划。
2. 已完整命中或计算受限时直接返回，不计算自动对齐。
3. 未完整时，在同一批候选中生成完整句推断候选，保留父记录身份与 revision，标记 `alignment: inferred`。
4. 推断只接受查询侧也覆盖完整句子的范围，并排除与第一阶段候选重叠的范围，既保留已选命中，也避免绕过未选候选的歧义；同范围推断文本不同则标记歧义。
5. 合并候选后复用覆盖规划和渲染；换行、空白、外部结构仍从查询原文拼回。

单条记录只在本次推断扫描中计算一次映射。复用每次扫描 50000 的比较预算和现有 500 条候选上限；受限不能假报完整命中。推断候选逐完整句生成，先分别判定冲突，再由覆盖规划组合相邻结果；禁止用更长推断块绕过其中单句的译文冲突。

## 集成

共享 SQLite 的 `createMatchIndex.plan`、诊断 `testTranslationCache`、插件和本作 `createSentenceResolver.plan` 共用 planner。新增规则不改索引 marker，不执行迁移，不调用翻译引擎。

诊断补充 `inferred_alignment` 标记；对实际匹配的范围记录推断来源。现有页面继续展示提取命中、父记录、译文与缺口，本轮不增加页面控件。

## 验证

纯算法覆盖整段优先、段首中尾提取、逗号聚合、完整句边界、句数和语气、控制码、人工映射、冲突、上限及源记录不变。服务测试覆盖只读快照、父记录修改后失效、共享与插件一致，并用真实语料回放本次链接。执行相关测试、Lint、类型检查与插件构建。

## 实施结果

2026-10-18：新增纯规则模块并接入两阶段 planner，诊断提供 `alignment: inferred` 和 `inferred_alignment`。复用原有候选检索和覆盖规划，未改数据库 schema、索引 marker 或持久化映射。

42 个相关测试套件、347 项测试通过，包含取消独立短句后的真实案例、段首中尾与连续句提取、原译句数、逗号聚合、变量错位、跨句格式、已有映射保护及长块绕过单句冲突的反例。真实本地缓存回放得到第一句提取命中、第二句保留原文；查询前后表与索引定义、cache_meta、缓存条数、命中计数和更新时间一致。

## CR 与修正

2026-10-18：对照需求审查实现，发现并修复两处边界问题：

- 查询 `X,A.B.` 时，缓存 `A.C.` 不得把查询中的逗号子句 `A.` 当作完整句子提取。新增查询侧句首、句末检查；`X.A.B.` 中的完整句 `A.` 仍可复用。
- 插件内存查询在高频句候选超过 500 条时，原先可能忽略 select 的 limited 标记并对残留候选继续推断。现在插件、SQLite planner 和只读诊断统一返回受限未命中，避免不完整候选集合产生自动填充。

两项均有回归测试；42 个测试套件、347 项相关测试通过。候选上限处理只调整运行时行为，不增加或升级索引。原译句数和标点相容仍只是结构证据，不能保证没有语义重排；不将自动映射写成 verified。

### 分隔符变体的冲突判断

2026-10-18：同一查询区间的候选按实际渲染结果判定冲突。缓存译文 `译文、` 与 `译文` 在查询的顿号边界都会拼成 `译文、`，不再误报歧义；正文不同或句末语气不同仍按既有规则拒绝。真实三行案例验证前两段命中，仅最后含 `羞 2恥` 的段落保留缺口。42 个相关测试套件、350 项测试通过，不新增或改写索引。

### 完整行独立词条回退

2026-10-18：新增最终一层完整行回退。`sentence-query.ts` 从真实或 literal 换行提取完整行查询，最多检查 200 个换行；SQLite 通过原有 match_keys、插件通过原有 whole Map 查询，不增加索引或生成派生记录。独立行候选与其它候选共用 500 条上限。

整段、句段或整句推断仍有缺口时，仅对未明确注解的换行构建临时 hard 分段视图，重映射已选命中的查询单元坐标，并补入起点和完整文本均对应某一整行的独立缓存。已有候选、已选命中和冲突区间不被覆盖；预算耗尽停止回退。不能按原译行数推断映射，也不能在行内任意找词。显式 soft 注解仍优先于临时 hard 视图。

验证覆盖改动前缀后的两行独立命中、SQLite 与插件一致、原始换行保留、连续整段优先、受保护引语、不按相同行数提取父译文、行内子串拒绝及查询只读。真实语料验证只剩 `3あたし、` 为缺口；42 个测试套件、354 项相关测试通过。

## 统一查询视图与组合验证

2026-10-18：停止按单个语料修改索引。新增纯模块 `lib/translate/sentence-query.ts`，由 SQLite 候选检索、插件候选检索与 planner 共同使用查询视图。视图包括原文、成对外层对白引号或括号的正文、逻辑换行形式和完整行；所有范围均映射回原始 UTF-16 坐标。只剥离完整外壳，保留正文内部引用，禁止丢弃外部问号和感叹号。最多剥离八层，规划器不递归展开外壳；按层尝试有限的正文视图。

规划顺序为原文整体与既有匹配优先，未命中时处理合法外壳正文，再处理整句推断与完整行独立缓存。结构扫描只决定是否允许自动推断，不能把后续独立行缓存查询一并提前取消。禁用拆分、已有歧义、候选上限与计算上限仍生效。未增加 schema、索引键类型或索引升级版本，也没有对本地库执行迁移或重建。

组合验证使用固定原译缓存，而非为每个线上句子增加特例：48 个用例覆盖四类分隔符、四类外壳和前中后改动位置，另有 12 个用例只保留父记录检验整句提取。改动前，前一组 48 项中有 36 项漏匹配；统一视图后 60 项均通过。六个用户语料只读回放分别得到一项整段命中和五项部分命中，无误报歧义；表与索引定义、cache_meta、条数及命中统计查询前后相同。
