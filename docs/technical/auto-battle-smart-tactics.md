# RPG Maker 自动战斗情境决策与智能战术技术方案

- **日期**：2026-10-31
- **状态**：MV 决策与取消恢复已实现，回归覆盖见第 6 节；真实游戏视觉验收单独记录。
- **对应需求**：[`../auto-battle-smart-tactics.md`](../auto-battle-smart-tactics.md)
- **有效范围**：本文描述 `plugins/mv` JavaScript 运行时的实现。MZ 共用该插件，但本文的引擎源码核对来自 MV 1.6.0。RGSS 有独立 Ruby 实现，本次修复没有同步或验证 Ruby 策略，不能据此宣称跨引擎完全一致。

## 1. 模块与调用链

| 文件                                                  | 职责                                                 |
| ----------------------------------------------------- | ---------------------------------------------------- |
| `plugins/mv/src/cheat/runtime/auto-battle.ts`         | 原型钩子、输入阶段补偿提交、公开 API 重导出          |
| `plugins/mv/src/cheat/runtime/auto-battle-tactics.ts` | 战局决策、动作槽 MP/TP 与物品数量预留                |
| `plugins/mv/src/cheat/runtime/auto-battle-effects.ts` | 动作构造、伤害与恢复估算、有效效果判断、回血物品匹配 |
| `plugins/mv/src/cheat/runtime/cheats.ts`              | `autoBattle` 开关与 200ms 补偿定时器、卸载清理       |
| `plugins/mv/src/cheat/session/battle-windows.ts`      | 技能、物品、目标与帮助窗口关闭，手动输入恢复         |

开启开关后，`Game_Actor.isAutoBattle()` 返回强制标记，引擎在生成动作时调用接管后的 `makeAutoBattleActions()`。决策直接读取 `usableSkills()`，无需点击技能菜单，也不限制 `stypeId`。

`tryAutoBattle` 补偿中途开启和部分插件未自动推进的输入阶段。事件、消息忙碌或阶段非 `input` 时等待；普通回合制为可行动角色准备动作后 `startTurn()`；YEP STB 只准备当前角色并 `selectNextCommand()`，不重启整轮。STB 从队伍命令返回时由其原生方法恢复 subject。

原型包装只安装一次；强制标记回调与战术实现引用在重新安装时更新，避免插件重载持有旧运行时。补偿调用不覆盖标记回调，关闭或卸载后可读取真实关闭状态。

## 2. 动作决策顺序

1. **合法性**：汇总所有技能菜单的可用技能，再检查 `canUse`、MP/TP 预算；排除角色自身的普攻与防御技能 ID。混乱时交给引擎 `makeConfusionActions`。
2. **复活**：存在阵亡队友时，先取死者范围的技能，再取同类物品。
3. **急救**：生命比例最低的存活队友低于 40% 时，优先有效治疗技能，否则匹配回血物品。自身范围 11 不能用于其他队友。
4. **MP 续航**：已学技能需要 MP、当前预留 MP 低于上限 35%、全队无低血危机时，先取净恢复 MP 为正的技能，否则使用接近缺口的回蓝物品。
5. **群攻**：两名及以上敌人时，优先范围 2 或随机多目标范围 4–6 的有效技能；空效果列表、无效公式与已免疫效果不会仅凭范围标签入选。
6. **输出与控制**：评估敌人上的 HP 伤害、吸收与有效状态/减益/驱散增益。伤害截到目标剩余 HP，斩杀额外加分，MP 成本用于细微区分。默认优先有效技能，即使其直接伤害低于普攻；若普攻已能击杀残血目标，则节省收费技能的 MP/TP。
7. **辅助**：输出未入选时，寻找尚可增益、解除状态或解除减益的友方目标。自身范围只检查自身，队友范围选实际需要该效果的人。
8. **受限输出**：无法普攻且无可用技能方案时，尝试敌方范围 1–6 的 HP 伤害/吸收物品，并选择预估伤害为正的目标；跳过无效公式与免疫目标。
9. **兜底**：可普攻则普攻，否则在 `canGuard()` 为真时防御。两者均封印时保留空动作，交给引擎跳过；不再任意选择一个可能无效的治疗或复活技能。

有效效果判断检查已有状态、状态免疫、状态抗性、增益/减益层数上限及可驱散效果，防止同一状态或满层增益无限施放。未知自定义脚本效果不被推断成有效技能。

## 3. 伤害与恢复估算

`safeEvaluateDamage` 暂时将标准伤害浮动设为 0，在 `finally` 中还原数据库值。优先调用单参数 `makeDamageValue(target)`；抛异常后兼容双参数 `(target, false)`。无效数值与异常归 0，不中断决策。

MV 公式型 HP/MP 治疗分别是 `damage.type === 3/4`，引擎返回负伤害。恢复估算反转其符号，不能直接按攻击伤害截断为 0。恢复效果码 11/12 则按目标 MHP/MMP 的比例加固定值，并计入目标 `rec` 与物品使用者 `pha`；使用技能时不乘物品药效。

伤害公式仍由游戏及其插件实现，异常捕获不构成无副作用沙箱；自定义脚本可能依赖执行期上下文。估算失败且无有效附加效果时跳过该技能，选择其他动作。

## 4. 物品匹配与动作槽预算

回血物品仅考虑存活友方范围 7、8、11。缺口为 `mhp - hp`，回复量不超过缺口时按覆盖率评分；超过缺口时扣减溢出，优先接近缺口的物品。

若同时满足 `recovery < mhp * 0.08`、`deficit > 300`、`recovery < deficit * 0.2`，将该物品在当前目标上判为低效并跳过。这是当前决策的淘汰判断，不删除库存，也不持久标记物品；后续局面改变时会重新评估。

每个角色的多行动槽会预留 MP、TP 与消耗品数量；非消耗品不扣库存预留。给自身或全体回复 MP 时更新预留 MP，避免连续槽重复补满。技能是否可用仍服从引擎当前的 `canUse`，不会绕过尚未实际恢复的 MP 限制。

当前不模拟整个队伍未来行动的治疗、增益、复活或伤害结果，也不跨角色共享物品预留；执行时仍由引擎重新校验有效性和库存。这些边界不能当作已实现的全队最优规划。

## 5. 取消自动战斗与菜单恢复

### 根因

原生 MV `Window_ActorCommand.setup` 打开并激活窗口，但不会调用 `show()`。接管时 `hide()` 会让后续手动回合保持不可见。技能列表在进入目标选择后还可能处于可见但未激活的状态，不能只关闭 active 窗口。

MOG 的 `Window_ActorCommand.setup` 已包含 `battle_commands_initialize()`，其更新循环也支持 `$gameTemp._bcom_need_refresh`。再次手动初始化会重复重建精灵。

### 恢复契约

- 接管动作时关闭、停用命令窗口，不隐藏命令窗口；关闭可见或激活的技能、物品、目标与帮助窗口。
- 只有从开启转为关闭时请求恢复，重复设置关闭不打断手动技能或物品选择。卸载时先清掉自动标记再恢复。
- 正在执行、结算或战斗消息/事件忙碌时不打开输入窗口。已提交动作继续执行，下次引擎输入阶段正常开放命令。
- 输入阶段若仍有未被接管的手动选择窗口，则保留该选择。
- 输入已关闭且允许手动输入时恢复命令窗口可见性，关闭互斥窗口，按当前角色或队伍重新启动命令选择；没有场景入口时通过 `setup/open/activate` 兼容。
- MOG 通过原生 `setup` 重建与刷新标记恢复，不额外直接调用一次初始化。

## 6. 验证范围

`__tests__/plugins/cheat/runtime/auto-battle*.spec.ts` 覆盖：

- 自动标记、重载回调、卸载关闭、普通回合与 STB 提交；
- 技能跨类型选择、MP/TP 预算、封印、缴械、防御封印与公式异常；
- 复活、负伤害治疗公式、恢复倍率、回血缺口匹配、低效药过滤、MP 续航、投掷物品与非消耗品；
- 空群攻、免疫控制、已有状态、满层增益与实际辅助目标；
- 取消后的命令可见性、MOG 初始化次数、执行期不抢输入、手动子菜单保留与可见未激活列表关闭。

这些测试验证 JavaScript 动作与窗口契约，不替代真实游戏的动画、手柄输入或第三方插件组合的视觉验收。MZ 和 RGSS 需分别验收。

## 7. 与 Companion 托管的关系

当前 `autoBattle` 是游戏内同步规则策略，Companion 是另一工作树中的异步托管管线；本次实现没有共用同一套决策代码，也不能宣称两者已有完全相同的战术行为。

同步规则可以直接满足引擎生成动作的调用约定，无需推理服务。异步托管也可以通过分阶段等待避免阻塞主线程，但需要额外的输入生命周期、取消与超时管理。本次不把网络请求接入原型回调，不承诺严格 0ms 决策或固定推理延时。
