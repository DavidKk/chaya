## 1. 背景

Agent 实例目前只有 Ollama 一种接入类型：

- 游戏内的旅伴面板、Agent 侧栏发起的任务（询问、托管、陪聊）都由**游戏内 Host** 的任务控制器执行：它自己跑「观察 → 调模型 → 执行工具」循环，每一步经 `/api/game-agent/model` 把 messages + tools 发给 Ollama，拿回一条带 `tool_calls` 的回复。
- Chaya 网页侧栏的询问在本机服务里跑同样的循环；托管转交游戏内 Host。
- 发起任务前先用同一个模型做一次意图分类（询问 / 托管）。

术语：**托管**指 Agent 直接接管游玩，用普通玩家输入（按键、移动、对话推进、战斗操作）替玩家控制游戏，持续到玩家停止（代码中的能力名为 `play`）；**询问**只回答、不操作游戏。

希望 Agent 实例能使用玩家的 Cursor、ChatGPT（Codex）、Claude、Gemini 订阅账号，不必配 API Key 或自建模型服务。授权方式与工单系统一致，按类型二选一、不可切换：

| 类型                    | 授权方式     | 含义                                                                                                   |
| ----------------------- | ------------ | ------------------------------------------------------------------------------------------------------ |
| Cursor                  | **本机登录** | 使用这台机器上 Cursor CLI 自己的登录；Chaya 只检测状态、发起登录 / 退出，不碰凭证                      |
| Codex / Claude / Gemini | **远程授权** | Chaya 服务发起官方登录，玩家在任意设备的浏览器完成授权；凭证由 Chaya 按实例加密保管，不碰本机 CLI 登录 |

Cursor 只能本机登录，因为它的 CLI 没有可隔离的凭证目录（见 §5.3）；其余三家只走远程授权，避免与本机 CLI 登录互相影响。

这些 CLI 都是完整的 Agent（自带工具循环），**不提供**「给 messages + tools、返回一次 tool call」的补全接口；工具只能通过 MCP 提供给它们。因此运行方式是：**由 CLI Agent 跑完整一轮，Chaya 通过 MCP 提供游戏工具**，与工单系统一致。

不采用的方案：

- 拿订阅凭证直连各家模型 API：凭证不面向第三方调用，也不是工单系统的做法。
- 把 CLI 当补全接口（工具定义写进 Prompt、要求返回 JSON）：工具调用不可靠，且每一步都要起一次 CLI，太慢。

## 3. 非目标

- **不做 API Key**（四种类型都不做）。
- Cursor 不做远程授权；Codex / Claude / Gemini 不做本机登录（不读取、不复用、不修改 `~/.codex`、`~/.claude` 等本机登录）。
- 不做工单系统里的邀请链接、管理员身份、执行租户与用量归属：Chaya 是单用户服务，授权就在玩家自己的配置页完成。
- 不支持 Cloud（Vercel / `remote`）运行：CLI 必须跑在 Chaya 本机服务所在的机器上。「远程授权」指授权页面可以在别的设备上完成，不是指云端运行。
- 游戏插件脱离本机服务单独运行时（含经远程 MCP 网关连接、插件直连 Ollama 的模式）不可用（插件不能起 CLI）。
- 不开放 CLI Agent 自带的终端、文件读写、联网等工具；它只能使用 Chaya 提供的游戏工具。
- 不改 Ollama 实例现有的运行方式。

## 4. 接入类型

| 类型         | 运行方式                           | 授权     | 授权交互                                                 | 凭证位置（运行时）              |
| ------------ | ---------------------------------- | -------- | -------------------------------------------------------- | ------------------------------- |
| Cursor       | ACP：`agent acp`                   | 本机登录 | `agent login` 输出登录链接，页面展示，玩家打开完成登录   | Cursor CLI 自己的存储（系统级） |
| Codex（GPT） | `@openai/codex-sdk`（`codex` CLI） | 远程授权 | 设备码：链接 + 用户码，玩家在任意设备打开并输入          | 独立 `CODEX_HOME`，强制文件存储 |
| Claude       | ACP：`claude-agent-acp`            | 远程授权 | 官方 OAuth 链接 + 回填码：授权后把页面给出的码粘回 Chaya | 独立 `CLAUDE_CONFIG_DIR`        |
| Gemini       | Antigravity CLI（`agy`）           | 远程授权 | Google 官方 OAuth 链接 + 回填码                          | 独立 CLI 主目录                 |

- 实例保存：名称、类型、默认模型、超时；Ollama 专属字段（服务地址、Temperature、Keep Alive、Token、单次模型请求超时）对这四种类型隐藏。超时只保留「单轮总时长」与「游戏调用超时」。授权方式由类型决定，表单不提供选择。
- 同步兼容：旧版本游戏插件只认识 Ollama 实例。新类型加入后，旧插件看不到新类型实例，Ollama 实例照常双向同步，且不得因此丢失或覆盖任何实例；更新插件后新类型自动出现。
- Codex / Claude / Gemini：每个实例一份独立授权，同类型多个实例可以登录不同账号。
- Cursor：所有 Cursor 实例共享这台机器上的同一个 Cursor 登录，多实例只区分默认模型 / 超时；配置页需明示「所有 Cursor 实例共用本机登录」。
- CLI 查找复用「集成 → 接入 Agent」已有的查找逻辑（PATH + GUI 启动时缺失的常见目录）；找不到时显示安装提示，不报模糊错误。

## 5. 授权

### 5.1 状态

配置页每个实例显示授权状态徽标（所有类型同一套措辞），进入详情、授权完成或退出后检测，不在后台轮询，也不提供手动刷新（连通性用下方「测试」）。每种状态只有一个操作按钮：

| 状态       | 徽标                    | Cursor（本机登录）                                                    | Codex / Claude / Gemini（远程授权）    |
| ---------- | ----------------------- | --------------------------------------------------------------------- | -------------------------------------- |
| 未安装 CLI | 「未找到 CLI」          | 安装说明                                                              | 安装说明                               |
| 未登录     | 「未授权」              | 「登录」                                                              | 「授权」                               |
| 已登录     | 「已授权」+ 套餐 + 邮箱 | 「退出」（退出本机 Cursor CLI）；Free 套餐提示通常无法调用 Agent 模型 | 「退出」（删除该实例的授权）           |
| 进行中     | —                       | 显示登录链接，可取消                                                  | 显示链接 / 用户码 / 回填输入框，可取消 |
| 已失效     | 「已失效」              | —（以本机状态为准）                                                   | 「重新授权」（刷新失败或被提供方撤销） |

- Cursor 检测：`agent status --format json` 读 `isAuthenticated`，`agent about --format json` 读邮箱与套餐；5 秒超时。
- 远程授权检测：只读 Chaya 保存的授权记录与账号摘要。
- 两者都**不发起登录、不调模型**；是否真的可用以「测试」为准。

### 5.2 远程授权（Codex / Claude / Gemini）

#### 流程

1. 玩家在配置页点「授权」。服务端为这次授权建一个临时 staging 目录（`0700`），在里面起官方 CLI 的登录流程。
2. 把挑战推给页面（页面轮询授权进度；游戏内配置页也能用）：
   - Codex：链接 + 用户码（设备码，走 Codex App Server 的结构化登录接口，不解析终端输出）。
   - Claude / Gemini：官方授权链接；页面同时显示「粘贴授权码」输入框，玩家授权后把码粘回，服务端转交给登录进程。
3. 登录完成后校验账号（邮箱提示与套餐），把 staging 里的凭证**加密**写入该实例的凭证目录，清理 staging。
4. 页面提示「授权完成，请点击测试验证当前模型」，并清空该类型的模型列表缓存。

约束：

- 链接只在页面上显示，由玩家自己打开（可以在手机或其它电脑上打开），服务端不自动打开浏览器。
- 拿到挑战 30 秒超时；整个授权 10 分钟超时。
- 玩家关闭弹窗或页面停止轮询超过 45 秒即取消并结束登录进程。**旧授权在新授权成功前保持可用**。
- 同一实例同时只能有一个授权进行中（进程内锁）；重复发起提示「该实例已有授权进行中」。
- 授权完成时若实例已被修改或删除，丢弃新凭证并提示刷新后重试。
- 错误文案区分：找不到 CLI、网络超时、提供方拒绝（如设备码 403）、授权码错误、未完成 / 已过期。

#### 凭证保管

- 静态只存密文：复用 Agent Token 现有的 AES-256-GCM 加密与密钥（`services/game-agent/secrets.ts`），按实例分目录，目录 `0700`、文件 `0600`，位于 Chaya 数据目录下，不进备份或制品。
- 运行时把凭证解密到临时目录，作为该 CLI 的主目录 / 配置目录传入。同一实例同时只有一份明文副本，供并发会话与常驻会话共用（refresh token 会轮换，两份副本各自刷新会互相作废）；最后一个会话结束时回写并删除。
- 强制 CLI 使用文件存储，不写系统钥匙串：Codex 写 `cli_auth_credentials_store="file"` 与 `forced_login_method="chatgpt"`；Claude 在 macOS 上会按配置目录写钥匙串，需要与工单系统一样在运行前后把钥匙串项与加密文件互相搬运并清理。
- **刷新回写**：CLI 运行中会刷新 access / refresh token。本轮结束后必须把临时目录里的新凭证加密写回；同一实例的并发运行要串行化回写，较旧的凭证不能覆盖较新的。回写失败则把授权标为「已失效」并提示重新授权。
- 「注销」删除该实例的密文与临时目录；能调用提供方注销接口的（Codex）同时注销。删除实例时一并注销并删除凭证。
- 注销、重新授权成功、删除实例、切换类型时，先结束该实例所有进行中的任务与会话（任务失败原因写明「该实例授权已变更」），再处理凭证；不让旧会话带着旧凭证继续跑。

### 5.3 本机登录（Cursor）

#### 为什么只能本机登录

- Cursor CLI 的登录存在系统用户级的存储（macOS 钥匙串 / 用户配置目录），没有可指定的独立凭证目录，无法按实例隔离、加密保管。
- 工单系统里 Cursor 也是本机登录；远程授权仅为 PoC，未上线。

#### 重新登录流程

1. 玩家在配置页点「登录 / 重新登录」。
2. 服务端以 `NO_OPEN_BROWSER=1`、清空 `CURSOR_API_KEY` 运行 `agent login`，从输出中解析 Cursor 登录链接推给页面（与远程授权相同的轮询方式）。
3. 玩家打开链接完成登录；登录进程退出码为 0 即视为成功，随后读取邮箱与套餐，提示「已登录 xxx（套餐），请点击测试验证当前模型」，清空 Cursor 模型列表缓存。

约束：

- 拿到链接 30 秒超时；整个登录 10 分钟超时；页面停止轮询超过 45 秒视为取消。
- 取消即结束登录进程。**原登录在 `agent login` 成功前保持不动**，取消不会让本机变成未登录。
- 全机只能有一个 Cursor 登录进行中（所有 Cursor 实例共用一把进程内锁）。
- 登录成功会替换这台机器上 Cursor CLI 的登录（与在终端里执行 `agent login` 等价），确认弹窗需提示这一点。
- 登录成功后结束所有 Cursor 实例进行中的任务与会话（可能已换账号）。
- Chaya 不读取 Cursor 的凭证内容；运行时只把 CLI 原样启动，环境里清空 `CURSOR_API_KEY`，避免误走 API Key。
- 错误文案区分：找不到 CLI、拿不到登录链接（版本或网络）、登录超时、未完成。

### 5.4 测试与模型列表

- 「测试」用当前实例与默认模型发起一次最小的只读会话（不挂游戏工具），成功显示模型名与耗时，失败显示原因（额度、套餐、模型不可用、未登录 / 授权失效）。
- Cursor / Claude / Gemini：模型从 ACP 会话的模型选项读取，失败退回「auto」。Codex：给出受控模型列表。
- 列表按类型缓存，登录 / 授权完成或手动刷新时清空。

### 5.5 代理

每个实例（含 Ollama）可选填一个代理，用于网络受限或所在地区被提供方拒绝的情况（例如 Codex 设备码 403）。

- 支持 `http://`、`https://`、`socks5://`（`socks5h://`），可带 `用户名:密码@`；只填协议、主机与端口，格式错误时不能保存或测试。
- 留空：沿用 Chaya 自身环境里的系统代理变量（原有行为）。
- 生效范围：登录 / 授权、状态检测、测试与运行都经由该代理；本机地址（`localhost`、`127.0.0.1`、`::1`，含会话 MCP 端点与本机 Ollama）始终直连。
- SOCKS：Cursor、Claude 等 CLI 只认 HTTP 代理，Chaya 在本机起一个仅监听 `127.0.0.1`、带随机口令的 HTTP 转发，把流量转进玩家的 SOCKS5 代理，所有类型行为一致。
- 授权用的是**已保存**的代理：表单里改了代理但未保存时，授权区提示「代理已修改，保存后再登录或授权」并禁用操作；「测试」直接使用表单里的值，可先测通再保存。
- Cursor 登录是本机共用的，登录、退出与状态检测使用当前查看实例的代理。
- 浏览器直连 Ollama（Cloud / 浏览器运行时）不经过服务端，不受此设置影响。

## 6. 运行

### 6.1 一轮任务

**任务归属不变**：游戏内发起的任务仍由游戏内 Host 的任务控制器管理（任务状态、进度、玩家卡片、输入占用、停止、托管周期）；网页侧栏的询问仍由本机服务管理。变的只是「思考并决定调用哪个工具」这一段：从「每一步调一次 Ollama」换成「交给本机服务里的 CLI 会话跑完整一轮」。

1. 任务归属方（游戏内 Host 或本机服务）请求本机服务开启本轮 CLI 会话，带上能力、Prompt、允许的工具清单与上限。
2. 准备凭证：远程授权类型把该实例凭证解密到临时目录；Cursor 直接使用本机登录。
3. 本机服务创建 CLI 会话（ACP 或 Codex SDK），工作目录是一个空的临时目录。
4. 会话挂一个**会话专用**的 Chaya MCP 端点，只暴露本轮允许的工具（见 6.3），以及玩家卡片 `chaya_player_card`；没有进行中的一轮时任何工具调用都被拒绝。
5. 发送与 Ollama 相同语义的系统 Prompt 与玩家目标。
6. CLI Agent 每次调用工具，本机服务把调用**转交任务归属方执行**（游戏内任务就回到游戏内 Host 执行），结果再返回给 CLI。因此输入占用、玩家卡片等待、操作确认、停止后拒绝执行等行为与 Ollama 实例完全相同。
7. 会话更新映射为现有任务事件（见 6.4）。
8. 结束、停止、超时或失败时关闭会话与进程；远程授权类型回写刷新后的凭证（§5.2）并清理临时目录。

本轮进行中游戏与本机服务断开时，CLI 会话随之结束，本轮按失败处理并提示「与 Chaya 本机服务断开」；不像 Ollama 实例那样等待服务恢复后续跑（会话已不存在）。

### 6.2 意图分类

意图分类使用所选实例本身：发一次不挂工具的短请求，返回与现在相同的结构——网页侧栏是 `{"operate": boolean, "edit": boolean}`（`edit` 决定询问时是否开放改数据的工具），游戏内是 `{"operate": boolean}`。

- 没有连接游戏时与现在一样直接按询问处理，不调用 CLI。
- 分类用独立的短会话，不借用旅伴常驻会话（§6.8），避免分类内容混进陪聊上下文。
- 20 秒内没有结果或返回无法解析时按「询问」处理，不阻塞玩家。
- 分类也消耗该账号额度；在额度冷却期内直接按「询问」处理并提示冷却中。

### 6.3 工具与权限

工具集合与同一入口的 Ollama 实例**完全相同**，由同一份能力配置和过滤规则决定；危险工具仍不开放：

| 入口与能力     | 暴露的工具（与现在一致）                                                                                       |
| -------------- | -------------------------------------------------------------------------------------------------------------- |
| 游戏内询问     | 非输入类工具 + 玩家卡片                                                                                        |
| 游戏内托管     | 状态读取 + 按键游玩 + 已允许的插件工具 + 玩家卡片                                                              |
| 游戏内旅伴陪聊 | 陪聊能力允许的工具 + 玩家卡片                                                                                  |
| 网页侧栏询问   | 游戏工具（分类为非改数据时只给只读工具）+ Agent 管理工具；未连接游戏或无需工具时不挂游戏工具；**没有玩家卡片** |

- 工具结果的截断长度与 Ollama 实例相同。
- CLI 发来的权限请求（写文件、跑命令、联网等）一律拒绝；能关闭的内置工具在启动参数里关闭。
- 单轮工具调用次数、步数、总时长上限由 MCP 端点强制：超限后工具直接返回错误并结束本轮，不依赖 Prompt 让模型自觉遵守。CLI 不上报「步数」，步数上限以工具调用次数与总时长代替。
- 托管时的游戏输入占用（玩家按键优先、停止后归还输入）与现在一致。
- 托管时「连续三次相同动作且结果相同即判定无进展并结束本周期」的保护照旧，由服务端按工具调用记录判断。
- `chaya_player_card` 的确认 / 选择卡片照常等待玩家回答，回答作为工具结果返回给 CLI Agent；等待期间不计入单轮总时长。

### 6.4 事件映射

| CLI 会话更新                    | Chaya 任务事件                    |
| ------------------------------- | --------------------------------- |
| 助手文本增量                    | `assistant.delta`                 |
| 思考片段                        | `thought.updated`（只展示摘要）   |
| 工具调用开始 / 结束             | `tool.started` / `tool.completed` |
| 用量                            | `usage.updated`                   |
| 本轮结束                        | `turn.completed`                  |
| 错误 / 额度 / 未登录 / 授权失效 | `turn.failed`，原因可读（见 §7）  |

旅伴面板、Agent 侧栏、思考过程时间线不需要区分实例类型；阶段状态（观察 / 思考 / 操作 / 验证）照常显示。

### 6.5 对话上下文与人设

- 对话历史与 Ollama 实例一致：本轮之前的问答照常带入（窗口大小相同），并照常写回任务 / 会话历史，后续的询问、任务详情与活动记录都能看到。
- 新开会话时把历史一并发给 CLI；复用会话时只发本轮新增内容。
- 玩家「新对话」、清空历史、切换旅伴角色、切换模型时，下一轮必须新开 CLI 会话，不能沿用旧上下文。
- 系统 Prompt（含旅伴角色设定、语言）与 Ollama 实例语义相同。CLI 自带「编程助手」类人设，需验证我们的设定能压过它（见 §12）。

### 6.6 停止与超时

- 玩家点停止（含工具栏「停止托管」）：发送会话取消，2 秒内未退出则结束进程；之后不再执行任何工具。
- 单轮超时沿用实例的超时设置；超时视为失败并说明原因。
- 本机服务重启或游戏退出时，进行中的会话一并结束。

### 6.7 托管周期

托管是持续任务：Ollama 实例每完成一个周期（一轮工具循环）等待约 1 秒再进入下一个周期，直到玩家停止。CLI 实例：

- 同一任务的所有周期复用**同一个 CLI 会话**，下一个周期只追加「继续同一目标 + 当前游戏状态」，不重放历史。
- 周期间隔不短于 5 秒；本周期没有调用任何工具（无事可做）时间隔加倍，最长 60 秒，有动作后恢复。
- 每个周期都消耗额度，配置页与托管开始时提示「托管会持续消耗该账号额度」。
- 宝箱托管（固定步骤、不调模型）不受实例类型影响。

### 6.8 旅伴陪聊

允许旅伴自动陪聊使用这四种实例（按所选实例走）。因为每次都会起一次会话、消耗订阅额度：

- 优先复用同一游戏的常驻会话（空闲一段时间后关闭），避免每句都冷启动；远程授权类型常驻期间凭证留在临时目录，关闭时回写并清理。
- 沿用现有触发冷却与「同时只跑一个」的限制；连续失败时按现有冷却退避，不刷请求。
- 配置页在这四种类型的实例上提示：「旅伴自动陪聊会消耗该账号额度」。

## 7. 错误与状态

| 情况               | 表现                                                                         |
| ------------------ | ---------------------------------------------------------------------------- |
| CLI 未安装         | 实例不可选，显示「未找到 X CLI」并引导到配置页                               |
| Cursor 本机未登录  | 本轮失败：「Cursor 本机登录已失效，请到配置页重新登录」，不自动弹登录        |
| 远程授权失效       | 本轮失败：「X 授权已失效，请到配置页重新授权」，不自动发起授权               |
| 额度用尽 / 限流    | 本轮失败并显示原因；同一实例进入冷却，冷却期内不再发起                       |
| 模型不可用         | 本轮失败，提示更换模型                                                       |
| Cloud 环境         | 这四种类型不可选，说明需要 App / 本机服务                                    |
| 插件未连本机服务   | 实例显示不可用，原因「需要连接本机服务」                                     |
| 运行中与服务断开   | 本轮失败：「与 Chaya 本机服务断开」，不自动续跑                              |
| 同时运行的会话过多 | 优先关闭空闲的旅伴常驻会话；仍不够时本轮失败：「Agent 会话过多，请稍后再试」 |
| 授权在运行中变更   | 进行中的任务失败：「该实例授权已变更」                                       |
| 旧版插件           | 游戏内看不到新类型实例；Ollama 实例不受影响                                  |

## 8. 安全

- 登录链接、用户码、回填码只在发起授权的页面与服务端之间传递，不写日志、不进聊天记录、不进同步数据。
- 远程授权凭证密文不随 Agent 配置同步到游戏插件；插件只知道「已授权 / 未授权」与账号摘要。
- Chaya 不读取 Cursor CLI 的凭证内容，只调用其状态、登录与运行命令。
- Agent 配置管理工具（Chaya 助手管理 Agent）可以新增、编辑这四种类型的实例（名称、模型、超时），但不能读取、导出凭证，也不能发起登录、授权或注销。
- 会话 MCP 端点只在本机模式可用、只接受回环地址连接（Chaya 监听局域网时也一样），带随机令牌，会话关闭即失效；没有进行中的一轮时拒绝调用。
- CLI 运行、轮询、停止接口与现有模型代理接口同样鉴权；一轮的事件与工具结果只能由发起方读取和提交。
- CLI 不得带上玩家机器上的其它 MCP 服务或全局规则：远程授权类型用独立主目录天然隔离；Cursor 共用本机配置，必须确认不会加载玩家的全局 MCP / 规则，加载了的工具调用一律拒绝（见 §12）。
- CLI 子进程的错误输出可能含 token，记录前必须脱敏；日志与活动记录按现有规则脱敏。

## 9. 与工单系统的差异

| 工单系统                                    | Chaya                           |
| ------------------------------------------- | ------------------------------- |
| 每种类型可选本机 / 远程 / API Key           | 类型决定唯一方式，不可选        |
| 管理员签发邀请链接，账号所有者在公开页授权  | 玩家在自己的配置页直接授权      |
| Postgres 表存凭证版本，CAS 激活、旧版本排空 | 每实例一份当前凭证 + 进程内锁   |
| Postgres advisory lock 保护 Cursor 登录     | 进程内锁                        |
| HMAC keyring、管理员签名身份                | 沿用 Agent Token 的本地加密密钥 |
| 执行租户、业务域、用量归属                  | 不需要                          |
| 审计表                                      | 本机日志（脱敏）                |

## 10. 分期

### Phase 1：类型与授权

- 四种接入类型的数据结构、同步与配置页表单。
- Cursor：本机登录状态、重新登录。
- Codex / Claude / Gemini：远程授权、重新授权、注销、状态；凭证加密保管与刷新回写。
- 测试与模型列表。

验收：Cursor 显示本机登录状态并能重新登录，取消不影响原登录；Codex 在另一台设备上完成一次设备码授权，取消不影响已有凭证，本机 Codex CLI 登录状态不受影响；测试返回模型与耗时。

### Phase 2：询问与旅伴陪聊

> 已开放：询问、旅伴陪聊、托管与意图分类对 Cursor / Codex / Gemini 实例可用。CLI 作为「每轮一次」的文本模型接入现有 Agent 循环，工具、玩家卡片与确认沿用 Ollama 路径；回答为整段返回（非流式），Cursor / Codex 常驻进程后单轮约 7–10 秒。实现见技术文档 §7.0。

- CLI 会话运行器（ACP + Codex SDK）、本轮 MCP 端点、工具转交、事件映射、停止与超时。
- 意图分类、询问与旅伴陪聊接入（游戏内与网页侧栏）；玩家卡片可用。

验收：分别选 Cursor、Codex 实例询问「我现在在哪」，能读到游戏状态并流式回答；Agent 发起确认卡片，玩家点选后继续；停止立即生效；Codex 跑满一次 token 刷新后仍可继续使用。

### Phase 3：托管、Claude / Gemini 验收

- 托管循环接入：按键工具、输入占用、上限强制、周期复用会话与间隔退避。
- 常驻会话复用与额度冷却。
- Claude、Gemini 用真实账号完成授权、运行与刷新验收。

验收：让 Agent「走到村长旁边并对话」，能完成并引用操作后的状态；超过上限自动结束；停止后游戏输入立即归还玩家。

## 12. 风险与待确认

| 项                    | 说明                                                                                                                                                                   |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cursor 共用本机登录   | 所有 Cursor 实例共用一个账号；在 Chaya 里登录或退出会改变本机 Cursor CLI 的登录（含玩家在终端里用的那份），退出前需确认                                                |
| Cursor Free 套餐      | Free 套餐通常无法调用 Agent 模型，状态行需提示                                                                                                                         |
| Claude 未完成验收     | 工单系统已实现但真实账号授权、刷新、运行与用量验收未完成；Chaya 跟进时需自行验收。macOS 钥匙串搬运增加复杂度                                                           |
| Gemini 未完成验收     | 已按工单系统改用 Antigravity CLI（安装：`curl -fsSL https://antigravity.google/cli/install.sh \| bash`），伪终端依赖 `@lydell/node-pty`；真实账号授权与 App 打包待验收 |
| 刷新回写              | 远程授权凭证的 refresh token 会轮换，回写遗漏会导致过一段时间后授权失效；并发运行需串行化回写                                                                          |
| 已登录 CLI 也要再授权 | Codex / Claude / Gemini 不复用本机登录，玩家即使 CLI 已登录也需在 Chaya 再授权一次                                                                                     |
| 依赖与版本            | 需锁定 Cursor `agent` / `codex` / `claude-agent-acp` / Gemini CLI 版本；Codex App Server 登录接口不匹配时直接报「协议不支持」，不退回解析终端输出                      |
| Codex 模型列表        | 受控模型列表取值，是否跟随工单系统默认（`gpt-5.6-sol`）                                                                                                                |
| 旅伴常驻会话          | 空闲关闭时长与额度冷却时长                                                                                                                                             |
| 托管额度消耗          | 每个周期都是一次 CLI 请求；5 秒起步、无动作加倍到 60 秒的间隔是否合适需实测                                                                                            |
| 意图分类延迟          | 冷启动 CLI 做分类可能要数秒，玩家会感到「发出后迟迟没反应」；若实测过慢，改为默认按询问处理、由 Agent 在询问中建议切到托管                                             |
| CLI 内置工具关闭      | 各 CLI 能否完全关闭内置终端 / 文件工具不一致；关不掉的只能靠拒绝权限请求与空工作目录兜底，需按锁定版本逐个验证                                                         |
| Cursor 加载本机配置   | Cursor 不能换主目录，`agent acp` 可能加载玩家的全局 MCP 服务、规则；需确认能否关闭，关不掉时只能靠拒绝非 Chaya 工具调用兜底                                            |
| CLI 人设压制          | CLI 自带编程助手人设，旅伴角色扮演与「只用游戏工具」的约束可能不稳定；需逐个 CLI 实测 Prompt 投放方式                                                                  |
| 多个 Chaya 进程       | 开发服务与 App 若指向同一数据目录，进程内锁挡不住两边同时用同一份凭证；需文件锁，另一进程占用时提示「该实例正在另一个 Chaya 中使用」                                   |
| 平台范围              | 与 Chaya App 支持的平台一致；Windows 需处理 `.cmd` 启动与进程树结束，Claude 钥匙串搬运仅 macOS                                                                         |
| 资源占用              | 每个 CLI 会话是独立进程（百 MB 级内存），需限制同时运行的会话数                                                                                                        |

## 13. 验收清单

- [ ] 四种类型可新增、编辑、删除，并与游戏插件同步（远程授权凭证不同步）；旧版插件不丢失、不覆盖任何实例。
- [ ] 游戏内任务的归属不变：工具在游戏内 Host 执行，输入占用、卡片、确认、停止与 Ollama 实例一致。
- [ ] 意图分类超时或失败时按询问处理；托管周期复用同一会话并按间隔退避。
- [ ] 授权方式由类型决定：Cursor 只有本机登录，其余三种只有远程授权，表单不提供切换。
- [ ] Cursor：状态检测不发起登录；重新登录可取消且取消后原登录仍在；同时只能有一个 Cursor 登录进行中。
- [ ] 远程授权：可在另一台设备完成；取消或失败后旧凭证仍可用；同一实例不能并发授权。
- [ ] 远程授权全程不读取、不修改本机 Codex / Claude / Gemini CLI 的登录，也不写系统钥匙串（Claude 搬运后清理）。
- [ ] 远程授权凭证静态只存密文；运行时明文目录在最后一个会话结束后删除；刷新后的凭证正确回写。
- [ ] 注销、重新授权、删除实例、切换类型、Cursor 重新登录后，旧会话与任务立即结束。
- [ ] 对话历史与 Ollama 实例一致；新对话、切换角色或模型后不沿用旧 CLI 会话。
- [ ] 工具集合与同入口 Ollama 实例一致（网页侧栏含 Agent 管理工具、改数据分类）；无进展保护照旧。
- [ ] Cursor 实例不会用到玩家本机配置的其它 MCP 工具。
- [ ] 运行任务时永远不会自动发起登录或授权。
- [ ] CLI Agent 只能使用本轮允许的 Chaya 工具，内置终端 / 文件 / 联网请求被拒绝。
- [ ] 工具次数、步数、时长上限由服务端强制。
- [ ] 停止后不再执行任何工具，进程在 2 秒内结束。
- [ ] 玩家卡片在这四种实例上正常等待与回传。
- [ ] 未登录、授权失效、额度用尽、模型不可用都有明确提示，且不会刷请求。
- [ ] Cloud 与插件独立运行时明确不可用。
