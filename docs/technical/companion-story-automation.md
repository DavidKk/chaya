# 旅伴全托管剧情推进实现与后续方案

> 有效范围：现行，2026-11-08。覆盖 MV 插件的 `story_custody`，以及托管模型请求、任务生命周期的相关边界；不改变独立自动战斗、游戏编辑或加速工具的契约。
>
> 实现进度：本轮修复已通过自动化回归；尚未完成首存档实机通关验收。已实现持久化失败记录和有界多步技能路线，实机证据见 [Map 6 基准记录](companion-story-map6-benchmark.md)。需求见 [剧情托管需求](../companion-story-automation.md)。
>
> 替代关系：覆盖本页旧稿中的自动新游戏、强制快进、额外推进引擎、随机方向脱困和全局进程强杀设计；这些内容不能作为当前执行依据。

## 1. 审查范围与判断

本轮审查覆盖当前未提交改动，并结合未推送提交检查剧情托管执行、战斗与菜单、任务停止、模型供应商调度及面板状态。优先修复能够从代码和回归测试确认的执行错误。

当前主要问题来自三个环节：把“输入已提交”当成“目标已完成”、失败状态在重新规划或切图时丢失、执行器跨过正常菜单与控制权边界。这些问题会使同一个错误决策被不断重复，也会让规划器拿到错误的成功记录。

本轮完成：

| 问题                             | 当前处理                                                                      |
| -------------------------------- | ----------------------------------------------------------------------------- |
| 宝箱弹出选项后提前记为成功       | 保留待结算目标，等对话与解释器结束，再核对开箱页或实际收益                    |
| 开箱失败、循环后重新清空限制     | 按地图保留失败与循环抑制，正常、引导、兜底、模型目标和执行入口共同检查资格    |
| 技能未达标仍反复挑战             | 标杆适配记录当前页最低开锁要求；技能跨过记录门槛后重新评估并提高优先级        |
| 发现陷阱被误认成已拆除           | 揭示陷阱作为中间结果，继续评估当前页；完成须有拆除状态或技能增长证据          |
| 切图或读档污染记忆               | 结果归属原地图；只用当前地图事件刷新对应上下文；更换存档对象时重置记忆        |
| 菜单切场景、战斗输入绕过正常流程 | 等待异步场景和实际激活窗口，通过可用命令的 `processOk` / `processCancel` 操作 |
| 玩家接管后旧异步结果继续执行     | 每轮动作取消信号、运行代次隔离；取消后的模型结果不得再提交游戏动作            |
| 战斗过快、死亡后继续假运行       | 剧情托管不额外推进引擎，不自动复活；死亡结束任务，连续相同异常触发停止        |
| 模型配置与执行不一致             | 托管决策按供应商分发，并加入共享资源队列；保留格式、温度、输出和超时参数      |
| 执行器退出后状态仍显示运行       | 持续任务的执行器异常退出产生失败；外部任务轮询识别终态并清理等待              |

## 2. 运行边界

`story-runtime.ts` 负责场景仲裁、暂停和动作生命周期；`story-driver.ts` 负责自然阅读与分支；`story-exploration.ts` 负责候选目标与资格检查；`story-actions.ts` 负责执行结果结算；菜单、战斗与输入分别位于 `story-menu.ts`、`story-battle.ts`、`story-input.ts`。

游戏状态和事件指令只用于读取事实。剧情托管的执行边界如下：

- 移动通过画布上的地图点击输入，逐段检查场景和事件中断；不直接修改玩家坐标或调用底层移动。
- 交互通过正常确认输入；道具和装备通过菜单、分类、物品、角色、装备槽等实际窗口完成。
- 对话等待正常文字显示和阅读停顿，再提交确认；不强制结束消息或设置快进标志。
- 战斗读取实际激活窗口，选择可用的攻击、技能、道具、防御或逃跑；不写入战斗动作，不额外调用战斗或场景更新。
- 玩家已打开的菜单交还玩家操作；标题页等待选择存档，不自动创建新游戏。
- 不修改 HP、物品、任务变量、开关或死亡结果；不扫描并终止无关游戏进程。

窗口命令必须处于激活且可用状态。菜单场景切换是异步的，不能在提交命令后立刻假定下一个场景已经可操作。装备和道具使用还需核对实际效果，避免把一次确认当成成功。

## 3. 失败记忆与重新规划

事件交互分为提交、等待、结算三步。遇到选项或事件拥有的场景切换时保留待结算信息，包括原地图、事件页、技能与收益快照。宝箱的打开页或物品、金币增长可作为完成证据；只发生文字播放或选择变化不能算开箱成功。

标杆适配读取当前事件页中的难度设置，避免从未激活页读出未来门槛。随机难度在静态扫描时只作为最低要求；进入选项时读取本次实际要求。上下文向模型提供记录的门槛与当前技能，供其选择其他目标。

失败与循环记录按地图保留。首次确认交互失败或无预期效果就排除目标；尚未结算出失败的连续相同目标或重复多目标周期由循环检测补充抑制。技能跨过记录门槛时重新评估对应限制。重新扫描、模型返回目标或切图不会直接清空限制。

返回来时地图的出口在当前运行上下文中持续受限，不再在两分钟后自动放行；玩家明确要求回程时才重新评估，原有游戏失败记录仍独立生效。变量指定目的地图和公共事件中的标准传送指令也参与判断；目的地图明确是前进方向时，不因靠近入口而误判成回程。当前机制尚不支持完整的跨地图依赖与回程计划，重载后也不能保证恢复入口关系。

`story-transfer.ts` 读取当前事件页及有界公共事件调用，解析标准传送、变量目的地图和选项所属分支。候选扫描先识别跨图事件，避免对话或奖励将楼梯归类为 NPC 或宝箱。默认将本地图候选放在出口之前；模型候选和执行入口也执行同一顺序约束，不能借标杆目标或路径前置事件绕过。

`story-guidance.ts` 按时间顺序保留的玩家文本解析方向、停留与回程限制；否定句不参与目标加分。宿主将原始请求传入任务，运行时持续保留目标与后续指示，不因超时或一次成功而消耗。新指示递增控制版本并取消选择、导航和解谜请求，旧响应不能继续执行。`story-choice-policy.ts` 在实际等待消息的解释器指令表中定位选项，阻止违反限制的传送分支，并结合当前问句处理“上楼吗？是 / 否”。无合规选项时单独报告路线冲突，不写入游戏失败记忆。

路线限制使用中、英、俄常见表达及标准事件指令作确定性保护；无法确认方向的出口在禁止某方向时保守排除。脚本或插件内部的隐式传送、任意自然语言的复杂条件尚不能通用识别，不能宣称已经完整理解所有玩家指令。

失败记录由共享账本与浏览器本地存储保存，停止后重新托管不会清除。持久化键包括游戏身份以及可验证的游玩记录版本与标识；没有游玩记录身份时，退回原生存档槽与时间戳。每条记录包含地图、事件、原因、结果证据、首次与最近失败时间、次数以及重试条件；一个事件可以保留多个已失败条件快照。第一次确认失败即排除该条件下的目标，普通扫描、玩家引导、模型目标、兜底和执行入口都不能绕过。

重新评估依据是相关事实：事件页、页条件、标准条件分支及公共事件读取的条件、所需道具、已知技能门槛、阻挡事件状态。技能从 1 升到 2 不能解除 11 级门槛；道具数量或无关变量变化、走远、切图、等待也不能清除失败。事件自己写入的临时难度变量不作为恢复资格的证据。旧条件再次出现时，仍会命中旧失败记录；有确切永久失败证据的记录可以禁止任何条件下的重试。

选项按实际等待消息的解释器所属事件、当前问句与解释器命令路径隔离；嵌套公共事件与路途中触发的事件不使用规划目标冒充所有者。选项内容用于识别失败标签，重新排序不会恢复失败选项。模型返回后仍需核对问句、事件、窗口与控制权；只有游戏菜单实际接受确认才登记待结算，失效响应和禁用选项不计尝试。

待结算选项保存在当前运行实例，防止相同条件下连续重复；结果确认失败后才持久化。目标成功时解除本次所有待结算选项，保留已确认的其他失败分支。非规划目标触发的选择，也在事件空闲时根据所属事件的相关事实变化结算。旧 `outcome-v2` 标签无法区分“曾选过”和“确实失败”，不参与新键 `outcome-v3` 的决策；原有事件失败、门槛与永久失败证据保留。分支耗尽时优先通过游戏定义的菜单退出选项离开，并将当前事件记为无效果后改走其他路线；没有安全菜单出口时才暂停，报告具体事件。无效果的普通调查也进入阻止重复的记录，避免兜底反复调查已读物件。未由事件拥有的超时按失败记录，主动取消、需要输入和场景切换仍按中断处理；已正常前进但尚未到达目标属于接近中，不记为失败。

这份账本不写入游戏状态。同一持久化身份重载时恢复记录；不同游戏与不同存档作用域隔离。原生槽的存档时间戳改变后会进入新作用域，新游戏的临时身份迁移到首次保存身份也尚未完整实现，不能宣称任意保存、读档与迁移都保留同一历史。脚本与插件内的隐式条件尚不能通用解析；无法证明相关条件变化时保持受阻，不靠等待或模型建议重试。

技能路线最多保留四条，每条训练链最多十六步。依据当前技能、可读的最低难度与预计技能增长，串联训练目标和达标后回访目标；经验不足的路线明确标记不完整，每步结果不符即重新规划。预期增长与曼哈顿距离只用于估计，不能替代实际收益和通路检查。导航在地图范围内搜索，当前目标为实体障碍时不穿过它；事件边界前置探索最多展开三十二个事件并防止依赖环。

交互执行抛出的程序异常不再作为游戏失败返回规划器：立即停止托管，在日志中保留地图、事件、错误消息与堆栈，不触发模型解谜。历史中旧版本保存的 `error` 记录仅用于诊断，不封锁目标。热更新会保留全局账本，因此新增的临时 `pendingChoices` 字段在读取入口补齐，避免旧实例在结果结算时访问不存在的 Map。

## 4. 战斗与控制权

战斗按引擎原有节奏运行。当前策略优先照顾受伤的存活队友；生命比例不高于 65% 时评估治疗，低于 35% 且无可用恢复手段时评估逃跑。窗口不可用或动作被禁用时尝试其他正常命令，不重复提交同一个不存在的技能或道具。

地图恢复优先选择生命比例低于 75% 的队友，并区分 HP 恢复与 MP、敌方或复活效果。自身范围道具必须匹配实际使用者；某道具在菜单不可用时继续评估其他候选。

以上是保守规则，不包含敌人伤害预测、治疗资源预算、撤退路线成本或全技能战术搜索。阈值通过测试不等于实际战斗的生存能力已经达标。

停止、玩家接管和读档会取消当前动作。宿主只运行一次托管实例，不因退出自动重启。交互执行异常立即停止；其他外层运行异常在 15 秒内相同错误达到三次时停止并给出原因，避免静默无限重试。

## 5. 下一步方案

按依赖顺序推进，每一步都需要可复现的验收样例：

| 优先级 | 方案                                                                                           | 验收条件                                                                                                                     |
| ------ | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| P1     | 建立事件的前置条件与效果契约：技能、道具、开关、事件页、预期收益、失败原因、证据与重新评估条件 | 1 级遇到 11 级宝箱时说明原因并换目标；到 11 级后重新评估；无关变量随机变化不会伪造任务进展                                   |
| P1     | 在现有有界技能路线之上补齐跨地图依赖、真实路径成本与资源预算；保留可行备选                     | 能给出“拆低级陷阱 → 开低级箱 → 技能达标 → 返回目标箱”的实机完成证据；必要回程不变成楼梯循环                                  |
| P1     | 用第一个存档建立真实游玩基准与检查点记录                                                       | 正常点击和菜单推进；记录初始状态、行动、结果与状态差异；完成三箱试炼、四份赐礼及最终赐福；死亡、人工干预和未完成必须如实计入 |
| P2     | 增加生存预算与恢复失败记忆，估算近期伤害、药品和退路，限制低血探索风险                         | 缺少恢复手段时停止冒险并说明原因；菜单效果无变化时换方案；统计死亡和资源耗尽                                                 |
| P2     | 输出结构化的状态严重度、受阻原因、当前计划与替代计划，替换面板按提示文本猜测危险状态           | 能明确显示“技能不足 / 缺道具 / 不可达 / 循环已阻止 / 等待玩家”，且与实际任务终态一致                                         |
| P2     | 将标杆硬编码流程逐步替换为可验证的事件事实与地图关系                                           | 标杆知识只保留适配层；其他游戏不会读取同 ID 的任务变量或剧情规则；模型不能绕过候选资格                                       |

多步规划不能只把当前候选列表改名为“多条路线”。每条计划需要包含前置条件、步骤、预计收益、代价、退出条件与替代步骤，并在实际结果不符时失效重算。

尚待解决的具体限制包括：脚本与插件隐藏的钥匙、任务和通路条件尚不能通用提取，无法识别时会保守维持受阻；失败记录在原生存档时间戳变化和首次保存时的身份迁移尚不完整；标杆 Map 6 未形成全地图资源账本；持续托管尚不能把最终赐福自动等同于所有后续剧情结束。

## 6. 验证与实机验收

自动化覆盖菜单异步切换、不可用动作、真实点击移动、选项所有权、待结算开箱、陷阱揭示、技能门槛、候选切换、循环抑制、跨地图与读档隔离、模型取消、资源队列和任务退出。类型检查和插件构建用于检查服务端、MV 与 RGSS 的集成。

实机基准必须从用户授权的第一个存档开始，记录存档标识、初始地图和任务状态。不得通过编辑 HP、给予道具、修改变量或开关、移动坐标、跳过战斗等方式构造通过结果。

标杆最终赐福以开关 30 / 683 等游戏实际状态结合事件日志确认；24 / 25 等中间教学标记不能代表通关。应记录有效交互、无效重试、循环拦截、模型调用、重新规划、死亡、人工干预及总用时。未完成这轮实机验收前，不宣称“全自动通关已验证”。
