# 翻译缓存结构化分段与缓存测试技术设计

- 状态：首期实现；任意边界拖拽、嵌套编辑及复杂控制码跨项拆分留待后续。
- 日期：2026-10-17。
- 需求：[结构化分段优化方案](../translation-structured-segmentation.md)。
- 关联：[语义分段与安全复用](translation-cache-optimization.md)、[翻译管线](translation-pipeline.md)。

## 1. 现有基础与本轮缺口

当前纯规则层包含 `sentence-units.ts`、`logic-text.ts` 和 `sentence-plan.ts`；共享缓存有记录版本、匹配索引及 confirmed 映射，插件 Store 已接入句段规划。`SentencePlan` 使用 `full / partial / miss` 表示覆盖状态，另有 `ambiguous` 与 `limited` 标记。

此前规则版本为 4，主要围绕标点、逻辑换行和已有映射生成单元。本轮升级为 6，增加标签、项目正文及 literal 布局，并让确认校验与匹配索引使用相同边界。

本轮扩展纯规则、确认校验、索引和诊断查询四条路径，不替换原始定稿存储，不改变写入秩和语言对约束。

## 2. 不变量

1. 原始文本和主键不改写，偏移统一为原文 UTF-16 半开区间 `[start,end)`。
2. 编号、分隔符、空白、换行和控制码均有明确归属；按布局重建原文必须逐字相等。
3. 列表结构证据与译文对齐证据分开。自动结构识别不能自动产生 verified 原译映射。
4. 标签、名词项目和条件均可作为完整单元；不能退化为任意词、字符或数字覆盖。
5. 整段可用结果优先；结构拆分只增加合法候选，不绕过人工保护、来源秩和歧义检查。
6. 单元、映射和派生索引绑定规则版本及定稿 revision；过期即重新校验。
7. 测试查询不调用模型、不写定稿、不回填本作、不增加命中计数。

## 3. 结构模型

共享纯函数模块 `lib/translate/structured-segments.ts` 提供结构扫描、候选分段和无损布局，当前类型如下：

```ts
type StructureSpan = { start: number; end: number }
type StructureAnnotation = { mode: 'accept' | 'disabled' }
type RecordStructure = { source?: StructureAnnotation; target?: StructureAnnotation }
type StructuredUnit = StructureSpan & {
  id: string
  kind: 'text' | 'label' | 'item'
  ordinal?: number
  state: 'accepted' | 'suggested'
}
type StructuredDocument = {
  units: StructuredUnit[]
  layout: Array<StructureSpan & { kind: 'literal' | 'unit'; unitId?: string }>
  diagnostics: Array<StructureSpan & { code: string }>
}
```

单元区间指向完整正文，不包含前置编号。`text` 保留列表前的说明段；标签和项目外部的编号、冒号、空白及分隔逗号归 literal。布局按原始顺序连续覆盖全文。`id` 由区间生成，只在同一文本快照内使用。

核心案例的布局为：

```text
unit(解锁条件)
literal(：①)
unit(等级60以上)
literal( ②)
unit(再次进行VIP特典工作)
```

命中时仅替换对应 unit。literal 按查询原文输出；译文中的原列表编号不能被二次带入，确认映射或满足下述严格编号对应条件时，仅复用目标正文。

首期遇到带参数的 RM 显示控制码或 HTML 时不启用结构拆分，返回 `protected_token`，保留现有整段／短句规则。URL、占位符和数值 token 内不扫描编号；引语及括号内部编号不作为外层标记。跨项目控制作用域解释和代码表达式解析尚未实现。

## 4. 识别流程

### 4.1 先保护，再扫描

1. 保护 URL、HTML、RM 控制码、替换槽及多段数值 token。
2. 按括号和引语层级扫描冒号、编号、项目符号，保留标记原貌。
3. 同层标记组成平面候选组，划分说明段、标签及项目正文。
4. 生成覆盖全文的 literal / unit 布局；项目内部沿用逻辑换行解释。
5. 检查同族、连续顺序、非空正文及项目上限，输出 accepted 或 suggested。

不能先删除换行、标点再找编号；行首、空白和编号作用域是必要证据。行内中点始终先输出 suggested，避免把多段人名直接自动接受。

### 4.2 标记族

| 标记族     | 初期格式                                       | 必要检查                                                 |
| ---------- | ---------------------------------------------- | -------------------------------------------------------- |
| 阿拉伯数字 | `1.`、`1、`、`(1)`、`（1）` 及常见全角变体     | 不是小数、版本或数量内部；同组格式和顺序一致             |
| 罗马数字   | `i.`、`ii.`、`I.`、`II.`、`Ⅰ`、`Ⅱ`，含括号格式 | 合法罗马数值；连续编号组；不在普通名称或英文单词内部     |
| 圈号       | `①` 至 `⑳`                                     | 同组顺序、相邻项目非空；显示字形原样保留                 |
| 项目符号   | `·`、`•`                                       | 行首或清晰并列结构；中点人名和词内使用保留歧义           |
| 弱分隔编号 | `i … ii …`、`1是什么 2是什么`                  | 默认建议；人工或来源声明确认后才作为独立边界             |
| 标签       | 当前组前的 `：`、`:`                           | 冒号后存在列表证据；标签非空；不是时间、URL 或表达式内部 |

仅在识别标记时做局部数字／字形归一化，得到 ordinal；不对整个正文做 NFKC 或替换，也不把显示编号变成持久化主键。罗马数字解析采用有界的合法形式校验，不用任意 `[ivxlcdm]+` 匹配英文子串。

同组通常至少两个项目，编号严格递增且格式相同。缺号、重复和混合编号输出建议；单个孤立编号保留原文，不构造列表。空项目使整个候选组失效。

### 4.3 项目完整性与层级

正文范围为当前标记结束至下一同层标记开始，中间的真实内容全部保留。只把明确属于分隔布局的外部空白移到 literal，不能 trim 掉正文内部有意义的空格。

识别清晰结构不等于自动证明语义完整。对于 `1. 如果满足` 接 `2. 就执行` 等有依赖的特殊文本，提供合并操作；人工否决边界需随定稿保存，后续不能被自动扫描反复覆盖。第一版不依赖关键词词典判断跨语言语法。

括号、引语和受保护范围按层级扫描；内部编号不终止外部项目。第一版处理平面组；括号或引语内部的编号保留在父项目正文中，不静默展平。多层列表编辑和专用嵌套诊断后续扩展。

## 5. 与现有单元及匹配规划衔接

`sentence-units.ts` 使用共享结构边界描述，不在优化页、服务端、插件中各写一套拆分规则。结构项目成为一级完整单元；标签和项目边界可由规则解释或明确人工确认。

一个列表整体可按原文整段精确复用；整段不命中时，规划器按结构单元查询。首期每个结构项目作为完整单元，内部软换行继续构建逻辑视图；不继续裁出项目内部短句。不同列表项之间是独立结构边界，不允许普通连续块候选越过；整个列表的精确命中与显式整体映射仍合法。

候选与排序依次经过：语言对、记录版本、人工保护、作用域、结构及对齐合法性、来源优先级、覆盖范围。可用整段优先；随后尽量使用完整合法块，最后使用单个完整项目。歧义不是一个较低分的成功结果。

普通正文从父记录提取译文，仍必须经 verified 对齐定位目标正文。编号列表允许额外的只读复用路径：原译两侧结构均自动接受、无诊断、至少两个项目、项目数相等且每项 ordinal 一一对应时，可复用完整项目及对应标签；缺号、重复、混合格式、无编号的项目符号或受保护文本不走此路径。它不按普通句子数量猜测对齐，也不裁切项目内部短句。

此类结构片段只作为带原记录 ID / revision 的临时候选，不新增定稿、不写入确认映射。相同范围先遵循本作作用域，再优先独立记录或已有显式映射；结构候选优先使用没有额外说明段的专用列表，并继续遵循来源秩和歧义策略。目标端 `①.正文` 中附随编号的点不带入译文，最终编号、标点与空白仍采用查询原文。

部分命中逐段回填，缺口逐段保留原文。例如 `解放条件：①レベル60以上 ②再度VIP特典の仕事をする` 仅命中标签与末项时，预览为 `解放条件：①レベル60以上 ②再次进行VIP特典工作`，不能因中间缺口而丢弃前后命中。

完整、部分、未命中沿用 `SentencePlan.status`；歧义和受限分别通过 `ambiguous`、`limited` 及诊断解释。测试页不得把“有候选”显示为“可复用”。

## 6. 注解持久化与对齐确认

在现有记录 ID、revision 和映射机制上增加 source / target 两侧的模式注解。使用独立的 `structure_annotations` 表，不修改 `translations` 的原始正文主键。

自动规则结果可重建，不必逐条永久保存；人工接受建议或禁用拆分必须保存并优先于规则推断。首期注解为 source / target 两侧的 accept 或 disabled 模式；任意拖拽边界和嵌套编辑后续实现，现有原译分组仍可编辑与合并。来源声明必须绑定精确快照，不能跨文本或版本套用。

`/api/translate-cache/optimize` 已接受 `structure`、`expectedRevision` 和 `replaceGroups`。服务端使用当前规则重新扫描与验证。修改边界模式时，优化页提示保存将替换旧映射，预校验与提交均携带 `replaceGroups: true`。关闭任意一侧拆分时，清空映射并只保存模式注解。

校验至少包括：

1. 父记录、正文快照、语言对和 revision 一致。
2. 标注指向合法原文区间，layout 覆盖完整且能重建原文。
3. 人工边界完整、无重叠，不破坏 token、控制作用域或已保护区域。
4. 原译正文映射单调、无重叠；目标端编号和正文位置明确。
5. 一对多或多对一作为完整映射块保存，没有内部映射时不单独裁出其中一项。
6. 预校验与提交执行同一验证器；整批原子写入，错误逐项返回。

`validateAlignments` 需要接受经验证的结构正文边界，而不是简单放宽为任意字符区间。成功后同步更新结构注解、对齐、索引与失效事件。正文改变后旧注解及其索引失效，重新加载后重建。更新译文时重新验证目标偏移，不能复用旧编号位置。

本作 `CacheRow` 携带结构注解，回填、读取和插件 Store 均传递同一数据；共享来源记录仍按 origin revision 校验。正常共享库初始化会重建 v6 派生索引，诊断入口自身不会迁移。

## 7. 缓存测试接口与页面

### 7.1 入口

- 页面：`/translate/test`，从缓存内容头部最右侧进入；GameEdit 浮层保留运行和缓存两个入口。
- 接口：`POST /api/translate-cache/test`，通过现有 `defineApiRoute` 和 API 信封注册。
- 首期运行范围：有磁盘缓存访问能力的本机服务或 App。Cloud 独立离线游戏测试后续接入，不展示成可查询本机共享库。

服务逻辑置于 `services/translate/cache-diagnostics.ts`，页面置于翻译功能目录。页面、优化预览、接口和插件调用同一纯规则与 planner。

### 7.2 查询契约

```json
{
  "text": "解锁条件：①等级60以上 ②再次进行VIP特典工作",
  "from": "zh",
  "to": "ja",
  "scope": "shared",
  "structure": { "mode": "accept" }
}
```

`scope` 为 `shared / game / combined`。游戏范围通过库 ID 解析并校验，不能接受任意文件路径；未绑定或游戏已变化时返回明确错误，不悄悄换到另一个游戏。`from / to` 显式使用现有语言代码集合。本作记录缺少语言对元数据，首期 game / combined 只允许 to=zh，并按 detectCacheLang 过滤源侧；其它方向只查询共享库。上例用中译日说明输入结构，与当前补译引擎默认方向分开。

`structure` 可省略，表示自动规则；`accept` 接受本次扫描建议，`disabled` 使用整段。它仅影响本次测试，不保存。game / combined 额外携带当前选择的 `gameId`。

当前上限：单次 20,000 个 UTF-16 code units、200 个结构项目、500 个去重候选。所有上限写成共享常量并返回截断或拒绝原因，不能因截断而误报 full。界面输入变化时取消旧请求并清空旧结果，提交时校验请求序号，避免旧结果覆盖新输入。

### 7.3 返回诊断

返回 query 快照、语言对、范围、规则版本、语料版本、结构布局、候选数、拼接预览及 `SentencePlan`。命中明细包含记录 ID、revision、来源、匹配方式及原文范围。未命中范围由 gaps 返回；首期不逐条展开所有被拒绝候选和目标偏移。

结构诊断代码包含 `ambiguous_marker`、`invalid_sequence`、`protected_token`、`candidate_limit`；匹配诊断包括 `missing_alignment`、`ambiguous_translation`。版本、游戏切换和索引未就绪通过 API 错误码返回。`missing_alignment` 是候选级提示，不表示已证明每个缺口均由映射缺失造成。

共享库以只读 SQLite 事务读取一致快照；本作文件以内容指纹校验读取前后状态。查询前后验证语料版本；发生修改时返回 stale 并让用户重试，不把不同版本拼成一个完整结果。本作记录无全局版本时，对本次加载的文件快照和来源依赖做校验。

部分命中时单独返回缺口和带标记预览，`plan.zh` 保持其既有完整性语义；不能把“缺口仍是原文”的展示字符串冒充完整译文。编号、分隔符不计为翻译命中，覆盖率以完整可翻译单元说明，字符范围只用于高亮。

### 7.4 只读约束

测试接口调用纯 planner 与不会增加 hitCount 的查询方法，不复用会自动推理的 live 翻译入口，也不调用 backfill、补译任务或写入队列。不能为了显示结果调用带计数副作用的 get。

数据库迁移、索引构建在正常服务初始化或独立维护流程完成；诊断请求发现索引尚未就绪时返回状态，不在用户点击测试时修改语料。测试接口遵守管理访问校验；游戏启动凭证不得获得任意共享库诊断和其它游戏文件访问权限。

## 10. 日文读点与优化边界

日文 `、` 按句内读点参与候选分段，与逗号使用相同的边界类型；它不能单凭形状证明是中文并列项目。优化预览与句段规划共享 `sentenceBoundaryAt`，保留各侧原始标点，原译对应仍须人工确认。

连续 ASCII／全角句点视为省略号，不单独截断。没有闭括号的行首圆括号视为游戏跨消息延续的外壳，保留其原始显示位置，同时允许内部逗号和读点生成候选；成对括号与引语内部仍受保护。规则升级至 6，正常初始化时重建索引，诊断请求不承担迁移。

- 路由辅助函数放入既有 `components/translate/tabs.ts`。生成调试地址时，从当前输入框取得最新搜索词；若与已提交查询不同，将分页重置为第一页，再将列表相对路径及完整 query 编码到 `returnTo`，并从合法语言筛选初始化调试语言。文本内容不写进 URL。
- 返回路径只接受 `/translate/cache` 及其 query，不接受外站、详情页、协议或任意路径。直接访问和非法参数退回 `/translate/cache`。返回使用显式地址，不能依赖可能离开应用的 `history.back()`。
- `CacheTestView` 通过 `useSearchParams` 读取导航参数，继续位于现有 `Suspense` 下。`PanelHeadStart` 注入返回按钮；测试页标题及四语言文案改为缓存翻译调试。
- `TRANSLATE_TABS` 保留 test 以兼容路由解析及旧链接；侧栏过滤 test，并在该页面将 cache 标为当前分区。调试页头部需要保留 `PanelHeadStartHost`。
- 调试结果显示候选数与规则版本；查询开始立即清空旧结果，沿用请求序号、取消、语言对和磁盘能力限制。它反映现有 planner 的只读查询结果，不承诺引擎补译后的输出。

### 文档 CR 结论

审查已补齐三个实现风险：避免重复测试页面与侧栏入口；对 `returnTo` 做内部路径白名单校验；窄屏把筛选滚动区与固定操作按钮分开。现有只读接口及语言限制满足本轮范围，可进入开发。

验证覆盖路由生成与返回参数白名单、语言预填、返回链接、导航选中态、入口顺序及旧请求隔离。浏览器检查 Tooltip、进入／返回、真实查询和窄屏按钮位置；运行相关测试、Lint、类型检查及构建。
