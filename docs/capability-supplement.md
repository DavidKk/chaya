## 1. 背景与目标

主功能大多已落地。本波不扩新产品面，把能力补齐与所有相关失败路径的恢复合为一个大需求。A–H 是实现分区，不是可独立宣称完成的产品需求；任一能力若在超时、断线、切换、停止或异常后可能永久占用页面 / 游戏 / 操作锁，均视为该能力未完成。

本波做五类事：

1. **命名澄清**：减少维护者把云端构建误读成 Next Edge Runtime。
2. **边缘兼容**：浏览器前提不满足、浏览器模式未连游戏时仍能完成合理操作或得到明确说明。
3. **现有能力收尾**：存档快捷键同步与本机离线只读列表；地图事件撤销与批量。
4. **Agent 运行时统一**：三份核心循环合为一份共享代码；托管宿主固定在 ext，控制台问答留在所在端；三端都可发起、续看和停止托管，托管不放开危险捷径。
5. **流程可恢复**：任何新增流程都必须成功结束，或在失败后释放资源、说明状态并允许玩家重试、停止、重连或重载恢复。

| 目标 | 玩家 / 维护者可感知的结果                                                                                                                          |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| G1   | `cloud` / `remote` 语义清晰；代码、接口、脚本与文档统一使用 v1 名称                                                                                |
| G2   | 非安全上下文 / 浏览器不支持目录访问时，选目录与写盘入口有原因说明，不是无声失败                                                                    |
| G3   | 浏览器模式授权读盘后，未连游戏也能浏览地图与事件索引                                                                                               |
| G4   | Web 控制台与游戏内改的快速存档快捷键双向同步；本机未连游戏可只读看存档列表                                                                         |
| G5   | 地图 / 公共事件页可撤销最近的可还原改动；事件表可批量切独立开关 / 满足条件                                                                         |
| G6   | cloud / local / ext 三端都能让 Agent 托管，由 ext 内同一运行时执行；关面板 / 关网页不中断；能看到暂停 / 进展 / 停止原因；托管仍禁止修改 / 脚本捷径 |
| G7   | A–H 的加载、同步、批量、撤销与 Agent 流程不会永久卡在中间态；异常后可恢复操作，迟到结果不会破坏新状态                                              |

### 1.1 全局防卡死约束

- 所有跨网页 / 本机服务 / ext 的请求都必须有请求 ID、超时和结束态；成功、失败、取消、超时、断线均在 `finally` 中释放页面 busy 状态与运行时锁，不允许按钮永久停在「处理中」。
- 页面切换游戏、切换数据源、断开或重连时，取消旧请求；无法真正取消的请求用「游戏 ID + 连接代次」隔离，迟到结果只丢弃，不得覆盖新连接的数据或重新加锁。
- 会产生写操作的命令按请求 ID 幂等。调用方超时后可以查询最终状态或安全重试；迟到回复不得造成重复执行、重复撤销记录或重复按键。
- 「停止」、操作所依赖的游戏 / 数据源断开和游戏关闭优先于模型请求、工具调用、重试计时和批量队列。仅网页或本机服务遥控通道断开时，页面结束本地等待，但 ext 任务是否继续按 §8 生命周期执行。进入终止路径后，即使旧 Promise、计时器或通道回复到达，也不得再执行写入或按键。
- 错误只终止当前操作；除游戏进程本身已关闭外，页面、ext 面板和其他功能必须恢复可操作，并提供重试或重新发起入口。
- 上述约束同时覆盖跨端通信与端内异步，包括 File System Access、Node 文件读写、IndexedDB 事务、截图 / canvas、模型流、SSE、WebRTC / GameLink 和插件工具调用；不得因“没有跨端”而省略超时、取消或收尾。
- 自动重连采用有限退避；连续失败达到上限后进入明确的「已断开」状态并停止后台重试，释放等待中的操作，提供手动重连。网络恢复后不得在后台悄悄重放已经失败的写命令。
- 订阅终态可能丢失：页面在订阅中断、重连或等待超时后必须查询 ext 的权威状态，以任务 / 操作 ID 校准本地 UI；不得仅凭本地 `running` / `busy` 永久置灰。
- 「一键清理」先无条件清除本端临时 busy / 订阅 / 计时器，再尽力通知 ext；通道不可达时页面也必须恢复可操作。重连后以 ext 权威状态再次校准，必要时再发停止请求。

### 1.2 完成定义

- A–H 的正常场景验收通过。
- 对应的超时、取消、断线、切换、重复请求、迟到回复和进程 / 页面重载场景同时通过；不得以“后续稳定性优化”拆出本波。
- 不允许新增无上限同步循环、同步等待或大文件整块处理。Chaya 自身的循环与批处理必须分片让出主线程；文件在读取和解析前校验大小上限；IndexedDB 与文件操作失败或超时后进入可重试状态。
- 浏览器原生目录选择器无法由页面强制关闭，因此选择器 pending 时只锁当前选择动作，不锁页面或其他能力；切页、切游戏或断线后忽略其迟到结果。用户关闭选择器后入口立即恢复。
- 若第三方游戏脚本已把 JavaScript 主线程硬冻结，页面代码无法执行停止或超时。本波要求 Chaya 不引入此类阻塞，并保证重载游戏后把未完成任务标为「已中断」、清除所有持久化运行锁；宿主重载是该场景的最终恢复路径。

- **配置只认新值**：`CHAYA_SERVICE` 仅接受 `local` / `app` / `remote`；变量未设置时沿用本版默认值，设置为其他值时直接报配置错误，不做别名识别或自动转换。`cloud` 构建与 `VERCEL=1` 强制 `remote`，云端不会误开本机磁盘能力。

4. 文档、代码注释与 UI 不再暗示 `cloud` 构建 = Next Edge Runtime。

## 4. B · 浏览器前置条件提示（O10）

### 4.1 行为

需要 File System Access 的入口（选游戏目录、装壳 / 装插件写盘、目录授权读盘等）按**能力检测**判定，不按浏览器标识（UA）判定：

| 检测                                                  | 不满足时说明                             | 建议                                |
| ----------------------------------------------------- | ---------------------------------------- | ----------------------------------- |
| `isSecureContext` 为假                                | 需要 HTTPS 或 localhost 才能访问本地目录 | 改用 HTTPS 地址或 `localhost` 打开  |
| 无 `showDirectoryPicker`                              | 当前浏览器不支持访问本地目录             | 换用桌面版 Chrome 或 Microsoft Edge |
| 调用时报 `SecurityError`（如被嵌入页 / 权限策略禁止） | 当前页面环境禁止访问本地目录             | 在独立标签页直接打开 Chaya          |

- **提示时机**：页面加载时即检测；不满足时入口按钮旁直接显示原因与建议，按钮禁用；运行时才暴露的失败（如 `SecurityError`）在失败时以同样文案提示。
- **替代路径**（仅列已有能力，不新增）：
  - 装壳 / 装插件：引导到下载中心下载安装包手动安装。
  - 选游戏目录 / 读写游戏：引导使用本机服务或 Chaya App。
- 用户主动取消选择目录（`AbortError`）不视为失败，不提示。
- 不改变已满足前提时的成功路径；不新增第二种装壳实现（PowerShell / Linux 命令不在本波）。

### 4.2 不阻塞约束

- 检测只在 `remote` 形态的浏览器模式入口生效。`local` / `app` 选游戏、装壳走服务端，不依赖浏览器目录接口，**不得**因浏览器不满足前提而禁用（例如在 Safari 打开本机服务、局域网 HTTP 访问本机服务都照常可用）。
- 只在检测**确定不满足**时禁用；检测不出（如权限策略只有调用时才报错）一律放行，失败时再提示，不预先拦截。

### 4.3 验收

1. 用 HTTP 非 localhost 地址打开：选目录与写盘入口显示「需要 HTTPS 或 localhost」，按钮禁用。
2. 在不支持 `showDirectoryPicker` 的浏览器（如 Firefox / Safari）打开：显示「浏览器不支持」与换用建议，并给出下载中心 / 本机服务替代路径。
3. 被嵌入页禁止时：操作失败有可读提示，无静默失败。
4. 满足前提时正常完成原操作；取消选择目录无提示。
5. 用 Safari 或局域网 HTTP 地址打开本机服务：选游戏、装壳流程照常可走，无禁用。
6. 打开浏览器目录选择器后一直不处理：其他页面和功能仍可操作；切页或切游戏后再完成旧选择，结果被丢弃且入口可重新使用。

## 5. C · 地图事件浏览器授权读盘

### 5.1 行为

- 适用：`remote` 形态的浏览器模式（含 `cloud` 构建与 dev 切到 Cloud）。本机 `local` / `app` 已有服务端读盘，保持现状。
- 读取范围：`MapInfos.json`、`Map%03d.json`、`CommonEvents.json`、`System.json`（开关 / 变量名），与游戏内、服务端走同一份解析（见 [`edit-map-events.md`](./edit-map-events.md) 数据来源）。
- 目录授权三种状态：

| 状态     | 判定                                                   | 表现                                                       |
| -------- | ------------------------------------------------------ | ---------------------------------------------------------- |
| 已授权   | `queryPermission({ mode: 'read' })` 为 `granted`       | 未连接游戏也可浏览地图树、事件索引、详情与引用关系（只读） |
| 授权失效 | 曾授权，但当前为 `prompt`（常见于刷新 / 重开浏览器后） | 显示「目录授权已失效」与「重新授权」按钮（需用户点击触发） |
| 未授权   | 游戏库中该游戏无目录句柄，或用户拒绝                   | 提示授权，不显示假数据                                     |

- 浏览器不提供 `queryPermission` 时，按「授权失效」处理：每次进入页面需点一次「重新授权」。
- 数据不可读（游戏已打包为单个可执行文件、`data/` 缺失或文件解析失败）：提示「该游戏数据无法从目录读取，请连接游戏后浏览」，不报通用错误。
- 需游戏在线才能执行的操作（执行事件、切开关、传送、撤销、批量等）在未连接时禁用，并说明「连接游戏后可用」。
- 读取结果沿用现有索引缓存；目录内容变化（游戏更新）时按现有缓存失效规则处理。

### 5.2 不阻塞约束

- 游戏一旦连接，数据源立即切回游戏内读取（现有路径），不再用目录读到的数据，避免执行操作基于过期数据。
- 目录读取在后台进行，读取中显示骨架屏，不阻塞页面其他交互；单个地图文件读失败只影响该地图，不让整页报错。
- 目录读取绑定当前游戏与数据源代次；切换游戏、重新授权或游戏中途连接时取消旧读取并忽略迟到结果。读取无论成功、失败、取消或超时都必须退出骨架屏；超时后显示可重试状态。
- 授权弹窗只由用户点击触发，进入页面时不自动弹、不循环弹。
- 本机 `local` / `app` 的服务端读盘路径不改动。

### 5.3 验收

1. `cloud` 构建（或 dev 切 Cloud）+ 已授权目录 + 游戏未连接：可打开地图 / 公共事件并看到索引与详情。
2. 刷新页面后授权变为 `prompt`：显示「重新授权」，点击后恢复浏览。
3. 未授权：明确提示授权；执行类按钮禁用且说明原因。
4. 数据不可读的游戏：显示专门提示，不出现空白或通用报错。
5. 目录浏览中途连接游戏：数据切到游戏内读取，执行类操作可用且结果正确。
6. 目录读取未结束时切换游戏、重新授权或连接游戏：旧读取结果不覆盖新页面，骨架屏能结束并可重试。

## 6. D–E · 游戏存档收尾（第 4 阶段）

### 6.1 D · 快捷键同步

- **现状**：快速存档绑定（`save:quick:N` / `load:quick:N`）属于产品快捷键表（`components/game-edit/run-hotkeys.ts`），不在存档设置 `GameSavesSettings` 里。快捷键表由全局表、本游戏覆盖、暂停列表三部分组成，网页存浏览器 `localStorage`（本游戏覆盖只有**一个槽位，不分游戏**），局内本游戏覆盖以游戏盘为准，两端之间**没有同步、没有 `revision`**。
- **同步范围**：整张快捷键表一起同步，不只同步快速存档子集——两端冲突标注与唤出键校验都基于整表，只同步子集会让两端结果不一致。
  - 全局表、暂停列表：网页一份，与任一连接的游戏对齐。
  - 本游戏覆盖：网页改为**按 `gameId` 分开存**，只与对应游戏对齐。
- **存储格式**：v1 只定义并读写带 `revision` 的格式；其他键名或格式不读取、不转换、不迁移。
- **同步规则**：对齐键鼠配置（见 [`technical/input-assistance.md`](./technical/input-assistance.md)）：两端连接或收到推送时按 `revision` 采用较新的一份并写回本端，较旧一端再下发自己的新版本。
  - 网页改：`revision` 递增，已连接则立即下发；未连接则在下次连接时对齐。
  - 游戏内浮层改：`revision` 递增，已连接时推送给网页，否则在下次连接时对齐。
  - 两端 `revision` 相同但内容不同：以游戏侧为准，避免两端来回覆盖。
- 同步完成后，在游戏内按绑定键能保存 / 读取对应快速槽（仍受「开启快速存档」总开关约束）。
- 快捷键冲突提示沿用快捷键页现有规则，不新增。

### 6.2 D · 不阻塞约束

- **唤出键永远可用**：收到的表先校验再应用；唤出键为空或非法时回落默认反引号（现有 `resolveOpenPanelChord` 行为），唤出键不可进入暂停列表（现有 `canDisableHotkey`）。任何同步结果都不能让局内面板打不开。
- 校验失败（结构损坏、字段非法）的整表**丢弃不应用**，保留本端现有表，并提示「快捷键同步失败，已保留本地设置」；不阻塞连接，也不影响存档、键鼠等其他同步。
- 同步只在连接时与修改时发生，不轮询；对齐过程不阻塞游戏输入，对齐完成前局内沿用本端现有绑定。
- 同步请求超时、断线或校验失败时释放同步中状态，保留本端可用绑定；不得阻塞游戏连接或其他配置同步。下次连接或再次修改时可重新对齐，迟到回复按连接代次丢弃。
- 网页本游戏覆盖按 `gameId` 分开后，切换游戏不会把 A 游戏的覆盖带到 B 游戏。
- **移除覆盖推断**：插件不得用「本游戏覆盖与全局表完全一致」推断没有覆盖（当前位置：`plugins/src/cheat/session/persist.ts`）。否则两表恰好一致时覆盖会被清空、`revision` 对不上，两端会来回覆盖。

### 6.3 E · 本机离线只读列表

- 适用：本机服务形态（`local` / `app`），**未连接游戏**时。
- 看哪个游戏：以「辅助 › 游戏存档」当前选中的游戏库条目为准；未选游戏时空态「请先选择游戏」。
- 读取位置：按该游戏的 `gameId`（规则同 [`technical/game-saves.md`](./technical/game-saves.md) 本机位置）同时读两处：
  - 游戏目录内 `chaya/saves/`（「存到游戏中」）；
  - 本机服务数据目录 `game-saves/games/<gameId>/`（「存到 Chaya 本机」）。
  - 自动 / 快速两张卡片各按设置中的存放位置取对应来源；某处不存在或无法读取时该列表显示空态并说明原因，另一列表不受影响。
- 展示字段：与在线列表一致——槽位（快速 `#0`–`#9`）/ 序号、保存时间、地图名、游戏时长、缩略图（有则显示）。
- 只读：保存、读档、删除、清空、立即存档全部禁用，悬停说明「连接游戏后可用」。设置区仍照常可改（现有行为）。
- 安全：只读接口要求本机盘能力（`canUseDisk`），只返回列表元数据与缩略图，不返回存档内容本体；游戏启动令牌不可调用。
- `remote` 形态没有本机存档目录，列表区维持现有「请先连接游戏」空态，不假装提供离线列表。

### 6.4 E · 不阻塞约束

- 连接游戏后列表立即切回在线数据与在线操作（现有路径），离线只读列表不残留。
- 离线读取失败（目录不存在、索引损坏）只让对应列表显示空态与原因，不影响设置区可改，也不影响之后连接游戏。
- 离线读取绑定当前所选游戏；切换游戏或连接游戏时取消旧读取并忽略迟到结果。两处来源独立结束，任一来源失败或超时都不得让另一来源或整页一直处于加载态。
- 只读接口只读不写：不修复、不重写 `index.json`，避免与游戏侧的索引版本校验冲突，导致连接后出现「存档列表已被其他窗口更新」。
- **两个 `gameId` 都要查**：游戏经 Chaya 启动时存档按游戏库 id 存放；直接双击游戏启动（没有库 id）时按 `path:<游戏目录>` 存放。离线列表只查库 id 会显示空，让玩家误以为存档丢了。离线时两个位置都查并合并显示。

### 6.5 验收

1. 仅在网页改快速存档快捷键 → 连接游戏后局内生效（对应原存档需求验收第 26 条）。
2. 在游戏内浮层改快速存档快捷键 → 网页刷新后显示新绑定。
3. 改唤出键 / 其他快捷键同样双向同步；同步一份唤出键为空或结构损坏的表时，局内面板仍能用反引号打开。
4. 网页先后连接两个游戏：各自的本游戏覆盖互不串。
5. 本机未连游戏、选中游戏后打开存档页：两张卡片按各自存放位置显示只读列表，写操作禁用并有说明。
6. 未选游戏显示「请先选择游戏」；`remote` 形态未连接保持「请先连接游戏」。
7. 离线列表打开时连接游戏：切换为在线列表，保存 / 读档立即可用，不出现索引冲突提示。
8. 快捷键同步或离线列表读取过程中断线 / 切换游戏：页面解除加载状态；迟到结果不覆盖当前游戏，也不影响重新连接。

## 7. F–G · 地图事件撤销与批量（第 3 期剩余）

### 7.1 F · 撤销

- **记录方式**：改状态的操作执行前，只记录该操作将触及的项的「改前值」与「改后值」（差量），不是整份全局快照，避免撤销时回滚无关进度。可记录项只有：开关、变量、独立开关、玩家地图与坐标。
- **深度**：按游戏保存最多 **10 步**，后进先出；页头「撤销」每次撤销最近一步，按钮提示显示该步摘要（如「撤销：切换独立开关 A（3 个事件）」）。
- **一次批量 = 一步**：§7.2 的一次批量操作合为一步，撤销时整体还原其中成功的项。
- **撤销栈放在 ext**：地图事件页在网页控制台和游戏内浮层（`plugins/src/cheat/ui/useOverlayEvents.ts`）都有。撤销栈放在游戏侧、所有客户端共享（做法同「数据修改」撤销栈，但是独立的一个栈），任一端看到的「撤销上一步」都是同一步。
- **生命周期**：随游戏进程；关闭 / 重载游戏后清空。网页刷新、断开后重连不清空，重连后撤销按钮恢复可用。
- **冲突**：撤销前比较各项当前值与记录的「改后值」；有不一致（例如之后游戏内又改过、玩家已移动）时先弹确认，列出不一致项，确认后仍按「改前值」写回。
- **不可还原的副作用**：执行事件带来的物品、金钱、角色、对话、战斗等变化**不承诺**撤销。这类操作仍记一步，但只还原上述可记录项；其确认框写明「执行后无法完全撤销」，撤销按钮提示写明「仅还原开关 / 变量 / 位置」（与 [`edit-map-events.md`](./edit-map-events.md) 一致）。
- 游戏未连接时撤销不可用（见 §5.1）。

### 7.2 G · 批量

- 事件表支持多选（单次上限 **50** 个事件，超出时提示缩小范围）；批量切换独立开关 / 满足条件。
- 确认框列出受影响事件（名称、编号、将改的项）；执行规则与单条一致，按列表顺序逐条执行。
- **部分失败**：某条失败不中断，继续执行其余；结束后汇总「成功 N / 失败 M」，失败项列出原因。成功项合为一步撤销记录。
- 执行期间禁止再次发起批量或单条修改，避免交错。

### 7.3 F / G · 不阻塞约束

- **游戏内时机**：批量与单条操作只在地图场景、无对话显示、无场所移动进行中时执行；不满足时提示「请回到地图后再试」，不排队、不强行写入。普通撤销同样检查；但用于关闭本次操作触发的自动执行事件时，允许在解释器或对话运行中先直接还原其触发开关 / 变量 / 独立开关，防止下一轮继续执行。此时不强制关闭当前对话，玩家结束当前段后即可脱离循环；位置还原若不安全则本次跳过并明确列出。撤销中的安全位置还原走现有传送路径，传送进行中不叠加。
- **自动执行事件**：切开关 / 满足条件 / 撤销都可能让某个事件页变成「自动执行」并立即开跑；批量一次改 50 个可能同时触发多个，剧情连锁卡住。
  - 批量与单条确认框标出「执行后将立即自动执行」的事件。
  - 「自动执行事件运行中」及其对话**不**拦截上述触发条件还原；撤销正是从这类循环中脱困的手段。传送进行中仍不执行位置还原。
  - 撤销还原玩家位置时，目标地图的自动执行事件照常触发，撤销提示写明这一点。
- **高风险事件不由 Chaya 启动**：执行事件、满足条件或切换共享触发开关前分析可达命令。若会启动包含脚本 / 插件命令、递归公共事件、无法证明会退出的循环或回跳的自动执行事件，拒绝本次「开启 / 执行」并列出原因；允许关闭其触发条件。不能依赖运行后的超时，因为同步死循环会连计时器和停止按钮一起冻结。
- **独立撤销栈**：地图事件撤销使用自己的栈，不复用「数据修改」的撤销栈（`plugins/src/cheat/session/save-data/undo.ts`），两页撤销互不影响，不会在地图页撤掉数据修改页的改动。
- **批量不卡死**：每条设单条超时（沿用单条请求超时）。超时后先取消并确认该条不会迟到写入，才能记为失败并继续；若无法确认最终状态，则停止本批剩余项目并标为「未执行（结果未知）」，避免旧操作稍后落地并与后续操作交错。执行中断开游戏时立即结束批量，解除「执行中」锁，已确认成功项照常记入撤销，未执行项列为「未执行（已断开）」。
- **自动事件打断批量**：某条成功后若已启动自动执行事件，立即停止本批剩余项目并汇总为「未执行（事件已开始）」，成功项仍合为一步撤销；不得一边运行事件一边继续批量写入。
- **操作锁必释放**：批量 / 单条 / 撤销的互斥锁归 ext 持有并带操作 ID；所有结束路径都释放。网页断线只让网页退出等待，ext 中的操作按既定规则完成或停止；重连后先查询操作状态，不凭页面旧状态继续锁定。
- **撤销失败不卡死**：撤销中途某项写入失败时停止该步，提示已还原 / 未还原的项；已还原项从该步移除，未还原项作为剩余步骤保留，可重试或明确放弃。页面与操作锁立即恢复，不得留下半完成但无法处理的隐藏状态。
- 除新增的高风险事件执行前门禁外，撤销与批量不改变单条操作的现有确认与执行流程。

### 7.4 验收

1. 改开关 / 变量 / 坐标后点撤销，相关项回到改前值；无关开关 / 变量不受影响。
2. 连续 11 次改动后最早一次不可撤销；刷新网页后撤销仍可用，关闭游戏后清空。
3. 在游戏内浮层改开关，网页「撤销」能撤掉这一步，反之亦然。
4. 把某事件切到会自动执行的状态导致卡在事件里：撤销可用并能脱困。
5. 改后在游戏内又动了同一开关，再撤销：先弹冲突确认并列出该项。
6. 多选批量操作：确认文案含影响列表；结果与逐条执行一致；人为制造一条失败时其余照常执行并汇总；整批可一步撤销。
7. 对话进行中点批量或普通撤销：提示回到地图后再试；若对话循环由本次操作触发，撤销仍可先还原其触发条件。
8. 批量执行中断开游戏：批量立即结束，页面解除锁定，重连后可再次操作。
9. 在数据修改页改值后，地图页撤销不影响该改动。
10. 批量确认框标出会立即自动执行的事件。
11. 迷你地图保持已有行为；**不做**图块 / 截图底图（已冻结）。
12. 自动执行事件进入对话循环：撤销仍可先恢复触发条件；结束当前对话后不再进入下一轮，页面操作锁已释放。
13. 批量中途触发自动执行事件、请求超时或网页断线：剩余项停止或由 ext 收尾，成功项可撤销；重连可查询结果且没有永久「执行中」。
14. 尝试通过执行、满足条件或共享开关启动含同步死循环 / 不透明脚本的自动事件：Chaya 在执行前拒绝，游戏主线程不被冻结；关闭触发条件仍可用。

## 8. H · Agent 运行时统一到 ext

### 8.0 现状与目标

现在同一个 Agent 有三份运行时，能力不一致：

| 入口                           | 运行位置                            | 实现                                                                                                  | 托管   |
| ------------------------------ | ----------------------------------- | ----------------------------------------------------------------------------------------------------- | ------ |
| `local` / `app` 侧栏、ext 侧栏 | Chaya 本机服务                      | `services/game-agent/`（`runManagedTurn` 托管循环、`turn-runner` 问答循环、`session-store` 内存会话） | 有     |
| `remote`（cloud）侧栏          | 网页内                              | `components/game-agent/browserTurn.ts`（最多 8 次工具调用的问答循环）                                 | **无** |
| ext 旅伴                       | `local` 走服务端、`remote` 走网页内 | `app/api/game-agent/companion/route.server.ts` 与 `browserRequest.ts` 各一份                          | —      |

目标：**Agent 核心运行时只有一份代码**，可以在不同宿主上起多个实例。侧栏问答、托管、旅伴是同一核心上的不同**能力配置**；每个实例能用哪些工具，由所在宿主提供的 MCP 工具决定。

| 宿主       | 位置                                        | 跑哪些实例                                       | 工具来源                                                                                                       |
| ---------- | ------------------------------------------- | ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| 控制台宿主 | `local` / `app`：本机服务；`remote`：网页内 | local / cloud 侧栏的问答实例                     | 该端 MCP：`local` 为本机 `/api/mcp`（服务端工具全量），`remote` 为网页 WebMCP 工具；连接游戏后再加上游戏侧工具 |
| 游戏宿主   | ext（游戏进程内的插件）                     | 托管实例（独占按键）、旅伴实例、ext 侧栏问答实例 | 插件 MCP（`mcpToolsFor('plugin')`）；`local` 下本机服务可达时再加上需要本机服务的工具                          |

**托管只在 ext 跑**：任一端侧栏判定为托管时，委托给 ext 的托管实例执行，进度经各自通道回到发起端。

```
     控制台宿主（问答）                       游戏宿主 ext
  ┌───────────────────────┐            ┌──────────────────────────┐
  │ local：本机服务         │  托管委托   │ 托管实例（独占按键）       │
  │ cloud：网页             │ ─────────▶ │ 旅伴实例                  │
  │ 工具：该端 MCP          │ ◀───────── │ ext 侧栏问答实例          │
  │ （连游戏后 + 游戏工具）  │  进度/事件  │ 工具：插件 MCP            │
  └───────────────────────┘            └──────────────────────────┘
     local 经本机服务转发，cloud 经 GameLink 浏览器通道；ext 侧栏同进程直连
```

v1 只保留一条实现路径：共享核心接通后删除服务端托管循环（`runManagedTurn` 等），`turn-runner`、`browserTurn` 与两份旅伴实现由共享核心替代，不保留兼容入口或并行路径。分四个子任务：

### 8.1 H1 · 共享核心与能力配置

- **核心循环一份**：观察 → 模型决策 → 工具调用 → 验证，复用现有托管循环逻辑（目标推断、换路、战斗、无进展判定、视觉观察）。同一份代码在本机服务（Node）、网页、ext 三处都能跑，只依赖抽象接口（模型调用、工具列表与调用、存储、事件输出），不依赖 Next / Node 专有 API。
- **能力配置**决定实例行为，不分叉核心代码：

| 配置 | 宿主         | 用途                             | 工具                                       | 输入     | 上限                                                           |
| ---- | ------------ | -------------------------------- | ------------------------------------------ | -------- | -------------------------------------------------------------- |
| 托管 | 仅 ext       | 侧栏与旅伴发起的托管             | 观察 + 按键 / 移动等游玩工具（现有白名单） | **独占** | 每轮 80 步 / 60 次操作，连续 3 次无进展后换轮；持续到玩家 Stop |
| 问答 | 控制台或 ext | 侧栏问询与工具操作               | 所在宿主 MCP 当前可用的工具（见下）        | 不可按键 | 8 次工具调用（沿用现值）                                       |
| 旅伴 | 仅 ext       | 陪玩聊天、宝箱 / 战斗 / 危险提示 | 只读游戏状态                               | 不可按键 | 单轮、短回复（沿用现值）                                       |

- **问答的工具按 MCP 分组动态给**（分组见 `lib/integration/mcp-catalog.ts`）：

| 工具组                                                       | 是否需要游戏                                                | 未连接游戏时                 |
| ------------------------------------------------------------ | ----------------------------------------------------------- | ---------------------------- |
| `library`（游戏库）、`game`（启动、装插件、装壳、窗口等）    | 不需要，`local` 需要本机服务，`remote` 由 WebMCP 浏览器实现 | **可用**                     |
| `translate`、`cache`、`logs`                                 | 不需要                                                      | **可用**                     |
| `live`（游戏状态、截图、按键等）、`edit`（修改页数值与动作） | 需要                                                        | 不提供给模型；连接后自动加入 |

- 每轮开始时按「所在宿主 MCP 的工具列表 + 游戏是否连接」生成本轮工具；未连接时不把 `live` / `edit` 交给模型，避免模型白白调用失败的工具耗尽步数。
- 问答实例永远不拿按键类工具（`chaya_live_press` / `chaya_live_play` / `chaya_live_tap` / `chaya_live_move_to` / `chaya_live_interact` 等），需要按键的请求一律走托管。
- 标为「破坏性」的工具（如 `chaya_cache_delete`、`chaya_logs_clear`）沿用现有「需玩家同意」规则。
- 侧栏仍是统一入口：由意图判定（现有 `classifyGameIntent` 逻辑）决定走托管还是问答，不恢复 ask/play 双入口。
- **统一运行名额**：同一游戏的托管、问答、旅伴共享一个非终态任务名额。任一 Agent 处于 `running`、`waiting_user` 或 `waiting_service` 时，另外两个入口只显示同一任务的「进行中」与 Stop，不得再启动任务；玩家停止并确认旧任务进入终态后才能发起新任务。

### 8.2 H2 · 三端接入与模型调用

- **侧栏问答**：在本端控制台宿主直接跑（`local` 在本机服务，`remote` 在网页），不经过游戏；连接游戏时，`live` / `edit` 工具经现有通道调用游戏（与现在一致）。
- **托管委托协议**：开始任务、回复、停止、查询状态、按序号订阅事件（`after=<最后序号>`）。三端用同一协议，通道不同：
  - ext 侧栏：同进程直接调用。
  - `local` / `app` 侧栏：经本机服务转发到游戏（现有游戏连接通道），事件经服务转为 SSE 给网页。
  - `remote`（cloud）侧栏：经现有 GameLink 浏览器通道直达游戏。
- **侧栏会话里两类实例要接得上**：同一个侧栏对话里，问答在控制台宿主、托管在 ext，二者的对话记录与当前任务都显示在同一会话里；托管任务的目标、进度与结果写回该会话，后续问答能看到。
- **模型调用按宿主走**：
  - 控制台宿主：`local` 在本机服务内直接调用（令牌在服务端）；`remote` 在网页内直连模型地址（与现在一致）。
  - ext · `local` / `app`：经本机服务的模型代理接口调用（游戏用启动令牌鉴权）。API 令牌继续只存在服务端（`services/game-agent/secrets.ts`），不下发到游戏。
  - ext · `remote`：直连模型地址（与现在网页直连的限制相同）。
- **Agent 配置**（平台、模型、提示词）：
  - `local` / `app`：沿用现有同步（插件经 `/api/integration/game-agent` 与本机服务合并），不改。
  - `remote`：没有本机服务，配置存在网页的浏览器存储里，与游戏不同源，ext 读不到。改为网页连上游戏时经 GameLink 把配置（含令牌）下发给 ext，ext 缓存在游戏本地；之后在 ext 面板直接发起也用缓存。从未下发过时，ext 面板提示「请先在 Chaya 网页连接一次游戏以同步 Agent 配置」。
- **GameLink 双层门禁**：cloud 的 GameLink 信令沿用 `CHAYA_LINK_TOKEN` 配对鉴权；普通游戏命令仍只放行 `AGENT_LINK_METHODS` 里的方法（`plugins/src/helpers/game/agent-link.ts`），Agent 任务通道另只接受本文列出的 `agent.task.*` 与 `agent.config.put` 结构化消息，未知方法或消息类型立即拒绝。任务消息不得伪装成 `/agent` 普通命令绕过任务门禁。此外，同一游戏进程内**第一次**由网页经 GameLink 发起托管时，游戏内弹一次「允许此网页控制 Agent」确认并仅在本进程记住，作为按键控制与模型额度消耗的二次授权。
- 首次确认带超时与取消：玩家拒绝、网页断开或 **60 秒**未处理时，本次开始请求失败且不创建任务、不占托管名额；网页退出等待并可重新发起。
- **没连接游戏**：local / cloud 侧栏照常可用，问答使用不需要游戏的工具（游戏库、启动游戏、装插件、翻译、翻译库、日志等）；只有托管和 `live` / `edit` 类操作需要游戏。用户提出托管时回复「托管需要先连接游戏」；`local` 下可直接用 `game` 组工具帮用户启动游戏（`remote` 不提供启动，提示手动打开游戏）。ext 侧栏本身在游戏内，不存在未连接的情况。

### 8.3 H3 · 生命周期、持久化与续读

- **托管 / 旅伴的生命周期跟游戏走**：这些实例存在于游戏进程内。收起 ext 面板、关闭网页不影响正在运行的托管任务；本机服务短暂重启时进入 `waiting_service`，按下文 60 秒规则恢复或失败。重新打开任一端即按序号续读进度。关闭游戏则任务随之结束。
- **挂机托管持续运行**：托管不是“一次目标完成即结束”的 Turn。每轮达成当前目标、连续无进展或达到单轮步数 / 操作预算后，记录一条过程摘要、重新观察并进入下一轮；正常情况下只允许玩家显式点击 Stop 结束。模型不可用、游戏关闭、宿主重载等不可恢复故障仍进入明确的 failed / interrupted 终态，不能伪装成仍在运行。
- **侧栏问答的生命周期跟控制台宿主走**：问答是短任务（最多 8 次工具调用）。`local` 问答跑在本机服务里，关网页不影响，服务重启则该轮中断；`remote` 问答跑在网页里，关网页即中断。中断的问答轮次在会话里标为「已中断」，可重新提问。
- **会话记录分两处存**：侧栏对话记录存控制台侧（`local` 本机服务数据目录，`remote` 浏览器存储）；托管任务状态存游戏侧（见下）。侧栏打开时把二者按时间合并显示。
- **页面重载 = 关游戏**：MZ 的 F5 重载、插件开发热更新都会重载游戏页面，运行时随之消失，按「关闭游戏」处理（重开后显示「已中断」）。
- **事件缓存**：每个任务在 ext 内缓存最近 200 条事件，续读超出缓存时返回缺口提示（沿用现有 `history.gap` 语义）。
- **持久化在游戏侧**：会话存游戏目录 `chaya/agent/`（无文件系统的浏览器版游戏存其 IndexedDB），按游戏隔离；保留最近 **20** 个会话、最长 **7 天**。内容：对话消息、任务目标与边界、最近观察摘要、未完成任务阶段。写入异步并节流（每步最多一次），不用同步文件写，避免卡帧。
- 创建任务时先等待一次初始持久化检查点，再允许第一次模型调用或按键；写入失败按下文退化为仅内存并明确记日志。存储正常时，即使首次操作期间 F5 / 热更新，重开后仍能识别该任务为「已中断」，不会遗留看不见的运行态。之后的阶段更新异步节流。
- 文件与 IndexedDB 持久化均有独立超时；初始检查点超时即退化为仅内存并在 UI 标明「本任务无法跨重载恢复」，不得无限等待后才开始任务。后台写入超时不阻塞模型循环或停止操作。
- **重开游戏后**：上次未完成的任务显示为「已中断」，玩家点「继续」时新开任务承接上下文，不自动继续执行。
- **暂停 / 恢复**：需要玩家回复时进入 `waiting_user`；回复后同一任务继续。超过 **30 分钟**未回复则结束并说明。
- `waiting_user` 与等待本机服务的 `waiting_service` 都不持有按键 / 移动互斥锁，也不阻止键鼠宏或外部 MCP 输入；准备恢复时重新竞争锁，并基于最新观察继续。两者仍占该游戏唯一 Agent 任务名额，玩家可停止后另开任务。
- **上下文预算**：超出预算时压缩较早轮次为摘要，始终保留任务目标 / 边界与最近 **5** 次观察；阈值写入 [`technical/game-agent.md`](./technical/game-agent.md)。
- 玩家显式停止（任一端）立即生效。

### 8.4 H4 · 进展判定、能力探测与过程 UI

- **无进展 / 单轮上限**：沿用现值（见 §8.1 表）作为每轮保护。触发后展示最后状态与最近操作，清理本轮上下文并继续下一轮，不自动结束挂机任务。
- **能力探测**：所选模型不支持工具调用、视觉输入等必需能力时给出明确状态（如「当前模型不支持工具调用，无法托管」），不假装成功、不静默降级。
- **过程 UI**：三端统一展示「进行中」、推断目标、当前阶段（观察 / 思考 / 操作 / 验证 / 等待玩家 / 等待本机服务）与步数、工具过程摘要、每轮结果和停止原因；使用面向玩家的简短状态描述，不展示内部思维链全文。

### 8.5 不阻塞约束

- **不卡游戏主循环**：运行时全程异步，模型请求、截图编码等耗时操作不在游戏帧更新里同步执行；视觉截图按需触发并限频。托管期间游戏照常渲染、玩家随时可停止。
- **每个等待都有上限**：模型请求、工具调用、视觉处理、遥控命令与持久化刷新都必须可取消并有有限超时；超时按对应操作失败或等待状态处理，不得让任务永远停在观察 / 思考 / 操作 / 验证阶段。持久化刷新不参与任务完成条件。
- **生命周期单向收敛**：任务可在 `running`、`waiting_user` 与 `waiting_service` 间按规定切换，三者只能进入 `completed` / `stopped` / `failed` 终态；结束态不可被迟到事件改回运行态。所有终态都在 `finally` 中停止计时器、取消未完成请求、释放按键锁与外部控制标记，再发送一次终态事件。
- **开始与停止幂等**：开始 / 回复 / 停止均带请求 ID，ext 缓存近期结果。重复开始不创建第二个任务；运行中只提供 Stop，不提供隐式替换。玩家确认旧任务进入终态且释放输入后，才可另行启动新任务。
- **停止压过迟到结果**：停止会立即中止模型请求和可取消的工具；无法中止的调用完成后只丢弃结果。运行时在每次写操作或按键前再次检查任务仍为 `running`，保证停止后无新动作。
- **恢复的任务永不处于运行态**：从持久化恢复时，原为运行 / 等待中的任务一律标为「已中断」，不占托管名额。否则重开游戏后会一直提示「已有任务在运行」，无法发起新任务。
- **持久化损坏或写入失败**：只读取 v1 格式；内容损坏或格式不符的会话直接跳过并记日志，不尝试修复、转换或回填。写入失败只记日志，任务照常运行（退化为仅内存）。两种情况都不让 Agent 面板或发起任务报错。
- **兜底清理**：保留「一键清理」，停止该游戏所有实例并清除「已中断」标记，任何卡住情况都能恢复到可发起新任务。
- **遥控通道断开不影响任务**：本机服务重启、网页断线、GameLink 断开只影响「看进度」，任务在 ext 内继续；通道恢复后按序号续读。事件转发失败不得反过来让任务失败。
- **终态主动校准**：三端订阅超时或重连后先查询任务状态；ext 是托管任务、操作锁与最后序号的权威来源。若终态事件丢失，查询结果必须让页面退出运行态；查询也失败时页面进入「连接中断」而不是继续显示「运行中」。
- **启动令牌要扛住服务重启**：启动令牌持久化到本机服务数据目录，服务启动时先加载再接受游戏请求；记录绑定游戏身份并带最后活动时间，长期无活动时清理。写入失败则本次启动明确提示令牌无法持久化，不承诺跨重启继续，不得表面显示可续而重启后持续 401。游戏明确退出或令牌超期时撤销；Agent「一键清理」只清 Agent 实例与任务标记，不删除 Agent 配置，也不撤销仍被存档 / 翻译等能力共用的游戏启动令牌。
- **本机服务短暂不可达时暂停等待**：模型代理连不上时，任务进入等待（显示「等待 Chaya 本机服务」），每隔几秒重试，最长 **60 秒**；恢复后继续，超时才结束并提示「无法连接 Chaya 本机服务」。不把每次失败当成一步消耗，也不重试到步数耗尽。
- **视觉观察去掉 Node 原生依赖**：现在战斗截图的裁剪放大用的是 `sharp`（`services/game-agent/visual-observation.server.ts`），这是 Node 原生库，游戏里用不了。迁入 ext 时改用 canvas 裁剪；否则战斗菜单的视觉判定会直接失效，托管卡在战斗里。
- canvas 截图、裁剪与编码设置尺寸 / 频率上限，大图按阶段让出事件循环；不得在游戏帧回调中同步编码整张图片。超过预算跳过本次视觉观察并记录原因，不阻塞后续停止或纯状态观察。
- **外部控制者也要让路**：
  - 键鼠宏：托管处于 `running` 时持续挂「Agent 操作中」标记，启动键鼠宏时提示「Agent 正在操作游戏」；进入 `waiting_user`、`waiting_service` 或任一终态立即释放。
  - 外部 MCP（插件 MCP 网关、本机 MCP）：托管处于 `running` 时，外部 Agent 的按键 / 移动类工具返回「Chaya Agent 正在托管游戏」并拒绝，只读工具照常；`waiting_user`、`waiting_service` 与终态不拦截。
- **模型调用失败要说清楚**：
  - `local` 模型代理不可达：按下文「本机服务短暂不可达时暂停等待」处理，超时后提示「无法连接 Chaya 本机服务」。
  - `remote` 直连被跨域或混合内容拦截（常见于浏览器版游戏）：提示具体原因与解决办法（如模型服务需允许该来源），不显示通用错误。
- **能力探测只在确定不支持时拦截**：只有服务商明确返回不支持或模型元数据明确声明不支持时才拒绝；探测不出或探测失败一律放行，首轮失败时再提示。避免元数据不全的模型（如部分 Ollama 模型）被误拦。
- **上下文压缩失败**：摘要请求失败时退化为截断较早轮次（仍保留任务目标与最近观察），不让任务失败。
- **问答中途游戏断开**：本轮已交给模型的 `live` / `edit` 工具调用返回「游戏已断开」，问答继续用其余工具作答，不让整轮失败；下一轮起不再提供这些工具。
- **未连接游戏不禁用侧栏**：侧栏输入框在任何连接状态下都可用；只有托管请求与 `live` / `edit` 操作给出「需要先连接游戏」，不得把整个侧栏置灰。
- **按键独占**：托管实例按键时，问答 / 旅伴实例不得发出任何输入；玩家手动按键不被屏蔽（现有行为），托管以下一次观察结果为准继续。
- **迁移顺序不留空窗**：ext 运行时在三端都验收通过后，才删除服务端托管循环与网页内运行时；同一提交内切换入口，不出现「旧的已删、新的未接」的状态。

### 8.6 禁止

- 不恢复 ask/play 双入口。
- **托管与旅伴**不开放修改数据、脚本执行、强制胜利等捷径（与 [`game-assistance.md`](./game-assistance.md) 一致）；能力配置只能收窄工具白名单，不能放宽。**问答**可在玩家明确提出操作请求时使用当前 MCP 已有的非按键工具，并沿用其确认 / 破坏性门禁；纯问询不得产生写操作。
- 不把「截图 / 视觉从零评估」做成新子项目；现有视觉观察能力随运行时迁入 ext，仅按需修补。
- API 令牌不下发到游戏进程（`local` / `app`）。

### 8.7 验收

1. cloud、local、ext 三端侧栏都能发起托管，委托给 ext 的托管实例执行；cloud 首次具备托管能力。
2. 托管中收起 ext 面板、关闭网页、在 60 秒等待窗口内重启本机服务：任务继续；重新打开任一端可续看进度。
3. 在 local 侧栏发起的任务，可在 ext 面板看到并停止，反之亦然。
4. 任一 Agent 运行中从托管、问答或旅伴再次发起：三个入口都显示同一个「进行中」任务且只允许 Stop，不创建第二个任务；停止确认后才可重新发起。
5. 关闭游戏后重开：上次任务显示「已中断」，可直接发起新任务，也可点「继续」承接上下文。
6. 等待玩家回复时收起面板不终止任务；回复后同一任务继续；超 30 分钟未回复有结束说明。
7. 显式停止后无新动作；连续 3 次无进展或达到单轮上限时展示摘要并开始下一轮，不结束挂机；未点击 Stop 时持续观察与操作。
8. 未连接游戏：local / cloud 侧栏可正常问答，并能调用游戏库、翻译、翻译库、日志等工具（`local` 还可启动游戏、装插件）；要求托管时回复「托管需要先连接游戏」；模型拿到的工具里没有 `live` / `edit`。连接游戏后，下一轮自动出现游戏工具。
   8a. 问答进行中断开游戏：该轮不失败，用其余工具作答。
9. `local` 下停掉本机服务后托管：提示无法连接本机服务；`remote` 浏览器版游戏模型跨域被拦：提示具体原因。
10. 选用不支持工具调用的模型：明确提示；元数据不全但实际支持的模型不被误拦。
11. 托管期间游戏帧率无明显下降，玩家随时可停止。
12. 过程 UI 三端一致，可见「进行中」、目标、阶段、步数、每轮公开摘要与停止原因，无思维链全文。
13. 问询类请求不产生写操作或按键。
14. 手动损坏会话持久化后启动游戏：Agent 面板正常，可发起新任务。
15. 迁移后仓库中不再有服务端托管循环；本机服务、网页、ext 的 Agent 都由同一份共享核心驱动，旅伴只有一份实现。
16. `local` 托管中重启本机服务：任务显示「等待 Chaya 本机服务」，60 秒内服务回来后继续，无 401 失败；超过 60 秒进入失败终态并释放全部锁，可立即重试。
17. `remote`：网页连上游戏后，在 ext 面板直接发起托管可用（配置已下发）；同一游戏进程内首次由网页发起托管时游戏内弹确认。
18. 战斗中托管：视觉判定在 ext 内可用，能选中菜单项。
19. 托管中启动键鼠宏、外部 MCP 调按键工具：都被拒并有提示；只读工具正常。
20. 托管中按 F5 重载游戏：重开后任务显示「已中断」，可新发或继续。
21. 模型请求或工具调用卡住时点停止：立即进入停止态；迟到回复不再触发按键或写操作，可马上发起新任务。
22. 托管进入 `waiting_user`：键鼠宏与外部 MCP 输入可用；回复后 Agent 重新取得输入锁并从最新状态继续。
23. Stop 连续点击或开始请求超时重试：最多只有一个 Agent 实例，不重复按键、不遗留输入锁；旧任务未确认终止前新任务保持禁用。
24. ext 已结束但网页丢失终态事件：订阅超时或重连查询后网页退出运行态，可继续发起任务。
25. 文件 / IndexedDB 写入或 canvas 处理人为挂起：任务进入降级或失败状态，停止仍可用，游戏渲染与其他面板不被卡住。
