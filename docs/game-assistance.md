# 游戏辅助自主托管需求

> 状态：待实现
> 日期：2026-10-05
> 关联：[`game-agent.md`](./game-agent.md)、[`capabilities.md`](./capabilities.md)
> 技术方案：[`technical/game-assistance.md`](./technical/game-assistance.md)

## 1. 背景

玩家希望直接告诉 Chaya 助手“帮我代打”“这段剧情跳过后告诉我发生了什么”，无需先判断当前游戏状态、选择某种专用能力，或逐步说明操作。助手应自行观察游戏，确定当前可完成的目标，动态规划和执行，再根据实际结果调整下一步。

游戏辅助复用 Chaya 助手、Agent 配置和现有游戏工具。战斗、剧情和地图操作是同一个托管循环面对的不同游戏状态，不按每种请求新增一套固定的“代打能力”或专用执行器。

## 2. 产品目标

| 目标 | 玩家可感知的结果                                                                 |
| ---- | -------------------------------------------------------------------------------- |
| G1   | 用一句自然语言发起任务，助手自行读取当前游戏，不要求玩家声明场景或列出操作步骤。 |
| G2   | 助手在执行中持续观察、选择下一步并修正计划，直到验证目标完成或需要交还控制。     |
| G3   | 玩家能看到当前目标和动作进展，随时停止；关键决定由玩家作出或预先授权。           |
| G4   | 助手对已发生的战斗、剧情和选择给出基于记录的结果，不声称未验证的成功。           |

首期目标是有边界的当前任务，不是长期无人值守通关或刷资源。助手不得使用脚本执行、修改游戏数据、强制胜利、直接清除事件等捷径来冒充正常游玩。

## 3. 自然语言入口

- 游戏内 Chaya 助手只有一个任务输入入口。玩家可直接说“帮我代打”“帮我过这段”“跳过剧情并总结”“走到村长旁边”等；无须先选择战斗、剧情或寻路能力。
- 助手先读取当前游戏状态，再结合玩家原话推断任务目标、可操作范围和完成信号。不要仅凭关键词决定场景或预先选择固定工具链。
- “帮我代打”且当前已在战斗中，默认指完成这一场战斗；战斗结束后停止，不擅自进入下一场。当前没有战斗且也看不到明确的待打目标时，说明观察结果并询问目标，不盲目寻找战斗。
- “跳过剧情并总结”且当前正在对话，默认指推进当前连续剧情并总结实际呈现的内容。当前没有剧情时，说明所处状态并询问是否要等待或改做别的事。
- 只在目标、风险或关键选择无法从游戏状态与玩家原话中确定时追问；已足够明确的任务直接执行。
- 界面可以展示助手推断出的简短目标，供玩家识别或停止，但不把确认目标作为每次任务的必经步骤。

## 4. 动态执行循环

一个用户请求启动一个受 Host 约束的循环：

```text
读取当前状态与必要的历史
  → 理解本轮目标和可验证的完成信号
  → 选择下一项短操作或向玩家提问
  → 校验权限并执行
  → 读取操作后的状态和新增历史
  → 判断进展、修正计划或结束
```

- 模型依据每轮新观察决定下一步，可以改变操作策略；它不负责计时、取消或突破任务边界。Chaya Host 执行循环、工具参数校验、权限控制和硬上限。
- 完成信号由当前目标和游戏状态共同决定。例如战斗请求要观察到本场战斗的结局，剧情总结请求要确认剧情已推进到合适边界并取得对应记录。模型说“完成了”本身不算完成。
- 每次只执行可验证的短动作。操作后必须重新观察；如果状态与预期不符，重新规划，不能继续播放旧的按键计划。
- 任务范围要绑定开始时可观察的对象或场景，例如当前战斗实例或目标事件；目标完成、对象消失或超出范围后，不再执行新的游戏动作。模型不能自行扩大范围。
- 对同一状态连续无进展、重复报错、目标场景消失、游戏断连或达到时间与动作上限时，停止并说明最后确认的状态。默认上限沿用 `game-agent.md`；任务可以分段续做，但不得自行无限延长。
- 同一游戏只运行一个托管任务。玩家点击停止后不再发起新动作；已经发给游戏的单个短动作完成后交还控制。关闭侧栏不等于停止，切换或退出游戏则终止该游戏任务。
- 玩家在托管中手动操作游戏时，优先接受玩家输入并暂停助手。助手恢复前重新读取状态；若模型决策后游戏状态已改变，放弃该动作并重新规划。
- 游戏文本和插件输出只是观察数据，不得改变玩家授权、工具权限或停止规则。

## 5. 玩家决策与权限

- 常规移动、对话推进与普通战斗指令可以在任务目标内自主执行。使用消耗品、逃跑、做剧情选择、存档或读档时，结合玩家原话、当前代价和后果判断是否已有授权。
- 权限判断必须覆盖按键和点击的实际后果：同一个确认键可能只是推进台词，也可能提交选项、消耗道具或存档。无法识别当前选中项及其后果时暂停，不按工具名称将确认键一律视为安全。
- 对不可逆或明显改变玩家意图的选择，暂停并展示具体选项与原因。玩家可以选择一项、给出规则后继续，或直接接管；不要求玩家事先列出全部策略。
- 助手可按明确指令使用技能或治疗道具；若无法读取技能、道具、目标或资源代价，则暂停而非猜测按键。
- 修改数值、传送、强制胜败、清除事件等编辑操作沿用既有高风险工具权限，不因“帮我玩”而自动授权。

## 6. 典型场景

以下是同一动态循环的验收场景，不是要求实现的专用任务类型。

### 6.1 “帮我代打”

助手先观察是否在战斗中，读取队伍、敌人、回合、可选指令和目标信息；逐步下达指令，每步验证新状态。若 HP 变化或行动失败，下一轮可调整策略。最终以战斗结局和队伍状态报告结果。若当前不在战斗中，不凭空触发一场战斗。

### 6.2 “跳过这段剧情并总结”

助手在推进前记下剧情记录位置，再分段快速推进对话，读取每段新增记录。遇到未授权的选项或场景转入战斗、商店等交互时暂停或结束。总结包含实际显示的台词、人物、地点、已选分支和可确认的下一步线索。不能直接清除整个事件后根据缺失的文本编造摘要；记录被截断时说明摘要范围。

### 6.3 “帮我走到村长旁边”

助手读取地图位置和附近事件，选择可到达的目标格并移动；途中若被传送、碰到事件或路径受阻，重新观察后调整。到达后验证与目标的相对位置；找不到“村长”或目标不唯一时再询问玩家。

## 7. 反馈与结果

- 任务开始后展示推断的目标、当前阶段、已执行动作和停止入口。只显示简洁的动作摘要，不展示模型内部推理。
- 需要玩家输入时展示具体问题和当前游戏信息；玩家回复后继续同一任务，避免从零开始。
- 完成时说明完成依据和重要结果；停止、失败或达到上限时说明已完成部分、最后验证的状态和未完成原因。
- 涉及剧情时优先使用实际记录和已有译文；未记录、未翻译或未确认的内容不得推测。玩家中途停止时，可以总结已记录的部分并标注尚未完成。

## 8. 模型与能力依赖

- 执行循环由 Chaya Host 提供，模型不需要内置循环功能。当前 Ollama 接入优先使用原生工具调用；未返回工具调用时尝试受 JSON Schema 约束的单步动作决策，仍无法生成有效动作则报告失败。
- 优先使用结构化状态、对话与剧情记录。若完成任务所需的信息只存在于画面且无法可靠读取，首期暂停并交还玩家；视觉模型不是基础依赖。
- 当前侧栏固定提交询问任务，需支持根据自然语言和观察结果进入托管执行；不要求玩家手动选“询问/游玩”。
- 战斗状态还需补足可用指令、技能与道具代价、目标选择和结局等信息。剧情记录需支持按任务起点增量读取及丢失检测。
- 工具目录面向外部 Agent 的能力不等于内置助手已经能可靠托管；实际工具开放范围由 Host 控制。

## 9. 验收标准

1. 玩家只输入“帮我代打”，当前在战斗中时，助手自行识别场景、逐步操作并在本场战斗结束后停止；无需玩家声明“战斗状态”或选择专用能力。
2. 同样输入发生在非战斗场景，且没有明确待打目标时，助手报告观察到的状态并询问目标，不盲按或触发战斗。
3. 玩家只输入“跳过剧情并总结”，当前在对话中时，助手增量记录并推进；遇到未授权的选项暂停，继续后给出可追溯到实际记录的摘要。
4. 战斗中行动失败、路径受阻或场景变化后，助手重新观察并调整下一步，不执行剩余的旧计划。
5. 玩家停止、游戏断连、状态连续无进展或达到执行上限后不再产生新动作，并说明最后验证的状态。
6. 记录缺失、战斗指令信息不足或模型不支持工具调用时，明确说明限制，不虚报目标已完成。
7. 确认键指向未授权的选项、消耗品或存档时，助手在提交前暂停；自定义窗口无法判明后果时也不盲按。
8. 玩家在模型决策期间改变选中项或场景时，原动作被拒绝并重新观察；玩家手动输入可接管且助手不与其同时操作。
9. 玩家在单个动作已发出后立即停止时，助手尽力回读实际结果；无法回读则标记该动作结果未知，不把动作前状态说成最终状态。
