## 1. 背景与核心问题

在历史设计中，实时翻译与批量翻译管线采用串行尝试（Fallback）机制：按照既定顺序依次调用各翻译引擎，前一个引擎失败或未返回有效译文时才尝试下一个引擎。该策略在多引擎混合环境（Agent 实例、公网平台、本地离线引擎）下暴露了诸多问题：

1. **时延叠加与阻塞**：Agent 实例（如本地大模型或远程 AI 服务）往往具有较高的首次生成时延；公网平台（Bing、Google）在偶发网络抖动或限流退避时也会等待较长时间。串行遍历会导致单个文本翻译耗时高达数秒，极大损害在游戏运行期间的实时翻译体验。
2. **调度原则错位（缓存 vs 翻译）**：在翻译管线中，“优先级”应当仅用于确定**缓存检索顺序**（即先查本游戏专属人工/修订缓存，未命中再查全局共享高置信缓存）；但在未命中缓存、需要发起翻译生成时，各启用的翻译引擎之间无需人为划分高低优先级，而应当以**最快产出有效译文**为核心指标。
3. **引擎属性与成本认知模糊**：公网平台目前为免费通道，未来将规划引入高质量收费商业通道；而 Agent 翻译与本地离线引擎（如 macOS 原生神经翻译、Bergamot）则由用户本机算力或已有环境承载。界面缺乏直观的引擎属性标示，用户无法预估速度与费用预期。
4. **离线引擎缺少就绪状态感知**：以 macOS 系统级 Apple 神经翻译和跨平台 Bergamot 为例，虽然支持零网络、零延迟离线运行，但强依赖本机操作系统是否下载安装了相应语言对的离线包或离线字典。历史界面仅有开关，用户开启后若本地未安装语言包，翻译会报错且用户无法提前预知。
5. **引擎开关耦合与误启动假象**：默认配置中若公网平台默认处于开启状态，用户开启离线翻译时会发现公网平台也在并发产生网络请求，造成“开启离线翻译自动打开了翻译平台”的误解。

## 2. 优化目标与调度原则

### 2.1 调度原则：“缓存查优先级，翻译全并发”

- **缓存分层严格保持优先级**：
  - 第一层：当前游戏本地专属缓存（`localLookup` / 本作专属人工精校）；
  - 第二层：全局共享可信缓存（`shared-cache.sqlite`），按来源置信度复用；
  - 只有在两层缓存均未命中且文本需要翻译时，才触发外部引擎翻译。
- **翻译执行全并发（首胜原则）**：
  - 遍历当前已启用的所有翻译引擎（包括公网平台、本地离线引擎、已启用的 Agent 实例），同时并发派发请求；
  - 采用 **首胜机制（First Valid Wins）**：最先返回非空、非无意义内容（通过 `isUsefulTranslation` 校验）的引擎胜出，立即作为终稿返回并双写至缓存；
  - 其余较慢返回或失败的并发任务不阻塞翻译流程，保证游戏界面极速响应；
  - 敏感文本（如 NSFW）依然严格遵守安全隔离约束，仅分发至已启用的本地 Agent 引擎。

### 2.2 引擎开关完全独立解耦

- 各翻译引擎（Bing、Google、Apple 原生、Bergamot、各 Agent 实例）开关完全独立，互不影响；
- 支持**全部关闭**（即用户可自主关闭所有翻译平台与外部引擎，仅依赖本地与共享缓存运行）；
- 开启某离线引擎（如 Apple 原生）时，绝不连带或隐式开启任何公网平台引擎。

### 2.3 引擎属性与就绪状态徽标

在侧边栏引擎管理列表（`TranslateEngineRail`）及单行控件（`TranslateEngineRow`）中，为不同引擎类型提供标准化状态徽标：

1. **公网平台引擎（Bing / Google）**：
   - 标注 `免费`（`tagFree`）徽标（轻量强调色，非圆点），以便用户区分免费平台与后续接入的商业收费平台。
2. **本地离线引擎（Apple 原生 / Bergamot）**：
   - 客户端进入翻译面板时自动进行静默探活；
   - 若系统已就绪并安装语言包：展示绿点 `就绪`（`tagReady`）徽标；
   - 若本地环境缺失语言包或运行环境未安装：展示橙点 `未就绪`（`tagNotReady`）徽标，提示用户前往系统设置下载或安装模型。
3. **Agent 引擎**：
   - 保留实例与模型标签，体现自由配置与多实例并发能力。

## 3. 用户体验与典型场景

| 场景                 | 用户操作                                     | 系统响应与交互                                                                                                                        |
| :------------------- | :------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------ |
| **纯离线机翻模式**   | 用户关闭 Bing、Google，仅开启 Apple 原生翻译 | 游戏内文本未命中缓存时，仅调用 macOS 本地神经引擎，零公网流量消耗，不会向外部网络发送任何文本。                                       |
| **多引擎并发加速**   | 同时开启 Apple 原生、Bing 与本地 Agent       | 并发发起请求。通常 Apple 离线神经翻译在 15~30ms 内极速返回胜出并写入共享缓存；慢速的 Agent 与网络请求自然作废，游戏内对话无卡顿跳出。 |
| **全引擎关闭**       | 用户将所有引擎开关全部关闭                   | 仅查询本地已提取译文与共享缓存。若遇到未翻译文本，安全返回提示“未开启任何翻译平台”，不抛出异常。                                      |
| **语言包未就绪提示** | 用户在 macOS 未下载日语离线包时查看引擎列表  | Apple 原生引擎标题旁呈现橙色“未就绪”徽标；用户点击开启或执行翻译时，弹出系统语言包下载指引弹窗，引导用户至 macOS 系统设置一键下载。   |

## 4. 国际化与文案契约

全站 10 种语言统一接入以下规范文案：

- `translate.tagFree`：中文“免费”、繁体“免費”、英文“Free”、日文“無料”、韩文“무료”等；
- `translate.tagReady`：中文“就绪”、繁体“就緒”、英文“Ready”、日文“準備完了”、韩文“준비됨”等；
- `translate.tagNotReady`：中文“未就绪”、繁体“未就緒”、英文“Not Ready”、日文“未準備”、韩文“준비 안 됨”等。
