## 1. 背景

玩家想“马上打一场”，或者想打某一组特定的怪（刷经验、刷掉落、复现某场战斗、测试翻译后的战斗文本）。现在只能靠游戏自身的随机遇敌碰运气。控制台里虽然有 `ChayaEdit.troop(id)`，但没有界面入口；而且它用 `SceneManager.goto` 切进战斗，地图场景不在场景栈里，战斗结束后引擎 `SceneManager.pop()` 会因为栈空而退出游戏。

RPG Maker 里“遇到的怪”按**敌群**（Troop，`Troops.json`）配置：一个敌群包含若干敌人和战斗事件页。所以“指定怪物”就是指定敌群。

另一种常见情况是已经在战斗里：这张图一直遇到 A，玩家想打 B。与其退出战斗再找 B 所在的敌群，不如直接把场上的 A 变成 B，或者往这场战斗里追加一个 B。

## 2. 目标

| 目标 | 玩家可感知的结果                                                               |
| ---- | ------------------------------------------------------------------------------ |
| G1   | 在“修改”里按名称或敌人找到任意敌群，一键开战。                                 |
| G2   | 在地图页直接看到这张图会遇到哪些敌群，并能立即遇到其中任意一组。               |
| G3   | 开战和正常遇敌体验一致：有遇敌转场，战后回到原地，战斗事件照常执行。           |
| G4   | 不会因为开战把游戏弄坏：剧情或对话进行中、传送中、已在战斗中时拒绝并说明原因。 |
| G5   | 战斗中能把场上某个敌人变成指定敌人，或追加一个指定敌人，战后按实际敌人结算。   |

不做：修改数据库里的敌群构成与敌人数值（战斗中变身 / 追加只影响当前这场战斗）、强制胜利（已有运行动作 `battle:*` 覆盖）、修改地图遇敌列表或遇敌步数。

## 3. 入口与位置

- **主入口**：“修改”新增二级分类**敌群**，路径 `/cheat/troop`、`/cheat/troop/:id`，放在“公共事件”“地图”之后。不做一级导航：一级导航是独立功能面，直接改游戏状态的操作统一收在“修改”。
- **快捷入口**：地图页（`/cheat/map/:id`）在迷你地图与事件表之间新增“遇敌”区块，见 §6。
- **战斗中**：敌群页顶部在战斗中出现“当前战斗”区块，见 §8。（已迁到独立的“战斗”页 `/cheat/battle`，见 [edit-battle.md](./edit-battle.md)；本文 §8 的规则仍适用。）“运行”页的“战斗”卡片加一个“管理场上敌人”链接，跳到敌群页。放在敌群页而不是“运行”页，是因为选敌人需要完整的敌人列表，而这份数据只在敌群页加载。
- **控制台**：`ChayaEdit.troop(id)` 保留，改用与界面相同的开战逻辑（§5）。

## 4. 数据来源

| 内容                   | 静态（不开游戏）                                       | 运行时（游戏在线）                              |
| ---------------------- | ------------------------------------------------------ | ----------------------------------------------- |
| 敌群名称、成员、事件页 | `data/Troops.json`（事件索引已读取）                   | `$dataTroops`                                   |
| 敌人名称               | `data/Enemies.json`                                    | `$dataEnemies`                                  |
| 地图遇敌列表           | `data/MapXXX.json` 的 `encounterList`、`encounterStep` | 当前地图取 `$dataMap`                           |
| 当前场景与可否开战     | —                                                      | `SceneManager._scene`、地图解释器、玩家传送状态 |
| 场上敌人               | —                                                      | `$gameTroop.members()`（仅战斗中）              |
| 译名                   | 现有翻译库查表（原文悬停可见）                         | 同左                                            |

读取方式、缓存与 local / edge 差异沿用 [edit-map-events.md §2.1–2.2](./edit-map-events.md)。

## 5. 开战规则

### 5.1 前置条件

全部满足才可开战，否则按钮置灰，悬停或 toast 说明原因：

- 游戏在线，且当前在地图场景（不在标题、菜单、商店、战斗中）。
- 地图解释器空闲（没有剧情在跑），没有对话框，玩家不在传送中，也不在切换场景。
- 敌群存在且至少有一个有效成员。

不排队：条件不满足时直接拒绝，不等剧情结束后自动开战。

### 5.2 开战选项

| 选项       | 默认 | 说明                                                                                                        |
| ---------- | ---- | ----------------------------------------------------------------------------------------------------------- |
| 可以逃跑   | 开   | 同“战斗处理”指令的“可以逃跑”。                                                                              |
| 战败后继续 | 关   | 关闭时战败会进入游戏结束画面；确认框需写明。开启时战败后回到地图。                                          |
| 敌人数量   | 原样 | 1–8。多于敌群可见成员时按成员顺序复制，少于时隐藏多余的（战斗事件仍可让其出现）；中途出现的成员不计、不动。 |

选项在敌群详情中设置，本次会话内记住，不写入游戏；地图页“立即遇敌”沿用记住的选项。

### 5.3 行为

- 与引擎“战斗处理”指令一致：设置敌群、重置遇敌步数，**压栈**进入战斗（有遇敌转场），战斗结束回到原地图原位置。
- 敌群的战斗事件页照常执行；战斗开始与结果照常进入 `chaya_live_history`。
- 与“运行”页的“遇敌”开关相互独立：关闭随机遇敌时，仍可手动开战。
- 局内浮层开战后自动收起面板，让玩家看到战斗。

### 5.4 确认

每次开战都需确认（会改变进度，且战败可能游戏结束）。确认框展示敌群名称、成员列表、当前开战选项；“战败后继续”关闭时用警示文案提示游戏结束风险。

## 6. 地图页“遇敌”区块

- 列出该地图 `encounterList` 的每一项：敌群名、成员摘要、出现概率或区域限制。附带地图的遇敌步数。
  - 无区域限制的项：显示在无区域项中按权重换算的概率（玩家不在任何限定区域时的概率）。
  - 有区域限制的项：显示“仅区域 1、3”和权重，不给百分比（实际概率取决于玩家所在区域）。
- 每项操作：**立即遇敌**（按 §5 开战，仅当前地图可用，非当前地图置灰并提示先传送过去）、**详情**（跳到 `/cheat/troop/:id`）。
- 遇敌列表为空时整块隐藏，不显示空态。
- 游戏未在线时可浏览，操作置灰并提示“启动游戏后可用”。

## 7. 敌群页

### 7.1 布局（宽屏）

```text
┌ 修改 › 敌群 ──────────────────────────────── [只看可遇到] [搜索敌群 / 敌人] ┐
│ ┌ 当前战斗 ─────────────────────────────────────────────────────────────┐ │
│ │ 史莱姆 A   HP 120/120   [变成… ▾]                                     │ │
│ │ 史莱姆 B   HP  40/120   [变成… ▾]                     [追加敌人 ▾]    │ │
│ └───────────────────────────────────────────────────────────────────────┘ │
│ ┌ 列表 ────────────────────────────┐ ┌ #12 史莱姆×2 ────────────────────────┐ │
│ │  1  史莱姆×2       史莱姆 ×2      │ │ 史莱姆、史莱姆 · 2 页战斗事件        │ │
│ │  2  蝙蝠×3         蝙蝠 ×3        │ │ [立即开战]  ☑ 可以逃跑  ☐ 战败后继续 │ │
│ │ 12  洞窟之王       洞窟之王、蝙蝠 │ │ 出现在：地下水路（权重 10）           │ │
│ │ …                                 │ │ 被调用：住宅地 › 守卫（第 1 页）      │ │
│ └───────────────────────────────────┘ ├──────────────────────────────────────┤ │
│                                       │ 战斗事件（解释器）                    │ │
│                                       └──────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────────────┘
```

“当前战斗”区块只在战斗中出现，不在战斗时整块隐藏。

### 7.2 列表

- 每行：编号、敌群译名（悬停原名）、成员摘要（相同敌人合并为“名称 ×N”）。
- 默认隐藏空敌群（无成员）；可切换显示。
- 搜索匹配编号、敌群名、敌人名（译名与原名）。
- 筛选“只看可遇到”（默认开启）：只显示出现在任一地图遇敌列表或被事件“战斗处理”引用的敌群。地图未扫描完整时提示结果可能偏少。

### 7.3 详情

- **头部**：名称、编号、成员列表、战斗事件页数。
- **开战**：主按钮 + 开战选项（§5）。
- **出现在**：哪些地图的遇敌列表包含它（含权重、区域），条目可跳到地图页。
- **被调用**：哪些地图事件 / 公共事件用“战斗处理”指定了它，条目可跳转。
- **战斗事件**：按页展示，复用解释器（[edit-map-events.md §2.3](./edit-map-events.md)）；只读，不提供逐行执行。

公共事件页“引用关系”中的敌群条目，在敌群页上线后改为可跳转。

## 8. 战斗中改敌人

### 8.1 当前战斗区块

- 每行一个场上敌人：显示名（含 A / B 字母）、HP / 最大 HP、状态（已倒下、未出现）。按场上顺序排列，随游戏状态刷新。
- 用数据列表展示，列为：敌人、HP、状态（正常 / 未出现 / 已倒下）、操作。
- HP 为一个输入框（样式同角色 HP，“当前 / 上限”在同一框内），当前与上限都可直接改：当前 HP 0 到上限，上限 1 到 999999；回车或移开焦点生效，Esc 取消。当前改为 0 等同杀死；上限调低时当前 HP 随之截断。已倒下或未出现的敌人不可改。
- 每行右侧三个图标操作（悬停只显示动作名）：
  - **杀死**：立即把该敌人打倒（HP 归 0，播放倒下效果），胜负由游戏照常判定。未出现的敌人不可用。
  - **复活**：已倒下的敌人在同一位置显示复活，以满 HP 重新出现（与事件“敌人完全恢复”一样由游戏播放出现效果），可再次被选为目标。
  - **复制**：追加一个相同的敌人，规则同 §8.3。
  - **替换**：弹出敌人选择器（按名称 / 编号搜索全部敌人），选中即把该敌人变身为目标敌人，见 §8.2。已倒下或未出现的敌人不可用。
- 区块右上“追加敌人”（图标）：同一个选择器，选中即执行。
- 敌人选择器只列数据库里存在且有名字的敌人；无名敌人可切换显示。

### 8.2 变身

- 基于引擎的“敌人变身”指令：被选中的敌人变成目标敌人，外观、名称、能力值、技能、经验、金钱、掉落都改为目标敌人；**HP / MP 回满**为目标敌人的上限（引擎本身只截到上限，回满是本功能额外处理），选择器顶部写明这一点。
- 战后按变身后的敌人结算经验、金钱与掉落。
- 原生能力，兼容性与游戏自身的“敌人变身”一致。

### 8.3 追加

- 往这场战斗里加入一个目标敌人，HP / MP 满，从**下一回合**开始行动；可以立刻被选为攻击目标。
- 位置自动选在不与现有敌人重叠的地方；画面放不下时仍会加入，但可能与其他敌人重叠。
- 存活敌人达到 8 个时不能再追加。
- 战后经验、金钱、掉落计入追加的敌人；胜利条件为全部敌人（含追加的）倒下。
- 兼容性风险：部分战斗插件（横版、ATB、YEP 系列、MOG 敌人 HP 条等）改写了战斗画面，追加可能失败或缺少插件附属 UI（如 HP 条）。失败时不留下“隐形敌人”，toast 提示“该游戏的战斗画面不支持追加敌人”，变身仍可使用。想多打几个敌人时优先用开战选项“敌人数量”，兼容性更好。

### 8.4 前置条件与反馈

- 游戏在线且处于战斗场景；战斗已结束（胜利、战败、逃跑结算中）时拒绝。
- 不需确认：只影响当前这场战斗，且是玩家主动点选；操作结果用 toast 反馈。
- 局内浮层打开时游戏暂停，变化在关闭面板后可见；面板不自动收起，方便连续操作。
- 变身 / 追加不进入 `chaya_live_history`（不是游戏自然发生的事件）。

## 9. 窄屏（局内浮层）

不分栏：敌群列表 → 详情，顶部面包屑返回；“当前战斗”区块在列表上方。地图页的“遇敌”区块在事件表上方。宽窄屏共用 `components/game-edit` 组件。

## 10. Agent 边界

**不**向 Agent 开放开战、变身、追加，`chaya_edit_action` 不新增动作。游戏辅助托管明确不得凭空触发战斗或修改战斗来冒充正常游玩（[game-assistance.md §2、§6.1](./game-assistance.md)），开放与否另行评审。

## 11. 分期

1. 修正开战逻辑（压栈进入、前置条件校验）并接入编辑命令；敌群页列表 / 搜索 / 详情头部与开战；地图页“遇敌”区块。
2. 敌群详情的“出现在”“被调用”、战斗事件解释器、“只看可遇到”筛选；公共事件页敌群条目改为可跳转。
3. 战斗中“当前战斗”区块与**变身**；“运行”页“战斗”卡片的跳转链接。
4. 战斗中**追加**敌人（含兼容性抽查，见 §8.3）。

## 12. 验收标准

1. 在当前地图从“遇敌”区块点“立即遇敌”并确认后，出现遇敌转场并进入指定敌群的战斗；战斗结束回到原地图原坐标。
2. 在敌群页搜索敌人名能找到包含它的敌群，开战效果同上。
3. 剧情或对话进行中、菜单 / 商店中、已在战斗中、传送中时，开战按钮置灰或被拒绝，并显示原因；不会在条件满足后自动开战。
4. “战败后继续”关闭时战败进入游戏结束画面，确认框事先提示；开启时战败后回到地图。
5. 关闭“运行”页的“遇敌”开关后仍可手动开战；手动开战不改变该开关。
6. 控制台 `ChayaEdit.troop(id)` 战斗结束后不再退出游戏。
7. 游戏未在线时，敌群页与地图“遇敌”区块可浏览，操作按钮置灰并提示“启动游戏后可用”。
8. 战斗中把敌人 A 变成 B 后，画面、名称立即（局内为关闭面板后）变为 B，HP 为 B 的上限；战后经验、金钱、掉落按 B 结算。
9. 战斗中追加敌人 B 后，B 出现在画面上且不与其他敌人重叠（放得下时），可被选为目标，下一回合开始行动；打倒全部敌人（含 B）才胜利，结算包含 B。
10. 不在战斗中时“当前战斗”区块不出现；战斗结算中变身 / 追加被拒绝；追加失败时场上不出现无法选中的隐形敌人。
