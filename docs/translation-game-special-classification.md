## 1. 背景与核心痛点

当前游戏本地翻译系统主要面向 RPG Maker、Galgame 等日语游戏，通过本地翻译模型完成游戏文本的批量翻译。随着翻译规模不断扩大，现有方案在翻译质量、处理速度和特殊文本适配方面逐渐暴露出瓶颈：

### 1.1 翻译质量不足

传统机器翻译模型偏向通用文本，对游戏特有的语言表达支持有限：

- **人物对白**：口语化表达、角色语气、敬语及复杂情绪变化。
- **特殊发声**：角色受伤或濒死时的惨叫、喘息、呻吟、咳嗽、哭泣等非标准日语词汇。
- **拟声拟态**：动作音效、环境声音、大量重复音节（如「あっ……」「う、うそ……っ」）。
- **复杂上下文**：省略主谓、隐含语义、高度依赖当前剧情的表达。
- **游戏特殊格式**：控制码（如 `\V[n]`、`\N[n]`、`\C[n]`）、特殊占位符及换行排版。

此类文本若仅靠通用分词或词典匹配极易崩溃，且同一段文本往往同时包含痛苦、恐惧等复合情绪，无法简单归入单一类别。

### 1.2 翻译速度与质量难以兼顾

全量文本使用大参数语言模型会急剧增加计算资源消耗与耗时，对于动辄数万至数十万条文本的游戏脚本而言不可承受：

- 必须保持本地低资源占用，保证高吞吐批量翻译。
- 避免所有文本都经过复杂模型进行二次处理，必须分流。

### 1.3 翻译异常缺少系统化积累

- 当前翻译流程中的漏译、误译和格式损坏尚未形成闭环的数据反馈机制。
- 单次单点修复无法阻止同类问题在后续游戏中重复发生。
- 高质量日中游戏语料（特别是特殊发声与情绪对白）人工采集成本极高，急需在日常翻译中实现自动化结构化沉淀。

## 2. 总体目标与核心原则

### 2.1 四大核心目标

1. **提升当前翻译质量与性能**：优化本地轻量推理与批量吞吐，完善控制码保护与确定性异常捕获。
2. **建立独立的多维文本分类系统**：构建模型驱动的文本理解与打标模块，对游戏文本输出结构化多维标签。
3. **建立持续的数据积累机制**：以沉淀资产为核心，持续记录原文、译文、上下文、多维标签及置信度。
4. **为未来模型优化提供基础**：为后续动态示例检索（Few-Shot）、小模型微调（LoRA）及第三方协同提供数据基础。

### 2.2 核心设计原则

- **性能优先**：主翻译流程坚决不因分类、打标、审核或修正任务而发生阻塞。
- **模型分类**：文本语义、情绪、发声及表达特征由模型统一识别，不依赖僵化关键词词典。
- **多维多标签（Multi-label）**：允许单文本同时挂载多个维度标签，真实还原复杂语境。
- **数据优先**：本阶段以“数据采集、分类与沉淀”为主，不急于盲目启动模型微调。
- **双轨解耦**：分类系统与主翻译流程彻底解耦，支持离线、增量与批量执行。

## 3. 多维文本分类打标体系（Schema 规范）

分类系统面向所有游戏文本设计，初期优先处理异常与高风险文本，后续逐步扩展。

### 3.1 分类维度定义

| 分类维度                           | 涵盖范围与示例                                                            |
| :--------------------------------- | :------------------------------------------------------------------------ |
| **文本类型 (text_type)**           | 对白（Dialogue）、旁白（Narration）、系统UI/菜单、动作/心理描写、环境音效 |
| **情绪 (emotion)**                 | 愤怒、恐惧、喜悦、悲伤、痛苦、羞耻、冷漠、温柔（支持复合多选）            |
| **语气 (tone)**                    | 命令、疑问、恳求、讽刺、撒娇、敬语、粗鲁、傲娇、迟疑                      |
| **声音类型 (voice_type)**          | 惨叫、喘息、呻吟、哭泣、咳嗽、狂笑、呢喃、叹息                            |
| **表达特征 (expression_feature)**  | 重复音节、拖音（〜/ー）、停顿（……）、结巴/短促（っ/ッ）、省略             |
| **翻译风险 (translation_risk)**    | 语义歧义、高度依赖上下文、特殊双关/俚语、非标准假名发音                   |
| **翻译异常 (translation_anomaly)** | 漏译（假名残留）、误译、语气/情感丢失、控制码/变量损坏、模型复读          |

### 3.2 语料存储元数据 Schema

沉淀的数据不仅包含单句，必须绑定完整上下文以保证后续训练价值：

- `original_text`: 日语原文
- `translated_text`: 中文译文（若已翻译）
- `context`:
  - `speaker`: 发言角色名称 / ID
  - `scene_id`: 地图 ID 或场景编号
  - `prev_lines`: 上文 1~2 句文本
  - `next_lines`: 下文 1~2 句文本
- `labels`: 多维标签键值对（支持每类多个值）
- `model_meta`: 打标模型名称、版本、打标置信度（Confidence）、推理理由（Reasoning）
- `status`: 待处理 / 已打标 / 人工已审核 / 第三方已修正

## 4. 实施范围、分期规划与里程碑验收（Milestones & DoD）

按**“固基 -> 闭环 -> 资产 -> 反哺”**递进演进，前一阶段达到验收准则后开启下一阶段。

```
M1: 翻译基线加固与异常捕获（P0 阶段）
       │ 交付物：无损控制码管道、轻量推理吞吐基线、确定性异常拦截库
       ▼
M2: 独立多维分类引擎与打标闭环（P1 阶段）
       │ 交付物：7 维多标签体系、异步解耦调度器、首批异常样本打标
       ▼
M3: 数据资产化管理与流转体系（P2 阶段）
       │ 交付物：多维数据筛选、标准导出导入、第三方/人工处理对接
       ▼
M4: 知识反哺与场景增强（进阶阶段）
       │ 交付物：动态 Few-Shot 示例检索、高频口癖规则库、微调数据集自动化生成
```

---

### Milestone 1: 翻译基线加固与异常捕获（P0）

- **目标**：不依赖分类，先把现有翻译流程跑顺、提速，建立坚固的控制码防火墙与确定性异常捕获机制。
- **核心交付物**：
  1. **格式保护与预处理引擎**：升级控制码、变量、标点转换器，实现 `原文 -> 占位符脱敏 -> 模型翻译 -> 占位符还原与校验` 的无损闭环。
  2. **轻量模型基准评测矩阵**：评估 2~3 款适合端侧/本地运行的模型，确立标准配置与并发吞吐指标。
  3. **确定性质量与异常检测器**：基于启发式规则（假名残留、格式丢失、复读检测、空译）实现零延迟的异常判定。
  4. **异常数据初始归档库**：被拦截的异常文本及其上下文（Speaker、前后句）自动落盘保存为待处理记录。
- **验收准则（DoD）**：
  - [ ] 完整翻译一本标准中型 RPG 脚本（3~5 万行），占位符/控制码损毁率为 0。
  - [ ] 本地推理吞吐量与稳定性达到基线预期（无内存泄漏、无崩溃挂起）。
  - [ ] 异常文本能够 100% 捕获并落入本地待处理库，且完全不阻塞主流程。

---

### Milestone 2: 独立多维分类引擎与打标闭环（P1）

- **目标**：建立与主流程完全解耦的模型驱动分类管道，完成首批异常文本与高风险文本的自动化结构化打标。
- **核心交付物**：
  1. **分类体系 Schema 固化**：正式固化 7 大维度枚举与 JSON Schema 输出约束。
  2. **独立异步分类任务调度器**：支持离线、增量、批量拉取未打标记录，调用指定分类模型进行多标签打标。
  3. **多标签存储结构设计**：持久化保存包含原文、上下文、多维标签、模型版本、置信度的完整结构。
  4. **首期定向打标验证**：针对 M1 积累的异常库，执行全量自动化打标与准确性验证。
- **验收准则（DoD）**：
  - [ ] 分类服务可作为独立命令行或后台 Job 运行，支持断点续打、重试与速率控制。
  - [ ] 抽样评估 200 条典型发声、情绪对白与异常句子，模型的标签打标合理率（人工判定）≥ 85%。
  - [ ] 分类结果与翻译表解耦存储，翻译结果更新时不破坏既有标签沉淀。

---

### Milestone 3: 数据资产化管理与流转体系（P2）

- **目标**：让沉淀的数据“可看、可查、可导、可流转”，为第三方协作与人工微调提供完备工具链。
- **核心交付物**：
  1. **数据检索与多维筛选器**：支持按情绪、声音类型、翻译异常等多维度交叉过滤查询。
  2. **标准化数据导出导入套件**：
     - 导出为标准格式（JSONL / CSV），携带完整上下文元数据。
     - 支持导出为 Prompt-ready 标注模板或第三方大模型修复任务输入格式。
     - 支持外部人工标注/第三方修复结果的结构化二次导入与增量合并。
  3. **数据清洗与去重工具**：过滤高频纯重复拟声词，保留高价值长尾表达。
- **验收准则（DoD）**：
  - [ ] 能一键导出特定标签集（例如：`声音类型=呻吟/喘息 AND 异常=漏译`）用于分析或外部批量修复。
  - [ ] 外部修改后的 JSONL 能够无缝回填/更新系统中的译文和状态标记。
  - [ ] 形成首个包含 1,000+ 条高质量对齐标记的本地游戏特殊语言表达语料库。

---

### Milestone 4: 知识反哺与场景增强（进阶演进）

- **目标**：将积累的数据资产反哺回翻译系统，不训练全量模型也能显著改善特殊文本表现。
- **核心交付物**：
  1. **动态 Few-Shot 示例检索（RAG 增强）**：基于 M3 沉淀的高分打标对齐样本，在主流程遇到高风险文本时，动态检索 2~3 个同类型优质译例注入 Prompt。
  2. **高频特殊发声/口癖映射表自动生成**：从标注沉淀中萃取高置信度模式，作为前置规则字典快速拦截。
  3. **微调（SFT / LoRA）训练集自动化生成器**：一键生成符合主流微调框架指令格式的训练/评估集。
- **验收准则（DoD）**：
  - [ ] 特殊发声与语气词在引入动态示例后，一次翻译合格率提升 ≥ 30%。
  - [ ] 成功产出首批可直接供轻量小模型 LoRA 训练的格式化数据集。

---

### 4.5 现阶段明确暂不纳入的范围（Out of Scope）

为保证前期专注，以下特性暂不在当前交付周期内：

- 全自动复杂文本在线实时二次修正。
- 大规模人工标注与外包审核流程接入。
- 独立端侧分类模型的正式预训练。
- 翻译模型全量参数微调。
- 第三方付费商业翻译 API 的自动化代付流转。

## 5. 双轨系统架构与数据流转

系统严格采用主翻译流程与数据处理流程分离的架构设计：

```text
【主翻译流程 (实时 / 高吞吐 / 零阻塞)】
游戏文本提取
    ↓
文本预处理 (控制码占位化、标点归一)
    ↓
本地轻量模型翻译
    ↓
确定性质量检测 (启发式规则)
    ├── 正常 ────────────→ 保存译文，继续后续翻译
    └── 异常 (漏译/破损) ─→ 记录异常数据池 (携带 Speaker 与上下文)
                            ↓
【独立数据处理流程 (异步 / 离线 / 资产化)】
待处理数据池 (已译文本 / 异常记录)
    ↓
独立调度器 (速率控制、批处理)
    ↓
模型多维打标 (7 维度多标签识别)
    ↓
结构化存储 (解耦独立存储，避免覆盖译文)
    ↓
多维筛选与格式导出 (JSONL / 外部处理)
    ↓
第三方修复 / 人工审核回填 (M3)
    ↓
动态 Few-Shot 检索 / LoRA 语料沉淀 (M4)
```

## 6. 预期成果与系统愿景

1. **更高效的本地翻译能力**：在低资源消耗下，消除控制码损毁，提高整包游戏吞吐量。
2. **可扩展的游戏文本理解体系**：建立针对对白、语气、情绪、特殊发声的标准多维标签能力。
3. **高复用性本地语料数据资产**：从日常游戏中自发沉淀高价值游戏语料，告别高昂的人工收集成本。
4. **平滑的未来模型迭代通路**：通过从规则到示例增强，再到模型微调的平滑过渡，持续提升复杂发声与口语对白的本地化品质。
