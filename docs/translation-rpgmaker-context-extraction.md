## 1. 背景与核心痛点

在当前的文本抽取与翻译管线（`services/extract/`）中，游戏文本主要被划分为粗粒度的「对话（dialogue）」与「剧情/旁白（story）」。在实际的日系 RPG 翻译与理解过程中，暴露出以下核心痛点：

### 1.1 说话人缺失导致主客体混淆与人称误译

日语句子中高频省略第一人称（私/俺/僕）与第二人称（あなた/お前/君），依赖说话人身份与对话双方关系来确立动词方向与授受动词（あげる/くれる/もらう）。缺少说话人时：

- 翻译模型极易颠倒动作发起者与承受者（如将“我送给你”翻译成“你送给我”）；
- 无法选用符合角色设定的口吻（如傲娇大小姐、粗鲁战士、谦卑仆人、年迈长者）；
- 译文无法保持同一个角色在全剧中的自称与语气一致性。

### 1.2 表达形态（当面对话 vs 心声独白 vs 旁白）边界模糊

在 RPG Maker 中，角色当面说出的话、内心的自我吐槽/暗自揣测、以及第三人称旁白在显示机制上有明确差异，但当前抽取统一打为 `dialogue` 或 `story`：

- 模型常将角色在内心的腹诽（Monologue）误翻为直接对 NPC 说出口的挑衅冒犯台词；
- 将悬浮字幕或全屏旁白误当成当前地图 NPC 的发言。

### 1.3 戏剧演出与情绪线索严重丢失

RPG Maker 的事件指令流包含丰富的上下文特征（如头顶气泡表情、字体放大缩小、紧随受击音效、地图真实地点名等）。这些信息目前在抽取时全部被忽略，导致模型只能“盲看干瘪文字”，丢失了愤怒、悲伤、呢喃、大喊等关键语气判断依据。

## 2. 核心目标与设计原则

### 2.1 核心目标

1. **多层级说话人精准识别**：覆盖日系 RPG Maker 常见的显式标记、插件控制码、原生参数、头像反查与事件名兜底，说话人识别覆盖率达到 85% 以上。
2. **细化表达形态（Speech Mode）**：准确区分「当面对话（Spoken）」、「内心独白（Monologue）」、「场景旁白（Narration）」与「系统提示（System）」。
3. **抽取演出与情绪暗示特征**：解析头顶气泡表情（Balloon）、音量特征（字体缩放码）、停顿节奏与场景空间地名。
4. **构建连续对话轮次滑动窗口**：为每条对白串联前后轮次（Turn-taking）及对话双方，为代词指代还原提供依据。
5. **格式无损与正文安全**：提取标记的同时，确保待译正文干净、占位符安全闭合，不污染通用翻译缓存。

### 2.2 核心设计原则

- **多层降级，绝不误伤**：自顶向下执行优先级流水线，高置信度显式标记优先；兜底规则宁可标记为 `unknown` 也不胡乱猜测。
- **正文纯净化**：剥离或保护如 `【アリス】`、`\n<Alice>` 等姓名外壳，送译正文不残留格式噪声，也不导致重复翻译角色名。
- **数据驱动反查**：利用游戏自带的 `Actors.json`、`MapInfos.json`、`Enemies.json` 等静态数据库实现动态映射，不依赖外挂的巨大词典。
- **双轨解耦输出**：抽取出的上下文元数据作为附加属性（Metadata）存储，既不破坏原有数据结构兼容性，又能直接被 UI、Prompt 组装器和 M2 打标引擎消费。

## 3. 说话人（Speaker）全场景识别规范

抽取器在遍历事件指令流（`cmd.code === 101` 等）时，按 **P1 至 P8 的优先级流水线** 依次匹配，命中后即确定 `speaker` 与 `speakerSource`：

```
[P1] 文本首部定界符
       │ 未命中
       ▼
[P2] 插件名字框控制码
       │ 未命中
       ▼
[P3] MZ 原生指令参数
       │ 未命中
       ▼
[P4] 角色变量控制码展开
       │ 未命中
       ▼
[P5] 头像反查角色表
       │ 未命中
       ▼
[P6] 前置注释 / 插件指令
       │ 未命中
       ▼
[P7] 战斗敌群怪物名
       │ 未命中
       ▼
[P8] 地图具名事件名兜底
       │ 未命中
       ▼
[兜底] speaker = undefined (由形态规则判定为旁白或未指明对白)
```

### 3.2 说话人定界符防误判过滤（Anti-Spoofing 规则）

在日系 RPG 中，括号除了表示角色姓名外，还常用于系统提示、章节标题或场景切换说明。P1 在提取定界符内容后，**必须通过以下白名单/黑名单过滤**，未通过者不得判定为 `speaker`：

1. **系统与提示类黑名单**：
   - 排除提示/操作类：`/(?:ヒント|操作|システム|Tips|Notice|Tutorial|ルール|ヘルプ|注意|警告|案内)/i`；
   - 排除获取/变更类：`/(?:入手|獲得|消費|装備|購入|売却|アイテム|スキル|クエスト|ミッション)/i`；
   - 排除状态/时间类：`/(?:回想|過去|現在|翌日|数日後|数時間後|数年後|夢|記憶|場面|視点)/i`；
   - 排除章节/场景类：`/(?:第[0-9一二三四五六七八九十]+[章幕節話]|Chapter|Prologue|Epilogue|Ending|Opening|Stage|Area|Map)/i`。
   - _处置_：此类定界符判定为**场景标记或系统提示**，不作为说话人，按其语义转入 `sceneHint` 或保留在原位。
2. **控制码解构与内联清洗**：
   - 若括号内部含有颜色码、图标码或字体码（如 `【\C[2]アリス\C[0]】` 或 `【\I[4]勇者】`），先剥离内部控制码提取纯文本 `アリス` / `勇者`，不能把 `\C[2]` 混入名字。
3. **长度与字符安全阀**：
   - 长度限制：1 ~ 16 个字符；
   - 排除包含算式、纯数字、货币单位、冒号过多或 URL 等明显非人名文本。

### 3.3 头像表情差分（Face Index 容差与 Stem 匹配）

许多作者在 `Actors.json` 中仅注册角色的默认表情头像（例如 `faceName: "Alice", faceIndex: 0`）。在实际剧情中，随着角色喜怒哀乐变化，事件指令 `101` 会传入 `faceIndex: 1`（笑）或 `faceIndex: 2`（怒），甚至换用 `Alice_angry`。

- **一级反查**：精确匹配 `(faceName + "_" + faceIndex)`；
- **二级反查（表情差分容差）**：若未命中，且该 `faceName` 在全游戏中唯一对应某一个 Actor，则允许忽略 `faceIndex` 差分，仍然解析为该 Actor；
- **三级反查（文件名前缀 Stem）**：若 `faceName` 类似 `Actor1_dmg` 或 `Heroine_angry`，按前缀剥离修饰词后匹配主角色名。

## 4. 表达形态与文本类别划分（Speech Mode）

在确定说话人的同时，必须为每条文本标记**表达形态**，明确文本是“说给别人听的”、“心里想的”还是“全屏旁白”：

### 4.1 窗口物理模式（Window Background）

指令 `101` 的 `parameters[2]`（Background）是游戏作者表达剧情意图的最直接机制：

- **`0` (常规窗口 Window)**：默认判定为 **`spoken`（当面对话）**。
- **`1` (暗淡变黑 Dim)**：绝大多数作者用于表现 **`monologue`（心声独白、心理描写、回忆场景）**。
- **`2` (完全透明 Transparent)**：常用于全屏剧场、场景标题或 **`narration`（场景旁白）**。

### 4.2 标点语义增强（Quote Semantics）

分析文本首尾的成对标点符号，辅助矫正或补充形态：

- **日文角引号 `「……」`**：确认为角色发声台词；若前置未识别出 speaker，标记为 `category = dialogue, speaker = undefined`。
- **圆括号 `（……）` 或 `(……)`**：确认为内心独白、耳语或小声自语，将形态重载为 `speechMode = monologue`。
- **双角引号 `『……』`**：记录 `quoteType = double_corner`，作为传音、回忆或引用等候选线索；仅凭引号不能确定表达形态，不新增契约外的 `speechMode` 值。
- **空引号 / 无括号且无头像**：若同时为透明窗口或无说话人，判定为 `category = story, speechMode = narration`（旁白描述）。

### 4.3 滚动字幕与系统文案

- **滚动字幕（Scrolling Text）**：指令 `105`（Setup Scrolling Text）+ `405`（Scroll Text），标记 `speechMode = scrolling`，专用于序章故事、世界观背景和制作人名单。
- **系统文案（System Prompt）**：匹配道具、金币、经验获得或系统状态变更，标记 `category = system`，剥离说话人属性。

### 4.4 连续多页对白与选项上下文继承

1. **连续多页同人对白继承**：
   - 当同一事件内连续出现多个 `101` 对白指令，若后序指令没有设置头像（`faceName` 为空）且首行未写新定界符，判定为**前一位角色的言论延续**，自动继承前一条对白的 `speaker`。
2. **选项分支（Command 102）上下文继承**：
   - 选项本身没有角色，但选项紧跟在某句提问之后。
   - 选项块自动挂载 `promptSpeaker`（提问者）与 `promptText`（上一句提问对白），方便翻译选项时（如「はい」「いいえ」）结合提问语义提供更精准自然的对仗译文。

## 5. 演出、情绪与发声特征抽取

为模型提供深层次的情绪与语气线索：

### 5.1 头顶表情气泡（Balloon Icon / MV 指令 Code 213）

在指令 `101` 紧邻前 3 条指令范围内出现的 `Code 213`，提取并映射为标准情绪提示。MV 的 `212` 是动画指令，不能当作气泡；其他引擎由适配器核对编号：

- `1: !`（惊愕/警觉，提示短促有力）；
- `2: ?`（困惑/纳闷）；
- `3: ♪`（轻快/愉快/得意）；
- `4: ♥`（娇羞/好感/撒娇）；
- `5: 💢`（暴怒/烦躁/粗鲁）；
- `6: 💧`（尴尬/冷汗/无奈）；
- `8: ……`（无语/沉思/欲言又止）；
- `9: 💡`（恍然大悟/自信）；
- `10: Zzz`（困倦/梦话）。

### 5.2 发声与音量控制码（Volume & Rhythm Hints）

- **大声呐喊（Shout）**：文本包含 `\{`（字体放大），尤其连续多个时，标记 `volumeHint = shout`。
- **低语呢喃（Whisper）**：文本包含 `\}`（字体缩小），尤其连续多个时，标记 `volumeHint = whisper`。
- **结巴/停顿（Stutter / Hesitation）**：文本包含 `\.`（等待15帧）、`\|`（等待60帧）或多个促音 `っ`，标记 `rhythmHint = hesitant`。

### 5.3 紧邻演出音效（Sound Effects）

- 若对话前紧邻指令 `250`（Play SE）播放惨叫（Scream）、受击（Damage）或喘息声，标记 `hasPainSound = true`，辅助模型在面对语气词时选用符合负伤语境的汉字。

## 6. 地理场景与连续对话轮次

### 6.1 空间场景名称绑定（Scene Context）

- 依据 `block.map` ID 读取 `MapInfos.json` 或 `MapXXX.json`：
  - 提取 `displayName`（玩家屏幕上可见的地点名，如 `王都地下牢`、`静謐の教会`）；
  - 若 `displayName` 为空，使用地图内部工程名 `name`（如 `牢房一层`）；
  - 作为 `scene` 字段注入上下文，使模型建立场所氛围感知（庄重、世俗、恐怖或日常）。

### 6.2 连续对话轮次滑动窗口（Turn-taking Window）

在同一事件流中连续出现的多个对话块组成一个 Session：

- 记录对话序号（`turnIndex: 0, 1, 2...`）；
- 为每条对白维护滑动上下文：
  - `prevSpeaker` 与 `prevText`（前一轮对话人与内容）；
  - `nextSpeaker` 与 `nextText`（后一轮对话人与内容）；
- **核心作用**：解决日语对白中“省略主语”导致的翻译崩塌，让模型利用上文的提问人准确补齐下文回答中的代词。

## 7. 数据结构规范（Schema 契约）

在抽取结果及单条记录中扩展上下文对象，保持向前兼容：

```ts
export interface DialogueContextMetadata {
  /** 规范化后的说话人姓名（如 "アリス"、"村長"） */
  speaker?: string
  /** 剥离控制码与定界符后的纯净正文（若首行仅为名字，则去除首行） */
  cleanedLines?: string[]

  /** 说话人来源判定途径 */
  speakerSource?:
    | 'markup' // 首部括号 【名】
    | 'plugin_code' // \n<名>、\name<名>
    | 'engine_param' // MZ p[4] 原生参数
    | 'control_code' // \N[1] 展开
    | 'face_actor_map' // 头像反查 Actors.json
    | 'face_fallback' // 头像文件名兜底
    | 'preceding_command' // 注释/前置指令
    | 'troop_enemy' // 战斗敌群名
    | 'event_name' // 地图事件名

  /** 表达形态 */
  speechMode: 'spoken' | 'monologue' | 'narration' | 'scrolling'

  /** 引号类型 */
  quoteType?: 'corner' | 'round' | 'double_corner' | 'none'

  /** 情绪与发声暗示 */
  emotionHint?: 'surprise' | 'question' | 'joy' | 'affection' | 'anger' | 'sweat' | 'silence' | 'idea' | 'sleepy'
  volumeHint?: 'shout' | 'whisper' | 'normal'
  rhythmHint?: 'hesitant' | 'normal'
  hasPainSound?: boolean

  /** 选项分支关联的提问上下文 */
  promptSpeaker?: string
  promptText?: string

  /** 地理与场景 */
  scene?: string
  mapId?: number

  /** 多轮对话流 */
  turnIndex?: number
  prevSpeaker?: string
  prevText?: string
}
```

在送给翻译引擎或分类模型时，在 Prompt 构造器（`lib/translate/engine-http.ts`）中映射为结构化提示；扩展时保留既有 `category / speaker / context` 输入与无新增元数据时的行为：

```text
【上下文信息】
- 说话人：アリス
- 表达方式：内心独白（未说出口的心声）
- 场景地点：王都地下牢
- 情绪暗示：警觉、紧张
- 上一轮对话：[衛兵]「誰かそこにいるのか？」
```

## 8. 验收准则（DoD）

1. **测试用例全覆盖**：
   - 编写针对 P1~P8 各种边界情况的单元测试集，涵盖：
     - 首部带 `【名】`、`［名］`、`\n<名>` 的正文提取与姓名剥离；
     - MZ 原生 `p[4]` 正常读取；
     - `Actors.json` 头像双向映射与 `\N[1]` 展开；
     - 排除 `EV001` 等系统事件名，保留有效 NPC 名字；
     - 窗口背景 `0/1/2` 准确对应 `spoken` / `monologue` / `narration`；
     - MV 气泡指令 `213` 与音量缩放码解析，`212` 不误判为气泡。
2. **正文提取安全性**：
   - 提取说话人后，待翻译正文不出现残余孤立括号（如残留的 `】` 或 `>`）；
   - 剥离的说话人标签不进入正文翻译词表，避免造成“角色名被二次翻译”的问题。
3. **管线与导出贯通**：
   - 抽取后的 `speaker` 和 `context` 正确体现在抽取中间件与 `/translate/list` 搜索加权中；
   - 构造的翻译 Prompt 在有无上下文时表现稳健，不出现 undefined 占位符。
4. **性能影响**：
   - 完整抽取一份 3~5 万行的中大型 RPG Maker 项目，上下文解析与头像反查带来的额外耗时增加不超过 5%。
