# Chaya 会议纪要

- **日期**：2026-09-19
- **议题**：翻译 / 修改工具独立化、与 NW.js / RPG Maker 游戏目录的关系
- **相关工程**：当前游戏内容在 NW.js `app.nw` 内；计划独立工具 **Chaya**

---

## 1. 背景

游戏需通过 **NW.js** 运行。已有能力包括：

- 翻译流水线：`translate-both.js` + NDJSON 缓存 + 质检重译
- 游戏内：`MTool_Trans_Loader`（汉化热更新）、`GameEdit`（`` ` `` 开表格改物品/变量等）、`GameBoost`

目标是做一个可复用工具，覆盖 **翻译管理** 与 **内容/数据修改**，且能换游戏、可迁移，不绑死某一作。

---

## 2. 结论摘要

| 议题          | 结论                                                     |
| ------------- | -------------------------------------------------------- |
| 工具形态      | **独立本地服务 + Web UI**（非常驻塞进游戏包）            |
| CLI           | 仅作附属（如启停翻译），**不作主入口**                   |
| 与游戏关系    | **选择游戏内容根路径**，读写原目录；**禁止复制**整份游戏 |
| NW.js         | **单独保留干净外壳**；启动时把内容根传给 NW.js           |
| 软链 `app.nw` | 可选快捷方式，**不当主方案**                             |
| 前端技术栈    | **TypeScript + Tailwind CSS**                            |
| 开发节奏      | 先定方案，再实现（用户要求确认后再写代码）               |

## 3. 形态：服务，而不是拷进游戏

### 3.1 为什么

- 游戏体积大，**不能也不该**把工具或内容整包复制进每个工程
- 工具需 **随时迁移**（整个 Chaya 目录可搬走）
- 换作只改「当前游戏路径」，不重新部署工具

### 3.2 定案

```
Chaya（独立目录，可迁移）
  └─ 本地服务 + TS/Tailwind Web UI
        │
        ├─ 配置中保存：游戏内容根、可选 NW.js 路径
        ├─ 读写：翻译缓存 / 开关 / data 等（均在所选游戏目录）
        └─ 可选：用 NW.js 启动该内容根

游戏（www 或 app.nw 内容根）—— 原位不动，不复制
NW.js 外壳 —— 与游戏、工具三者分离
```

- 浏览器打开本地地址（如 `http://127.0.0.1:xxxx`）使用界面
- 配置持久化在工具目录（如 `config.json`），不写进游戏大文件树里作为「安装标记」

---

## 4. 游戏路径：直接指向内容根（含 www）

### 4.1 什么是「内容根」

含 `index.html` + `data/` + `js/` 的目录，即 RPG Maker 的 **`www` 内容**，或已展开的 **`app.nw` 目录包**。

### 4.2 路径自动识别（约定）

用户可选中以下任一，服务解析为内容根：

1. 内容根本身（当前这种展开的 `app.nw` / 解压后的 `www`）
2. 发布目录下的子目录 `www/`
3. macOS `.app` → `Contents/Resources/app.nw`

翻译相关文件（`ManualTransFile.json`、`translate-both.cache.ndjson`、`translate-both.js`、`translate-switches.json` 等）在 **内容根或其上一级** 查找。

### 4.3 明确不做

- 不把 Chaya 做成必须复制进每个 `www` 的附属文件夹才能用
- 不以「工具必须和游戏同级拷一份」为工作流

---

## 5. NW.js 外壳与软链

### 5.1 外壳

- **单独保存一份干净的 NW.js**（SDK 或正式版均可）
- **不要**把唯一一份游戏内容长期嵌死在 SDK 的 `Resources/app.nw` 里（难迁移、难升级外壳）

### 5.2 启动方式（主方案）

```bash
/path/to/nwjs.app/Contents/MacOS/nwjs /path/to/游戏内容根
```

Chaya「启动游戏」即：已配置的 NW.js 路径 + 当前选中的内容根。

### 5.3 软链（可选）

- 可将 `Contents/Resources/app.nw` **软链**到某作内容根，方便双击外壳
- 软链是指针，**不是复制**
- 换作要改链；多作并行时不如「启动参数指向目录」清晰
- **主工作流仍用选路径 + 传参启动**

### 5.4 体积原则（用户强调）

> 反正别复制就行了，因为游戏可能很大。

所有方案均遵守：**游戏资源原位引用，工具与外壳都不拷贝游戏内容。**

## 6. 职责划分

| 能力                                                                     | 由谁负责                                               |
| ------------------------------------------------------------------------ | ------------------------------------------------------ |
| 翻译开关、缓存检索/手改、启停 `translate-both`、浏览 data、查变量/开关名 | **Chaya 服务 UI**                                      |
| 运行时金钱 / 背包数量 / 变量值 / 开关状态                                | **游戏内 GameEdit**（快捷键 `` ` ``）                  |
| 对话/UI 汉化热更新                                                       | **游戏内 MTool_Trans_Loader**（读所选游戏里的 NDJSON） |
| 跑游戏进程                                                               | **NW.js 外壳** → 指向内容根                            |

## 7. 技术栈（Chaya）

| 层       | 选型                                          |
| -------- | --------------------------------------------- |
| 前端     | TypeScript + Tailwind CSS                     |
| 后端     | 本地 Node 服务（实现阶段再定 JS/TS 同仓结构） |

| 依赖游戏 | 仅路径配置，无游戏文件打包进工具              |

## 8. 与现有游戏内改动的关系（备忘）

已在当前作中做过、可随内容根一起走的部分：

- 翻译缓存质检：译文仍含日文则剔除并重译；不合格结果不入库
- MTool：NDJSON 热更新（轮询 + watch）
- GameEdit：表格面板，`` ` `` 开关；`package.json` 中 `devtools: false`
- 早期曾在 `app.nw/toolkit` 放过原型；**正式方案改为工具独立目录**，不依赖拷进游戏
