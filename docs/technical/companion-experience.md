# 旅伴条件经验：实际 HP 观察

> 有效性：现行；2026-10-30。
> 范围：核心重构 T7 的首个增量，只归纳实际 HP 观察并供战术判断和聊天检索。沿用重构方案 §8 的来源、存储和管理屏障，不替代累计遭遇统计。
> 不包含：通用机制推理、资源消耗归因、模型假设持久化、跨周目迁移、新执行能力或完整 T7 验收。

## 来源与交互

```text
引擎行动结果 → 原有记录批次 → 存储确认
                                ↓
                   有界记录读缓存（最多 512 个事件）
                                ↓
                  代码归约 HP 条件经验（无模型调用）
                      ↙                     ↘
             战术判断上下文               聊天上下文
             引用校验及原有采纳屏障       引用校验及代码摘要
```

经验是已确认记录的可重建读投影，没有第二条写通道。恢复时使用同一快照中的 `recentEvents` 重建。清理、版本重载、关闭记录与旧批次拒绝继续由原有存储事务和宿主版本屏障管理。关闭记录后可检索之前的经验，但不能用关闭期间的实时状态新增经验。

投影版本为 1，覆盖范围固定为 `retained_observations`，携带 `memoryEpoch` 和 `detailsTrimmed`。样本量只描述保留窗口，不代表完整历史；细节裁剪后结论只根据剩余证据重新归约，不能声称反例从未存在。累计遭遇统计不由此投影重建。

## 归组与最小样本

- 游戏、数据版本、周目严格隔离。同周目不同实例、读档分段的观察允许在相同条件下汇集；行动与遭遇计数使用完整实例 / 分段身份去重，引用保留完整 scope。首增量不跨周目检索。
- 归组条件：来源实体种类和 ID、技能 / 物品种类和 ID、目标实体种类和 ID、目标生命上限、行动前目标状态 ID 集合、行动前血量段。血量段为 ≤30%、≤70%、>70%；未知字段不能视作相同的已知条件。
- 只接收 `observed_action` 且来源、能力、行动前后 HP 可确定的记录。未知归因、旧记录缺失证据、仅报告伤害而无实际前后 HP 的结果不参与。负 HP、超过已知上限和无效 HP 区间不参与。
- HP 减少量 = `hpBefore - hpAfter`，负值为实际恢复。伤害受零血截断、治疗受满血截断；报告值不覆盖实际值。零变化只是零变化，不推定未命中、免疫或技能无效。
- 每条合法目标结果保留，行动数按完整遭遇身份 + `actionId` 去重；同一次群攻 / 多段命中不能伪装成多次独立行动。不统计 MP、TP、道具消耗，避免按目标重复计费。
- 以时间及稳定身份排序后的首条非零变化作为候选方向；全零时仅观察“HP 未变化”。后续零变化或相反方向变化是该候选的反例。支持与反例均展示计数，各保留至多 3 条完整来源引用。
- 至少 3 次独立行动、2 场独立遭遇、上述目标条件已知，且方向一致、非零、没有反例，状态才为 `conditionally_supported`。出现反例立即变为 `has_counterexamples`；其余为 `observation_summary`。这只是保留样本的方向一致性，不是机制确认或统计置信度。
- 首增量不产生 `unverified_hypothesis`。当前目标的上限、血量段或状态集合不同时标记 `conditions_differ`（当前不适用），字段缺失为 `unknown`；只在所列目标条件均匹配时标记 `matching_observed_conditions`。同 ID 的多个目标只需有一个匹配，使用时仍需核对具体目标。来源属性、装备、等级等没有采集，始终列为未知。

## 消费与限制

检索按当前敌人过滤，优先当前目标条件匹配的观察，然后按时间排序；默认至多 3 条，硬上限 8 条。返回值与缓存分离，调用方不能改写归约结果。输入缓存变更或管理清理即失效，空闲轮询不重复归约。

战术请求携带经验 ID、条件、范围、状态、样本量、HP 区间和正反来源。沿用有界 JSON 上下文，超预算整条剔除可选历史；模型只能引用实际送入请求的经验 ID 或经历 ID，不能借未发送的缓存条目通过校验。保持既有规则和玩家约束，经验不会直接驱动输入，也不增加每步模型调用。

聊天通过 `experience_ref` 引用实际发送的经验 ID。显示摘要由代码重建，模型不能用输出字段改写样本数、状态、适用条件或结论；未知引用降级。清理或切换记录使生成中的旧回复失效，原有代际与记忆版本检查保持有效。

新增测试覆盖去重与群攻、范围隔离、未知值、实际恢复截断、反例降级、条件变化、恢复重放与管理屏障，以及战术 / 聊天的引用与上下文裁剪。实际游戏回归只验证这条增量链路，不宣称验证未知机制或完整 T7。

- 自动化：旅伴核心、MV 宿主和存储回归共 36 个测试套件、332 条测试通过；应用与 MV / RGSS 类型检查、MV 插件构建通过。测试脚本另行进行 TypeScript 检查。
- 官方 MV 示例 `LivingShipCowboy_fix1113`，`mv-host-hp-experience-t7-r4`：默认静音启动、两场自动战斗、记录落库和宿主经历检索通过。真实聊天请求携带 3 条条件经验，逐条与持久化引擎记录重新归约的条件、计数、HP 范围、版本和来源引用核对一致。
- 同次请求模型已常驻，加载准备耗时 16 ms、排队 5 ms，但生成在 5 秒首字预算内未返回内容，报 `MODEL_TIMEOUT / First token timeout`。因此尚未实测通过“本地模型返回 `experience_ref` → 宿主展示代码摘要”；这段引用校验和展示当前由自动化覆盖，不能宣称完整实测验收。
- 之前 `r1`、`r3` 在初始语义路由超时，`r2` 在第二场追加 MP 约束的语义路由超时。专项 `r4` 跳过该追加约束检查，默认宿主场景仍保留。未放宽产品模型预算，也未将降级回复当成模型引用成功。

上述目录均位于 `/tmp/chaya-official-rpgmaker/`。`mv-host-hp-experience-t7-r4/hp-experience-context-evidence.json` 保存实际请求与持久化记录核对结果，`host-model-trace.json` 保存模型状态与超时事件，`host-failed.json` 保存宿主失败状态。这些是临时验证产物，不随代码持久保存。

### 远端 Ollama MBA 验证

按用户指定切换为已配置的 `Ollama MBA`（`ollama-mvv2m0pk`），模型 `gemma4:e4b`。宿主测试通过 `CHAYA_SMOKE_PROFILE_FILE` 读取导出的完整 agent 配置，继续保持模型常驻；指定的配置文件读取失败时测试直接报错。

- `mv-host-hp-experience-t7-mba-r1`：远端模型冷启动约 9.0 秒完成；随后语义路由在 5 秒生成预算内超时。
- `mv-host-hp-experience-t7-mba-r2`：已识别模型常驻，语义路由仍超时。两轮均未进入战斗，不能作为 T7 完整宿主验收。
- 单独回放同一语义路由请求，在放宽诊断等待时间后，首字约 8.9 秒、总计约 9.3 秒，返回正确的持续代打意图。该结果仅说明远端可以完成意图判断，不代表满足现行产品预算。
- 单独回放之前官方 MV 两场战斗产生的真实经验上下文，首字约 14.8 秒、总计约 16.2 秒。模型引用了已提供的经验 ID，但将 `blocks` 写为嵌套的 `experience_ref` 对象，缺少约定的 `kind` 字段，结构不合格。调用产品引用校验与渲染函数后确认 `degraded: true`，输出回退为代码生成的真实观察摘要；不能记为模型引用成功。

回放没有游戏控制权限，产品预算保持不变。这些远端模型请求没有回退到本机。证据位于 `/tmp/chaya-official-rpgmaker/` 下的两轮宿主目录，以及 `ollama-mba-route-diagnostic.json`、`ollama-mba-hp-experience-replay.json` 和 `ollama-mba-hp-experience-validation.json`。
