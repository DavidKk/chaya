## 2. 语言注册与能力

新增数据驱动的语言注册表，逻辑字段为 `tag`、展示名、显式别名及版本。标签使用 BCP 47 形式；规范化大小写后保留脚本、地区子标签，不按前缀自动合并。别名必须唯一指向已注册标识，不允许覆盖、循环或链式解析。旧 `zh` 保持独立身份，不批量推断为 `zh-Hans`，也不与 `zh-Hant` 互查。

- 入口解析顺序：显式参数 → 游戏配置 → 历史兼容默认。显式参数存在但无效或未注册时返回校验错误。
- `sourceLanguage/targetLanguage` 进入任务后固定；检测语言只辅助未指定的源语言，不随每次缓存查询重新猜测。
- 引擎适配器维护自身方向映射与资源状态。语言注册成功不等于引擎可用；不能映射或资源未安装时返回结构化能力错误。
- `CacheLang` 等硬编码联合类型逐步替换为经过校验的语言标识；分词、断行等语言策略保留能力表与安全默认，不要求每种语言均有专用算法。
- 质量规则按语言对启用。假名残留仅为适用方向上的风险信号，专名、引用等允许保留；同文译文不一律视为失败。

第一版支持通过导入入口注册语言，不建设独立语言设置页面。初始注册数据覆盖现有五个代码；新增代码只改变数据，模型和分词能力按各自状态显示。

表现性文本资源按 `ja > en > ru > ko > 其他` 建设，以各源语言到中文为首要评估方向；顺序不影响已配置语言对的独立查询。各方向分别记录完整译例、模板与质量验证状态，未验证模板不激活。

## 3. 外置数据包契约

### 3.1 格式

UTF-8 JSONL 首行为 manifest，其余行为完整条目。第一版只接收完整版本包，更新时提交新版本；缺失旧条目表示该包新版本不再提供该条目，不删除用户独立保存的译文。

```jsonl
{"type":"manifest","schemaVersion":1,"packId":"core-game-terms","version":"1.0.0","languages":[{"tag":"ja","name":"日本語"},{"tag":"en","name":"English"}]}
{"type":"entry","entryId":"menu.save.ja-en","sourceLanguage":"ja","targetLanguage":"en","sourceText":"セーブ","targetText":"Save","aliases":[],"scope":{"kind":"global"},"match":{"kind":"exact","category":"menu"},"reviewStatus":"reviewed","provenance":{"kind":"curated","note":"初始术语迁移"}}
```

示例展示逻辑格式，不是已有导入命令。每行只表达一个方向；多语言概念可以共享业务 ID 前缀，不能自动产生反向翻译。manifest 可声明新语言，注册与包激活同事务提交。

| 字段                            | 约束                                                                       |
| ------------------------------- | -------------------------------------------------------------------------- |
| `packId/version/schemaVersion`  | 包身份、发布版本、格式版本；另保存内容哈希及每次激活的单调 revision        |
| `entryId`                       | 包内稳定且唯一；新版本允许更改译文，不更换条目身份                         |
| `sourceLanguage/targetLanguage` | 已注册或本包声明的语言，有向匹配                                           |
| `sourceText/targetText`         | 非空文本，保留原始控制码、空白与重复音节；合法同文允许保存                 |
| `aliases`                       | 显式完整原文别名，仅属于源语言；不能由任意子串生成                         |
| `scope`                         | `global` 或 `game` + 稳定 `gameId`，不以游戏路径充当身份                   |
| `match`                         | 第一版仅 `exact`；可加 category、speaker、scene 等精确条件，缺失条件不命中 |
| `badTranslations`               | 可选的目标语言错误候选，只用于未受保护的机器结果纠偏；不用于语义分类       |
| `reviewStatus/provenance`       | 候选或已审核、来源说明；导入者自报字段不授予 `manual` 写入权威             |

初始迁移保留旧表中的译文、别名及纠偏候选，同时检查歧义。现有宽匹配如 NFKC、跨源语言搜索不得直接继承为安全规则；默认只做现行管线认可的规范化，原文保持不变。纠偏候选若无法确认适用范围，保留为未启用候选。

除上述 `type: entry` 完整译例外，第一版增加 `type: vocal_rule` 资源记录，使用相同的稳定 ID、语言对、scope、审核状态和包版本，但不强制包含 `sourceText/targetText`；改用 `templateKind`、`units` 和 `modifiers` 描述受限发声模板。其 schema 独立校验，不能把缺少译文的普通条目当成规则接受。

- `templateKind` 首版仅支持纯发声序列；`units` 是完整音节到目标文本的显式映射，不执行代码或任意正则。
- `modifiers` 声明允许的重复、拖音、促音与标点处理，限制输入长度与输出扩展量。未配置策略的修饰符直接导致不命中，不能隐式删除。
- 完整译例优先于模板。音节按最长已声明单元匹配，存在多种切分且译文不同则拒绝匹配；模板必须消费整条内容。边界外壳和控制码由现有管线保护，不能把 `はぁ……もう歩けない` 当成纯发声。
- 同优先级模板产生异译时跳过并报告冲突；任何语言对都不继承其他方向的映射。模板执行只生成译文，不生成 emotion、voice_type 等模型标签。
- 初始迁移还覆盖 `FIXED_PHRASES`、发声字符表及 `HONORIFICS`。旧实现中删除促音、删除称呼、重复前一汉字表达拖音等行为逐项审核，不原样启用；存在歧义的完整译例和模板限定本作或场景。

模板采用共享执行器和按语言对配置的资源，具体约束如下：

- 保留原文，先尝试完整译例。模板只在保护控制码后的匹配副本上做 NFC 规范化；维护原始片段映射。NFC 只处理 Unicode 规范等价，不自动合并大小写、近形字符、兼容字母或韩文兼容字母。参照 [Unicode UAX #15](https://www.unicode.org/reports/tr15/)。
- 将已声明的发声单元、重复段、停顿段、标点段解析为有序片段，分别保存原始形式、数量及位置。点号串和省略号、全半角感叹号只有在资源声明后才能按结构等价匹配；逗号、空格不能任意删除或跨越。
- `modifiers` 明确重复范围、计数单位、标点别名和输出策略；默认保留重复与标点，其他策略必须显式配置并经过审核。字素计数与单元重复计数分别定义，不用 UTF-16 长度代替发声次数。
- 英语以已审核完整单元和受限拖长模板处理，大小写策略逐条声明；不将任意重复字母认作发声，不自动将词内拖长还原为普通词。俄语使用独立西里尔字母单元，禁止与拉丁近形字母互换或默认合并 `е/ё`。韩语分别声明完整音节与独立字母形式，不任意拆分拼接或将字母序列自动当作等价音节。
- 对各语言均要求整条消费及无歧义匹配。跨文字、未知字符、未声明修饰或含普通对白时回退。现有 `templateKind` 无法表达的新语言结构需新增执行器能力并验证，不能导入任意脚本规避限制。
- 回归按语言对覆盖重复数量增减、点号数量、逗号、全半角标点、大小写、组合字符、混合对白和未知单元；报告中分别标明已实现、仅完整译例可用和未验证状态。

### 3.2 使用与冲突

- 未审核条目不进入运行时索引。外部包须经预览后显式启用；启用不升级为人工定稿。
- 现有有效本作记录与受保护共享记录先按缓存管线处理。tombstone 为终止信号，不能通过数据包恢复已删除译文。
- 数据包仅填充未覆盖区间，候选顺序为本作限定包 → 全局包；同一范围内选择具有更多已满足条件的候选。条件个数相同且异译则报告冲突，不按加载先后或 ID 静默选一个。
- 任何包命中不得覆盖人工保护区间；未经确认的控制码重排、缺失上下文或字段类型不符均跳过。
- 特殊发声不默认跨场景复用；重复次数、停顿和语气属于原文，不通过全局去重或压缩生成匹配键。

## 4. 存储与原子导入

### 4.1 权威与文件

沿用存储 daemon 单写者，经现有 RPC 扩展操作，不在插件、Next 请求处理器或 CLI 中另开 SQLite 写连接。以下均为拟新增逻辑表，实施时通过既有迁移机制建立：

| 表                                   | 内容                                                      |
| ------------------------------------ | --------------------------------------------------------- |
| `translation_languages`              | 语言与别名注册，注册版本                                  |
| `translation_resource_versions`      | 包版本、哈希、导入来源、格式版本                          |
| `translation_resource_entries`       | 按包版本保存的完整条目，索引语言对、scope、原文键         |
| `translation_resource_activations`   | 有效版本或停用状态、单调 revision、操作回执；保留激活历史 |
| `translation_observations`           | 异常/失败事件与不可变原译文快照                           |
| `translation_collection_checkpoints` | 任务采集游标、积压及未完整状态                            |

第一版放在现有 `translate-cache/shared.sqlite`，通过域接口隔离，避免引入跨库提交。包归档放在数据根下 `translate-resources/archives/`，由统一路径 helper 解析。导入文件和归档不参与运行时直接查找；有效版本只由数据库确定。游戏目录的翻译视图仍为派生只读数据。

包归档和 DB 无跨文件原子事务：先暂存并校验归档，再事务提交版本与激活；提交失败的孤立归档可清理，不允许 DB 指向尚未完成的输入。归档缺失时可从完整条目重建导出，数据库备份需包含新增表。

### 4.2 导入流程

1. 流式解析，限制文件大小、条目数、单行长度与嵌套深度；具体限制配置化。拒绝未知格式版本、重复 ID、非法语言、无效 scope、控制码不一致和不支持的匹配形式。
2. 生成预览：新增/更新/移除/冲突/无效条目，以及受影响语言对与游戏范围；返回输入哈希及所基于的激活 revision。
3. 应用请求携带预览 token、输入哈希、基准 revision 与幂等键；权限与游戏身份按现有存储入口验证。预览后数据发生变化则要求重新预览。
4. 单事务写版本、条目、语言注册、激活状态及回执。错误包全包拒绝；跨包异译作为可见冲突保留，命中时按 §3.2 跳过歧义候选。
5. 同 `packId/version/hash` 重复导入返回已有结果，不隐式重新激活停用包；同版本不同哈希拒绝。重新启用、停用、恢复上一版本为独立激活操作，每次产生更大的 revision。
6. 提交成功后通知连接客户端失效并提供增量拉取；通知失败不回滚数据，下一请求必须通过版本握手补偿。

恢复旧版本只改变激活指针，不降低 revision。语言已被其他包或译文引用时保留注册项，不随包停用删除。

## 5. 运行时快照与缓存

```text
提取 / 实时 / 批量任务
  → 固定语言对与上下文
  → 现有本作保护、删除语义与缓存规划
  → 用外置完整译例填充允许的缺口
  → 未命中的完整纯发声尝试受限模板
  → 剩余缺口调用支持该方向的引擎
  → 格式校验、保存有效结果、提交采集事件

包导入 / 更新 / 停用
  → 存储服务事务提交 activation revision
  → 各入口拉取语言对与游戏范围的只读快照
  → 原子替换索引并重新检查依赖
```

- 运行时索引键包含语言对、scope、完整原文键及条件；同一个请求使用同一快照，不逐条打开文件或查询包表。
- 服务端、CLI、seed worker、MV/RGSS 插件使用同一快照协议和纯匹配函数。快照由本机存储服务提供，按语言对和游戏范围有界分页，不向游戏进程发送全库。
- 新缓存依赖至少包含语言对、匹配规则版本、相关包激活 revision 及已有译文保护版本。只失效受影响分区；通过版本检查兜底丢失的通知。
- 引擎等待后、写回前及插件应用前重新检查依赖；发生更新则重新规划缺口，避免旧任务覆盖已变化的定稿。
- 包命中直接作为带 `packId/entryId/version/revision` 的派生结果返回，第一版不写成无来源的共享定稿。运行时组合缓存保留依赖，停用后不可继续命中。
- 对固定短语和完整发声译例记录 `matchKind: exact`，模板记录 `matchKind: vocal-template` 及规则 ID；命中项不调用引擎。称呼组合只在已确认姓名、称呼与标点壳全部可解释时执行，未知残余不能交给逐字发声表吞掉。
- 人工明确保存包结果后形成独立 `manual` 记录，不随包撤销；这一步须为用户保存动作，不能因缓存回填自动升级。
- 离线保留最后确认快照，不能承诺即时停用；恢复连接先对账再应用新结果。Cloud 通过已有本机连接访问，未连接时不伪装导入成功、不另建浏览器权威副本。

## 6. 异常采集与恢复

观察记录使用中性字段 `sourceText/targetText`。旧表 `zh` 仅在适配层映射为目标文本，不因列名限制语言。最低字段：

- `eventId/sampleId/taskId`、稳定 `gameId`、原文位置或上下文身份。
- 语言对、原文与译文快照、源/译版本或内容哈希、采集时间。
- speaker、scene、前后句及缺失标记；上下文变化产生新版本。
- 引擎/模型/配置版本、重试次数、错误码及简短错误信息。
- `checks[]`：规则 ID、版本、严重级别与证据；区分确定失败和疑似风险。
- 包依赖、当前分类/审核状态，预留 §8 标签关联。

同一任务事件重放以 `eventId` 幂等，不以原文字面全局去重。不同场景和语言对保留不同样本。没有稳定译文 revision 的入口先保存不可变快照与哈希，不以可变 rowid 充当持久引用。

格式损坏不发布译文，候选和错误单独保存；语义疑似异常默认记录并继续，避免假阳性导致无限重试。主流程不调用分类模型，也不等待其审核。

采集采用有界批量提交，成功持久化后才推进采集游标。后台分类队列不是事件唯一载体。批量任务从持久化输入重放；实时来源需在本机数据根下新增持久化采集日志，由采集域通过存储服务管理，在入库确认前保留最小事件。队列满则停止接收该任务的新采集项并标记未完整状态，有持久化来源的事件恢复后补采。若磁盘故障导致实时事件无法可靠保存，明确显示缺口，不能假称可无损恢复。

第一版提供按任务/时间/语言对/错误类型分页 JSONL 导出。完整标签筛选和外部修正回填留待 M3，不直接把导入语料当作激活术语包。

## 7. 实施落点与迁移顺序

本方案第一版对应需求 M1「外置资源与直接匹配翻译」，交付范围以需求 §7–8 为准，验收以 §9 为准。先完成外置完整译例与受限发声模板的直接翻译，保留现有引擎回退；独立分类在 M2 实现，新模型选型不作为 M1 前置条件。

具体文件按职责拆分，以下目录为计划，不表示已创建：

| 位置                                | 职责                                      |
| ----------------------------------- | ----------------------------------------- |
| `services/translate/resources/`     | 包校验、预览、激活编排、快照读取          |
| `services/translate/observations/`  | 事件构建、批量采集、游标恢复与最小导出    |
| `services/storage/`                 | RPC、迁移及唯一写入实现                   |
| `lib/translate/`                    | 无 I/O 的语言校验辅助、快照匹配与检查函数 |
| `constants/paths.ts` 等现有路径入口 | 数据资源路径定义与解析                    |

顺序：先建立语言对严格解析和调用方清单，再实现包存储/导入/快照，迁出静态术语，统一各入口，最后接入采集及性能对照。初始资源数据文件放在翻译资源模块内的 `defaults/`，属于随应用交付的数据资产；用户变更放数据根，不覆盖应用文件。

初始包按固定哈希幂等安装；已有用户包及人工译文优先保留。升级时逐条比较旧表行为和新包结果，歧义、纠偏越权及未知源语言采用更保守行为并列入迁移报告。回退仅切换资源匹配功能与包版本，不删除原译文或采集数据。

## 8. 后续独立分类契约

M2 才实现分类调度、推理与标签查询。第一版只保存可供读取的样本，不引入新模型依赖。

- 分类作业通过观察快照和普通译文快照取数，支持异常优先、增量和全量；任务固定输入上界，记录游标、重试和失败状态。
- 原文标签结果绑定 `sampleId/sourceRevision/contextRevision`；翻译异常标签还绑定 `translationRevision`。任一依赖改变则对应结果过期，历史保留。
- 标签按需求 §3 的七维输出稳定 ID 数组，允许空数组和未知，不强迫每维选标签。输出 schema、标签集、模型、提示词及推理配置均记录版本。
- 自报置信度允许缺失，独立记录简短依据，不存储隐含思维链；格式通过不代表语义正确。
- 语义标签完全由模型生成；规则检查结果单独存储，不伪装成模型标签。模型结果不得自动修改译文或激活数据包。
- 对同一输入版本的重复作业可幂等跳过；换模型重打标保存新运行记录，不覆盖其他模型历史。训练导出需单独审核及隔离评估集。

## 10. 第一版实现与操作（2026-10-26）

### 10.1 实际存储与调用

本次通过现有 storage daemon 的单写者连接创建以下表，不新增独立写进程：

| 表                                 | 实际内容                                                         |
| ---------------------------------- | ---------------------------------------------------------------- |
| `translation_resource_state`       | 全局单调递增 revision                                            |
| `translation_languages`            | 规范语言标识及展示名，包停用后保留                               |
| `translation_resource_versions`    | 不可变包版本、SHA-256 及完整规范 JSONL                           |
| `translation_resource_activations` | 每包当前版本及启用状态                                           |
| `translation_observations`         | 自增分页序号、唯一事件 ID、语言对、时间、游戏 ID 及完整事件 JSON |

完整包保存在现有 `translate-cache/shared.sqlite` 内，导出可直接重建 JSONL；本版没有额外 archives 目录、规范化条目表、激活历史表或任务检查点表。默认包在首次资源初始化时安装；已停用的默认包不会因重启重新安装。

RPC 白名单为 `resources.preview/apply/activate/disable/list/export/snapshot` 和 `observations.append/export`。预览 token 绑定当前 revision 和规范包哈希；应用时事务内重新校验，过期预览整包拒绝。同版本不同内容拒绝，重复导入已有版本不隐式重新激活；重新启用或回滚使用 `activate`。

每包最多 700000 字节、1000 条记录，每行最多 32000 字符，嵌套深度不超过 16；最多 32 个活动包、10000 条活动记录、6 MB 快照。当前为整包有界解析及整快照读取，不是流式导入或快照分页。预览返回总数、哈希、revision、冲突条目 ID 及 token，尚未实现逐条增删改差异报告。

### 10.2 匹配与入口

- `lib/translate/resource-types.ts`、`resource-matcher.ts` 为无 I/O 契约与匹配器。使用 NFC 键、显式有向语言对；`zh` 和 `zh-Hant` 不合并。
- `services/translate/resources/snapshot.ts` 每批一个只读事务读取 revision；按数据库文件身份及 revision 复用索引。当前批次固定快照，下个批次检查更新；没有推送通知或在途资源结果重算。
- 完整译例先于模板。只对显式 `allowBoundary` 的译例保留标点壳；同优先级异译不选择任意条目。模板要求整条消费，最多 256 发声单元、512 输入字符、4096 解析转移；结果超过 16000 字符或输出存在歧义则回退。
- 本机实时翻译与共享查询返回 `resource` 来源，包含 `packId/version/entryId/revision/matchKind`；命中时不调用引擎，不写普通共享译文缓存。手工保存后才成为独立人工记录。
- 批量 CLI 在数值/模板派生完成后将资源结果填入当前 seed 内存，避免资源命中继续派生为无版本共享记录；其翻译方向仍固定日中。显式合并导出属于静态产物，不承诺随资源停用自动撤回。
- 抽取导出及 RGSS 列表加载一次匹配器，优先已有有效译文并尊重删除标记。纯函数兼容 API `lookupGameTerm`、`translateWithLookup`、未注入 resolver 的 `buildTranslationExport` 和旧优化服务仍读取外置默认术语表，不接受动态包停用；这些遗留调用仍需逐步收敛。
- MV 插件查询服务端资源，不保留独立内置术语回退。离线有本作译文/引擎回退，没有资源快照持久化；非中文目标仍限制为资源和 Apple/Bergamot。插件全局查询不携带游戏身份，不承诺命中游戏限定包。
- 部分命中句子的缺口目前沿用原引擎补译，不把资源派生结果无版本地拼回普通缓存。新增发声模板没有默认启用，默认数据来自原有完整译例；旧逐字假名发声表已移除，未知结巴残余不再被称呼组合吞掉。

### 10.3 操作示例

当前优先在本机 dev server 验证。资源文件无需发布到 GitHub，也不经过官方更新器；`pnpm translate:resources import FILE` 自动预览并应用新版本。开发服务和 CLI 必须使用同一个 `CHAYA_DATA_DIR`。本地资源导入仍执行格式、占位符、冲突及不可变版本校验；重复导入已有版本不重新激活，重新启用使用 `activate`。

所有资源变更通过 CLI 调用存储服务。新建 UTF-8 JSONL，第一行为 manifest，后续每行为一个 entry 或 vocal_rule；下面的法语只用于验证无需改代码即可增加语言，不是默认发声规则：

```jsonl
{"type":"manifest","schemaVersion":1,"packId":"demo.fr","version":"1","languages":[{"tag":"fr","name":"Français"},{"tag":"zh","name":"中文"}]}
{"type":"entry","entryId":"aie","sourceLanguage":"fr","targetLanguage":"zh","scope":{"kind":"global"},"reviewStatus":"reviewed","provenance":{"kind":"manual-example"},"sourceText":"Aïe","targetText":"哎哟","match":{"kind":"exact"}}
```

```sh
pnpm translate:resources preview /tmp/demo.fr.jsonl
pnpm translate:resources apply /tmp/demo.fr.jsonl '<preview 返回的 token>'
pnpm translate:resources lookup fr zh 'Aïe'
pnpm translate:resources list
pnpm translate:resources export demo.fr 1
pnpm translate:resources disable demo.fr
pnpm translate:resources activate demo.fr 1
```

新增版本时更改 manifest.version，重复预览、应用；恢复旧版本使用 `activate PACK VERSION`。语言标识按 BCP 47 规范格式校验；未声明的语言须已经存在注册表。合法标识不代表引擎支持该语言方向。标点不同的完整译例需要独立数据或显式受限模板，不自动删除标点以提高命中率。

### 10.4 失败日志与验证边界

本机实时管线在 `persist !== false` 时收集最终失败项，记录不可变原译文、语言对、时间、引擎、错误及可用的游戏/角色/上下文信息。批末写入 `translation-observations/pending/`：先写 `.partial`、fsync 文件，再 rename 为 `.jsonl`。写盘异常通过返回值 `collectionError` 和 trace 暴露，不等待分类模型。该阶段仍有一次批末同步磁盘写入。

```sh
pnpm translate:resources collect
pnpm translate:resources observations
pnpm translate:resources observations 200 ja zh
```

`collect` 按文件、每四条提交存储服务，确认整文件后删除；崩溃重放依赖 eventId 幂等。`observations` 每页最多 200 条，JSONL 写 stdout，nextCursor 写 stderr。RPC 还支持 gameId/since 筛选。未完成的 `.partial` 不自动回放；磁盘故障、进程在批末前终止及批末前的 onItem 通知不具有持久化回执保证。尚无任务检查点、自动定时收集、完整采集状态 UI 或全入口补采，不能宣称无损采集。

本次自动化验证重点为有向语言隔离、新语言导入、标点/重复保持、混合对白回退、冲突与审核状态、版本生命周期、人工/删除优先、实时零引擎调用和证据重放。完整里程碑仍须补齐需求 §9 的人工语料质量与大批量性能报告，不能以单元测试通过替代。

2026-10-26 验证结果：翻译、抽取、存储、翻译基础库、插件运行时及翻译 API 相关回归共 91 个套件、964 条测试通过；主项目 TypeScript 与两类插件类型检查通过，`build:plugins`、`build:translate` 构建通过。真实存储 RPC 测试使用临时目录及本机临时端口。此处不代表全仓测试、完整应用构建或人工翻译质量验收已经完成。

第一版实际交付以本节为准；后续实现与验收继续补充实际 schema/RPC、入口覆盖范围及验证证据。

## 11. 独立资源与匹配算法更新接入设计

本节保留目标设计，资源更新已有首个实现增量。GitHub 入口、可信元数据、下载与恢复以[统一更新设计](application-updates.md) §3.2、§4、§5.1 为准；当前实现见该文 §8。本文只定义翻译侧接入。当前 `resource-matcher.ts` 的纯函数边界可作为拆包基础，不代表已具备远程算法加载能力。

### 11.1 宿主与能力包职责

| 宿主保留                                 | 独立匹配能力包负责                           |
| ---------------------------------------- | -------------------------------------------- |
| 人工译文、删除标记和游戏限定范围保护     | 在宿主提供的范围内匹配完整译例及受限模板     |
| 资源导入、快照读取、版本选择与兼容性检查 | 根据已验证的只读快照建立匹配索引             |
| 控制码保护、结果格式校验、输出大小限制   | 归一化、标点壳、重复和拖音等受限匹配计算     |
| 任务调度、缓存、引擎回退、异常记录       | 返回命中、未命中或结构化错误及条目来源       |
| 下载、可信校验、安装与 worker 生命周期   | 声明协议及资源格式兼容范围，不自行下载或升级 |

资源包始终是数据。算法变化发布匹配能力包；调度、引擎调用、数据库或宿主接口的不兼容变化仍通过 App 更新交付。游戏插件继续查询宿主，不在此阶段引入游戏内独立算法更新器。

### 11.2 资源包安装与版本映射

本地开发另提供 `GET/POST /api/translation-resources`，直接调用相同资源 RPC，供版本管理及试匹配使用。参数、返回值与请求边界见[统一更新设计 §8.6](application-updates.md#86-dev-server-资源管理-api)。此入口不经过 GitHub 更新器，不生成官方安装记录，也不允许执行代码；完整管理 UI 尚待建设。

更新协调器从固定 GitHub 渠道取得并验证内容，在暂存区完成下载校验，再调用 `resources.preview/install/activate` 接口。`resources.install` 已新增为仅导入、不激活；原 `resources.apply` 保持导入并激活，兼容原 CLI。预览 token 过期时重新预览，不绕过 revision 校验，不直接写共享 SQLite。

外层分发描述与现有 JSONL manifest 分开：`packageVersion` 用于分发及兼容性选择，manifest 的 `packId/version` 用于资源身份。二者建立明确映射，保留已有 `"1"` 等历史版本，不强行转换为 SemVer 或重写已安装数据。现有内容 schema 的变化另行版本化。

资源激活表继续作为数据生效状态的权威来源。更新状态库记录下载、安装意图和恢复进度；资源事务提交后进程退出，重启应按实际激活状态补全记录，不能以另一份更新指针覆盖资源状态。官方包更新保留用户包及人工译文保护规则。

### 11.3 调用与批次一致性

任务开始时固定兼容的 `(algorithmVersion, resourceRevision)` 组合，资源快照包含实际活动包身份。当前算法尚未独立版本化，接入时须为内置算法建立明确身份，不能用“内置”或空值永久代表不断变化的实现。

宿主按组合复用已初始化的 Node worker，以只读快照初始化一次，之后发送有界批次请求，不逐条复制完整资源。worker 运行官方自包含 JS；它隔离计算与生命周期，不构成不可信代码的安全沙箱。安装过程不执行 npm 脚本，算法不直接访问数据库或承担下载职责。

请求包含唯一身份、原文、明确语言对和必要范围；响应包含请求身份、命中结果及资源条目来源，或未命中/结构化错误。宿主校验响应关联、来源与当前快照一致性、控制码和长度。超时或异常终止 worker 后，按固定的回退策略使用已验证内置匹配器或引擎；回退产生的结果记录实际算法来源，不冒充原算法成功。

算法或资源更新只供新批次选择。旧批次继续使用原组合，版本清理保留所有运行任务引用；异常恢复需要改变算法时，显式记录回退及实际结果身份。算法选择与资源激活并非同一跨库事务，新任务必须在提交选择前复核兼容性并取得固定快照，不能观察到不兼容的中间组合。

### 11.4 来源、缓存与入口收敛

现有 `packId/version/entryId/revision/matchKind` 只描述资源来源，须补充算法身份及必要协议版本。所有资源派生缓存键或有效性校验纳入算法与快照组合；算法变更后不能只因原文和资源版本相同而复用旧派生结果。人工保存的独立译文继续遵循人工保护语义，不随算法更新自动撤回。

本机实时、批量、抽取导出和插件宿主查询逐步接入同一匹配适配器。§10.2 列出的默认 JSON 和纯函数兼容入口尚未支持动态停用，不因新增下载器自动获得远程算法能力；每个入口需单独记录接入与回退范围。无法承载 worker 的同步兼容 API 保留明确的内置行为，调用方需要动态能力时改用宿主异步适配器。

### 11.5 接入验收

- U2a：GitHub 两个数据版本完成发现、下载、导入、激活和本地回滚；不发布 App 即可增加词条，已安装内容不重复下载，离线基础包可用。
- U2b：GitHub 两个算法版本完成独立构建和加载；旧任务固定旧组合，新任务选兼容新组合；异常、超时与重启恢复不会将坏结果写成成功译文。
- 验证人工译文、删除标记、语言对隔离、格式保护、用户资源和算法来源；覆盖资源先更新、算法先更新及两者不兼容场景。
- 记录实际 GitHub 请求及下载来源，确认不经过 Vercel 代理；沿用主流程不等待分类的约束。
- 对照内置匹配器测量 worker 初始化、批处理吞吐和主线程响应，U0 先确定可接受阈值，未通过不启用远程算法默认路径。

本节验收只证明更新接入，原需求 §9 的人工质量语料与大批量性能验收仍须独立完成；§10.4 的既有测试结果不能作为本节已实现的证据。
