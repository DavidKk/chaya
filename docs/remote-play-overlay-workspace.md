# 远程串流：全屏局内工作台、调试与日志解耦及移动端低功耗需求

- **日期**：2026-11-02
- **状态**：需求草案已确认，待技术评审与分阶段实施
- **对应技术方案**：[技术方案](technical/remote-play-overlay-workspace.md)
- **关联文档**：[静默与多实例需求](remote-play-silent-multi-instance.md) · [封面直出与加速需求](remote-play-acceleration-and-cover.md) · [Chaya UI 风格指南](technical/chaya-ui-style-guide.md)
- **有效范围**：WebRTC 远程串流端（`/play` 页面）的局内抽屉与弹出工作台。覆盖 iOS/Android 移动端（Safari / Chrome）与桌面端（Chrome / Edge / Safari）。

---

## 1. 背景与现状痛点

当前 `/play` 页面中，通过「局内控制台」弹窗（`RemoteCheatDrawer`）承载了修改、调试与日志功能。经过实机（特别是 iOS 移动端）验证，暴露以下体验与架构问题：

1. **小弹窗在移动端横屏下极度局促**：
   - 当前采用居中小弹窗（固定宽高或百分比最大宽高），在手机横屏（有效视窗高度通常仅 320px–360px）下，弹窗的内边距、外边距、阴影吃掉了近 30% 空间。
   - 内容在竖向上被大幅压缩，导致滚动困难、容易误触下层的虚拟遥感或手势。
2. **功能职责堆叠，信息架构混乱**：
   - 常用修改（无敌、穿墙、脱离卡死、剧情推进）、链路调试（RTT、画幅、Eruda、性能 HUD、终端命令）与实时日志流全塞在同一个弹窗内，通过简单的 Tab 切换，彼此逻辑与状态相互缠绕。
   - 玩家只是想按一下「脱离卡死」或调整倍速，却要面对密集的网络与调试技术卡片。
3. **未打开时仍产生内存与计算开销，违背移动端低功耗要求**：
   - 日志订阅（`remotePlayLogger.subscribe`）在组件挂载阶段常驻运行，哪怕面板处于关闭状态，后台产生的日志仍会触发 React 状态更新和无谓的 re-render。
   - 手机端需全力保障 60 FPS WebRTC H.264 视频流解码和 Canvas 渲染，后台隐式 DOM 与事件轮询直接导致发热和掉帧。
4. **视觉风格与主应用脱节**：
   - 当前弹窗采用临时堆砌的粗圆角、任意内边距与非标准深灰底色（`bg-neutral-900`），未对齐主应用的轻量圆角（`rounded-[0.375rem]`）、主题变量（`bg-paper`, `border-line`）与通用控件规范（`components/sk`）。

## 2. 目标与非目标

### 2.1 目标

| 编号   | 目标项                                    | 验收口径                                                                                                                                                           |
| :----- | :---------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **R1** | **全屏铺满式视图（Full-screen Sheet）**   | 呼出后铺满可视区域，严格遵循 `env(safe-area-inset-*)` 规避灵动岛、刘海与底部手势条；横屏与竖屏针对性布局，无多余外层边距浪费空间。                                 |
| **R2** | **职责清晰拆分与独立入口**                | 彻底解耦为三个独立面板：**常用修改**（Cheats）、**串流调试**（Debug）、**运行日志**（Logs）；菜单入口清晰，一次只聚焦一个任务。                                    |
| **R3** | **极致低功耗与按需挂载（Zero Overhead）** | 面板关闭时彻底销毁 DOM（`unmountOnExit`）；日志订阅仅在「运行日志」面板处于前台活动时激活，关闭或切走立即注销；调试轮询按需启停。                                  |
| **R4** | **移动端内存有界保护（Ring Buffer）**     | 移动端日志列表最多保持最新 100 条，超出自动丢弃历史，防止 Safari 内存泄漏或崩溃。                                                                                  |
| **R5** | **全面对齐 Chaya UI 规范**                | 统一采用主应用主题色系（`bg-paper`, `border-line`）、排版字阶（`text-xs`/`text-sm`）及基础组件库（`components/sk` 的 `Button`, `Badge`, `ScrollArea`, `Switch`）。 |
| **R6** | **多语言完整覆盖**                        | 支持 10 种语言无死角翻译，不得在 UI 中硬编码中文文案。                                                                                                             |

### 2.2 非目标

- **不将桌面端完整表格搬运到手机**：不直接将桌面端包含几万个变量/道具的 `GameEditWorkbench` 虚拟表格原样塞进移动端，避免灾难性的性能开销与点按灾难。
- **不改变 WebRTC 与信令协议底层**：底层通信继续沿用 `GameLinkMessage` 与 `agent-protocol`，本次重构仅聚焦客户端工作台架构、视图呈现与性能能耗。

## 3. 详细功能需求

### 3.1 页面形态与布局规范

1. **容器特性**：
   - 采用 `fixed inset-0 z-50` 铺满整屏，背景使用毛玻璃与半透明暗色遮罩（`bg-paper/95 backdrop-blur-md`）。
   - 内容区计算 Safe Area 内边距：`padding: max(0.5rem, env(safe-area-inset-*))`，确保在 iPhone 灵动岛横屏持握时不遮挡操作与标题。
2. **极简头部**：
   - 高度统一为 `40px`，左侧为返回/关闭图标按钮，中央为面板标题（`text-sm font-semibold text-ink`），右侧预留辅助动作（如日志的一键清空或复制）。
   - 去除沉重的粗分割线，以微弱的 `border-b border-line/40` 或背景纯色分层。
3. **横竖屏自适应**：
   - **横屏模式**（宽 > 高，高度极窄）：优先采用左右双列或左右分栏，滚动条完全贴边。
   - **竖屏模式**（高 > 宽）：单列纵向流式排版，底部留足操作空间。

### 3.2 拆分后的三大面板定义

#### 3.2.1 面板一：常用修改（RemoteCheatsPanel）

- **核心定位**：专注于游玩过程中的游戏状态干预与卡死抢救，面向玩家角色。
- **功能分区**：
  1. **卡死急救与剧情推进**（置顶高优先级）：
     - 一键脱离卡死（恢复画面亮度、解除隐身、解除移动锁定与等待）。
     - 推进/跳过剧情（自动完成过场变量更新并传送回主地图）。
     - 返回上一安全地图（遭遇单向过场通道卡死时的安全回退）。
  2. **状态快捷开关**：
     - 无敌锁血（HP/MP 锁定）、穿墙模式、遇敌控制、自动对话开关。
  3. **运行辅助**：
     - 游戏倍速档位切换（1x / 2x / 3x / 5x）。
     - 一键快速存档至指定槽位。

#### 3.2.2 面板二：串流调试（RemoteDebugPanel）

- **核心定位**：专注于真机网络链路状况排查与手机端调试，面向开发者与排障场景。
- **功能分区**：
  1. **链路质量指标卡**：
     - 连接状态（已连接 / 协商中 / 断连）、RTT 往返时延（ms）。
     - 实时解码画幅（例如 `1280 × 720`）。
     - 客户端环境（系统与浏览器内核）。
     - H.264 硬件解码支持状态。
  2. **调试工具箱**：
     - **移动端 DevTools 开关**：轻量唤出/销毁 Eruda 控制台，悬浮于右下角供深度检查。
     - **性能 HUD 开关**：在主游戏画面上方悬浮帧率与网络监控条。
     - **终端监视命令**：一键复制 Mac 端实时流式日志查看命令（`curl -N ...`）。

#### 3.2.3 面板三：运行日志（RemoteLogsPanel）

- **核心定位**：纯粹的高效全屏日志流查看器，用于定位串流异常与错误溯源。
- **功能分区**：
  1. **顶部操作栏**：
     - 级别过滤单选标签：`全部` / `仅异常 (Warn/Fail)` / `常规 (Info/Ok)`。
     - 快捷动作按钮：`复制全部日志`、`立即上报电脑端`、`清空本地日志`。
  2. **全屏日志列表**：
     - 等宽字体、高对比度语法标签（`OK` 绿色，`FAIL` 红色，`WARN` 黄色）。
     - 单条支持点击展开查看完整的上下文 JSON Payload，避免在列表上直接打乱排版。
  3. **上报状态提示**：
     - 底部展示日志同步状态（自动定时上报或离线缓存条数）。

## 4. 移动端能耗与资源治理策略

1. **按需订阅与注销（Lazy Subscription）**：
   - 只有当用户显式打开「运行日志」面板时，才调用 `remotePlayLogger.subscribe()`。
   - 当用户关闭弹窗、或者切换到「常用修改」/「串流调试」时，**立即注销订阅**，切断一切日志推入引发的 React re-render。
2. **彻底卸载（Unmount on Exit）**：
   - 面板未呼出时，对应 React 子树必须完全从 Virtual DOM 和真实 DOM 中卸载，不得仅使用 `display: none` 或 `opacity: 0` 隐藏。
3. **指标轮询隔离**：
   - WebRTC 链路统计与帧率定时拉取仅在打开「串流调试」面板时开启定时器，面板关闭即清理。
4. **日志条数上限保护**：
   - 前端日志缓冲区强制保留最近 100 条记录，防止长时间游玩产生数千条日志拖垮移动端 Safari 的 JS 堆内存。

## 5. 验收标准

1. **视觉与交互验收**：
   - 在 iPhone 真机横屏与竖屏下打开工作台，面板完全铺满视窗，四周边距精确避开灵动岛与手势条，无内容被截断。
   - 滚动条完全贴合边界滚动，无双层滚动条嵌套现象。
   - 整体色调、字阶、按钮与开关与 Chaya 主应用一致，无突兀大圆角或刺眼底色。
2. **性能与能耗验收**：
   - 在面板关闭状态下，运行日志模块不产生任何 React state update 与 re-render；
   - 切换面板或关闭时，相关定时器与事件监听器全部清理归零；
   - 开启/关闭工作台过程中，底层 WebRTC 画面的 FPS 波动不超过 3 帧。
3. **全量测试与构建门禁**：
   - 现有全部单元测试（486 套）持续通过；
   - 新增针对解耦组件的挂载/卸载、订阅清理与多语言文案的测试覆盖；
   - `pnpm lint:check` 与 `pnpm typecheck` 保持 0 errors 0 warnings。
