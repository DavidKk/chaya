# Apple 原生离线翻译接入需求

- 日期：2026-10-18
- 状态：草案评审中
- 技术设计：[Apple 原生离线翻译接入设计](technical/apple-native-translation.md)

## 目标与定位

在 macOS（OSX）环境下引入基于系统底层的 Apple 原生离线翻译能力，为 Chaya 翻译流水线提供**零云端网络依赖、零 API 成本、极低调用延迟（毫秒级）**的端侧机翻兜底支持。

## 翻译流水线优先级策略

遵循以下优先级顺序（从高到低），由精到粗，兼顾文案质量上限与离线可用性：

1. **手动翻译（Manual）**：人工精修校对与保存内容，绝对优先级，不可被自动翻译覆盖。
2. **导入翻译（Imported）**：外部翻译包、旧版资源导入的预置成果。
3. **模型翻译（Agent / LLM）**：理解上下文、剧情背景与人物语气的高质量大模型（Claude, GPT, 本地大模型等）。
4. **翻译服务（Platform Services）**：成熟云端机器翻译服务（如 Bing, Google），句意自然通顺。
5. **系统原生离线翻译（System / Apple Translation）**：纯端侧硬件加速的极速离线基准机翻，作为兜底安全网。

## 业务需求与核心场景

### 1. 毫秒级极速兜底

- 当云端翻译服务（Bing/Google）遭遇网络超时、断网或 HTTP 429 频控限流时，无缝降级到 Apple 原生离线翻译。
- 单句翻译调用响应要求控制在 **5ms ~ 30ms** 水平，确保大批量自动化填充时不发生管道卡顿。

### 2. 离线/飞行模式可用

- 在完全无外网连接环境下，依然能够利用本地神经引擎完成游戏文本的自动化基准初翻。

### 3. 可用性与状态自检

- 系统应当能够主动检测：
  - 当前操作系统是否为 macOS（非 macOS 平台自动隐藏或禁用该引擎）。
  - 当前语向（如日译中 `ja -> zh-Hans`）系统是否已下载并安装离线语言包。
- 若未安装对应语言包，系统应当提供清晰的状态提示与系统设置跳转引导，并优雅跳过（fallback）而不导致整个流水线崩溃。

### 4. 引擎开关与管理

- 用户可在引擎管理界面自由开关 `apple` 引擎。
- 遵循默认引擎排序规则：`agent:*` 组优先于 `platform` (Bing, Google)，`apple` 作为兜底引擎位于平台末位。

## 验收标准

1. **平台隔离**：在 macOS 环境下正常加载；在 Windows / Linux 环境下自动禁用且不产生运行时异常。
2. **流转合规**：当高优先级引擎失败或缺漏时，`apple` 引擎能正常填补未翻译词条。
3. **性能达标**：长驻进程下，日译中单句翻译平均延迟 ≤ 30ms。
4. **自愈与降级**：当未安装语言包或系统版本低于 macOS 15 时，任务日志清晰记录跳过原因，自动回退到默认行为，不阻塞整体任务。
